# 难度口径：K/A/C 加权（difficulty-formula）

> 口径来源：题库仓 `ees-banks/difficulty.md`（2026-11-18）。`score.py` 与 `verify.py` 都按本文件实现；两者与本文冲突时以脚本源码为准，并同步修正本文。

## 1. 公式

```text
S = 0.35 × K + 0.45 × A + 0.20 × C          S ∈ [1, 4]
K 知识点数量      1–3     权重 35%
A 算法难度与数量  1–4     权重 45%
C 代码行数        1–4     权重 20%
```

难度**只由 S 与分档表决定**：不得按题号、位置、卷面比例或“每档配额”切档；同一 S 必须得到同一档。

| 题型 | 分档（固定阈值） |
|---|---|
| 单选 / fill / fix | S<1.90 → 1；S<2.55 → 2；否则 3 |
| 大题 | S<1.75 → 1；S<2.60 → 2；S<3.30 → 3；否则 4 |
| 多选 | 真实 S 必须落在 **[2.00, 2.20]**；JSON `difficulty` 固定写 **9** |

## 2. K：知识点数量（1–3）

| K | 判定 |
|---|---|
| 1 | 只考 1 个知识点：单一事实、单个表达式、单条语句 |
| 2 | 1 个知识点 + 1 个支撑概念（“数组 + 下标”“函数 + 返回值”） |
| 3 | ≥2 个知识点交互（“嵌套循环 + 二维数组”“指针 + 函数参数”“宏 + 运算符优先级”） |

## 3. A：算法难度与数量（1–4）

| A | 判定 |
|---|---|
| 1 | 无算法：查表、单表达式、单条赋值/输出 |
| 2 | 1 个线性算法，或 1 个分支/1 次数据访问（单层循环、单次查找、一次条件判断） |
| 3 | 嵌套循环 / 递归 / 两个及以上算法步骤（先统计再求值、双指针、模拟） |
| 4 | 算法设计：多模块协作、状态机、贪心/搜索/动态规划、开放方案设计 |

> “数量”体现在：出现 2 个及以上**独立**算法步骤时，A 至少 3；A=4 仅用于设计类，不得用于“写得长”的题。

## 4. C：代码行数（1–4）

| C | 非空代码行数 |
|---|---|
| 1 | 0–3 |
| 2 | 4–8 |
| 3 | 9–20 |
| 4 | >20 |

统计范围：题干围栏代码块、`body.template`、`body.code`。

**大题例外**：以 `answer.reference` 的**核心算法行**计——不含 `#include`、`main`、输入输出、花括号、`return 0;` 等样板；由作者在 `meta.scoring.c` 标注，复核抽检其合理性。纯文字且无参考解按 0 行计（C=1）。

## 6. 多选：JSON 9 与真实 S 是两回事

- `difficulty` 是**展示/统计标签**，固定 9，不参与 S 分档；
- **真实 S ∈ [2.00,2.20]** 必须逐题成立；现行库统一 `meta.scoring={k:3,a:2,c:1}` → S=2.15；
- 结构要求：4 条独立单事实陈述、2–3 个正确项、单条 12–35 字、无嵌套推理、四选项认知负荷相当——这是“真实 S 落在 2.15 附近”的**实现手段**，不是可选项；
- 主观分布目标：**10 易 / 35 中 / 5 难**（中档 70%），由复核人逐题判，偏差记遗留项（现库实测约 13/30–31/6–7）。

> ⚠️ `verify.py` 对 `type=multiple` **跳过** S↔档校验（只强制 `difficulty==9`）；`score.py` 会照 `meta.scoring` 打印多选 S，但档位一律写 9，**越界不报错**（只有缺标注时才回退 `{3,2,1}`）。所以“多选 S 越界”只能用 **`qc.py` V4** 抓（它直接读 `meta.scoring` 复算并 error）。

## 7. 大题：统一口径

| 项 | 值 |
|---|---|
| 每库题数 | 30 |
| 难度 | 全部 **3**（不按 1/2/3/4 分档） |
| 每题分值 | **15** |
| 总分 | **450/库** |
| 标注 | `meta.scoring={k:3,a:3,c:2}` → S=2.80（D3 区间 2.60–3.30），仅用于质量抽检 |

- `answer.rubric.total` 与评分点合计 MUST = 15；
- `answer.reference` 必须可编译，`answer.samples` 必须逐字节匹配；
- K/A/C 仍要真实标注：抽检时若某题明显不属 D3（如 S 应 <2.60），记 B 级并修正标注，**不得改 `difficulty`**（统一档是硬口径）；
- **不要对大题跑 `score.py --write`**：它按 S 重新分档，并按 1/2/3/4 的 10/15/15/25 改 `score`/`rubric`（实测把 S=1.00 的题改成 difficulty=1、score=10），会直接违反“统一 3/15、450/库”。

## 8. fill / fix：每档 ≥15

- 难度 1/2/3 每档**至少 15 题**，题库总量不设上限；
- 不许把 D2 标签改成 D1/D3 来“凑档”：档位由 S 决定，凑档的唯一合法手段是**改题**（改 K/A/C）；
- 当前库：fill 26/19/15、fix 28/18/15——3 档刚好卡在下限，任何降档都会立刻触发门禁 error。

## 9. 标注与复核

1. 出题人 MUST 为每题写 `meta.scoring = {"k":…, "a":…, "c":…}`；无法标注的题不得进库；
2. `verify.py` 复算 S 与档位并与 JSON `difficulty` 比对，但**只在标注存在时**，且跳过多选；
3. `qc.py` V4 补三件：缺整数标注（REVIEW）、多选真实 S 越界（error）、C 标注与非空行数差 ≥2 档（REVIEW）；
4. 复核人 MUST 抽 **15 题**按本表独立打分：偏差 >1 档即 FAIL；偏差 1 档且 S 距阈值 <0.05 记 C 级分歧；
5. 多选 MUST 逐题确认真实 S∈[2.00,2.20] 且四选项负荷相当；
6. 口径变更后旧题 MUST 重新标注并重算，不得沿用历史数值。

## 10. 常见误标（真实案例）

| 现象 | 根因 | 处置 |
|---|---|---|
| 单选 203 题档位与实际不符 | 旧口径按“行数/陷阱”主观判 | 按 K/A/C 重算，同 S 同档（report §2.2） |
| 多选 6 题偏易/偏难 | 统一 S=2.15 但陈述负荷不均 | 重写陈述（单事实、12–35 字）而非改标签 |
| fill/fix 3 档长期只有 5/4 题 | 旧配额 17/17/16 + 总量 50 | 扩容 + 重写 D3 题，不是平移标签 |
| 大题按 10/15/15/25 分摊 | 旧四分档 | 统一 3 档 15 分，rubric 合计重算 |
| `meta.scoring` 抄上一版 | 口径变更未重算 | 全部重标；`score.py --write` 的 `source=heuristic` 行必须人工确认 |
| 多选 `difficulty=9` 但 `meta.scoring` 仍写旧值 | 只改标签没改标注 | `qc.py` V4 重算 S，越界即 error |

## 11. 原子化前提

难度评估只看本题信息，不得引用其他题；若某题必须依赖另一题才能评估/作答，直接判 FAIL（原子化硬规则）。
