## 2. `verify.py` 不检查（必须 `qc.py` 或人工补）

| 盲区 | 为什么门禁看不见 | 补法 |
|---|---|---|
| 选项“屏幕同形”：仅差尾随空格、NBSP、零宽字符 | 只看选项文本是否 `!=`，不做可见性归一 | `qc.py` V1：去首尾空白/去不可见字符后比较 |
| 空位是否被测试钉死 | 只验“官方答案通过”，不验“错误值失败” | `fill_inject.py` 注入错误值 |
| 句式族（同壳换标识符） | 骨架算法只看数字/代码块，随机函数名会逃逸 | `qc.py` V3：掩掉标识符后再聚类 |
| 难度标签语义 | 只验数值在 1/2/3，不验“这题是否真的难” | 抽 9 题/库人工按行数+陷阱判断 |
| kp 语义是否与原大纲同源 | 只验编号合法，不验编号含义 | 对照大纲人工抽查；`qc.py --strict-kp` 可把越纲升 error |
| 概念题答案事实正确性 | 编译只能验代码题 | 人工核对（至少 20 题/库） |
| pick 是否符合考务 | 只验 1..题量 | 与考务确认；异常值（如 500 题 pick=2）应质疑 |
| 多选“统一 9”是否回退 | 允许 1/2/3/9 兼容历史库 | 统计检查 `{9:50}`，回退即 FAIL |
| 领域等价答案（`&&`↔`&`） | 只看输出，域内等价会通过 | 逐条归类“等价/补用例”，不能静默 |

## 3. 使用顺序

1. `verify.py` 完整模式 —— 先拿到 0 error；
2. `qc.py --no-compile` —— 补选项可见性/句式族/难度账本/kp/pick；
3. `check_choice.py --all` / `fill_inject.py` —— 答案与空位实跑；
4. 人工抽样（难度语义、概念题事实、多选答案键）；
5. 全绿后再交付；任何修复都从第 1 步重跑。

## 4. 历史事故对照

| 事故 | 当时门禁状态 | 真实原因 |
|---|---|---|
| 选项只差尾随空格 | PASS | 门禁不做可见性归一 |
| 44 道单行 `int main` | PASS（旧版） | 旧版无排版规则；新版已 error |
| `n%10` 逆序题错答 | PASS | 用例只覆盖个位数，门禁只验“官方通过” |
| `&&`/`||` 被乘积掩盖 | PASS | 缺含 0 的用例；注入检查才发现 |
| kp 越纲 112 条 | PASS（仅 warning） | 门禁只警告，不阻断 |
