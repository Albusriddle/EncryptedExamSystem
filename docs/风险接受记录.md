# 风险接受记录

- 记录日期：2026-10-29
- 适用版本：v1.0.0 及后续 v1.0.x
- 决策：**项目接受以下已识别的安全风险，不在 v0.15.x 内升级 container v8 / answer_sheet v2。**

> 本记录不是“风险已修复”的声明。它说明项目为什么在已知残余风险下继续使用当前格式，以及使用时必须遵守的补偿措施。任何“读不到题目”“防伪造答题卡”的绝对承诺都不再成立。

## 1. 接受的风险

### R-01 同场学生可解出本场全部题干

**事实**：每个场次只有一个 `session_secret`，`PayloadData.banks` 保存本场完整题库；学生用自己的学号解开信封后，可以解出本场所有题干。答案与 `judge` 已剥离。

**影响**：本场题干可被合法名单内学生获取并扩散；不能读其他场次，不能读标准答案。

**接受理由**：

- 系统定位是“防君子 + 现场监考”，不是防逆向的强保密系统；
- 题干泄露的损失低于标准答案泄露，且现有流程依赖现场监考；
- 真正修复需要 per-student 试卷数据与密钥，属于 container v8，当前版本不做。

**补偿措施**：

- 重要考试必须现场监考、禁止携带可运行程序的设备；
- 题库按场次拆分，减少单场题干暴露面；
- 不把“题干绝对不可见”作为对教师的承诺。

### R-02 同场学生可读取/伪造他人答题卡

**事实**：答题卡密钥由包内 `K_manifest + paper_fingerprint` 派生；`check_binding` 只比较原卷指纹和 qids，不证明答题卡作者身份。收据是可选审计措施。

**影响**：同场学生可读取、修改或伪造他人 `.eea`；教师端绑定校验只能发现“不是本包原卷”，不能发现“不是本人填写”。

**接受理由**：

- 现有收卷流程是现场收卡/统一拷贝，答题卡不经过学生自提交；
- 真正修复需要 per-student 答题卡密钥或教师签名，属于 answer_sheet v2，当前版本不做；
- 收据可检测收卷后的改动，但不能替代身份认证。

**补偿措施**：

- 收卷必须现场完成，学生不得自行提交/转发 `.eea`；
- 教师校验时**必须**选择学生端包，不接受“未校验绑定”的通过状态；
- 重要考试启用答题卡收据，并核对签发人指纹；
- 不把 `check_binding` 当作“作者身份认证”。

### R-03 默认无 PIN 时，任意已知名单内学号可解锁

**事实**：`--pin-login` 默认关闭；无 PIN 时入场密钥只依赖学号、场次和 salt。知道名单内任意学号的人可以解锁该生信封。

**影响**：可冒用同场学生身份获取该场题干；与 R-01 叠加后影响扩大。

**接受理由**：

- 默认零配置是产品可用性要求；
- 低风险/随堂场景由现场监考和名单管理控制；
- 高风险场景可以显式启用 `--pin-login`，无需改格式。

**补偿措施**：

- 高风险考试必须启用每生 PIN；
- 名单与 PIN 表按考试保密管理，不公开传播；
- 发现异常登录时按场次作废/重考处理。

### R-04 Header 可被重加密，时间窗/回看策略可被改包绕过

**事实**：Header（含场次起止时间、时间令牌配置、`student_review`）只由包内 `K_manifest` 加密；学生可还原密钥、修改 Header 后重加密。

**影响**：时间门禁、到点自动收卷、学生回看策略只对“不改包”的学生有效；不能作为密码学边界。

**接受理由**：

- 纯客户端无法防拥有本机完全控制权的学生；
- Header 签名需要教师密钥与容器 v8，当前版本不做；
- 现场监考与网络时间仍是主要控制手段。

**补偿措施**：

- 时间门禁按“UI 约束 + 现场监考”宣传，不作为防作弊保证；
- 重要考试使用现场统一开考/收卷，不依赖学生端自动冻结；
- 不把 `student_review` 当作强制保密控制。

## 2. 不在本记录中接受的事项

以下问题不是“安全边界”，仍需按普通缺陷修复，不能引用本记录豁免：

- 重叠场次导致学生被路由到错误场次；
- `check_binding` 未选包时的“未校验绑定”状态；
- Verify/Keygen 子进程残留、答题卡 `recovered` 文件恢复、测试门禁误判等工程质量问题；
- 任何会导致正常考试无法进行、答题卡丢失或成绩错误的功能缺陷。

## 3. 复审触发条件

出现以下任一情况时，必须重新评估本记录，并优先实施 container v8 / answer_sheet v2：

1. 考试要求从“现场监考”变为“远程/无人监考”；
2. 题干或答题卡进入合规审计范围；
3. 发生同场题干扩散、答题卡伪造或时间窗绕过事件；
4. 需要把“防伪造/防篡改”作为对客户的合同承诺。
