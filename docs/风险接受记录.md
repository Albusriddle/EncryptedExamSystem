# 风险接受记录

- 记录日期：2026-10-29（首次决策）；本次随 **v1.3.1** 重述
- 适用版本：v1.0.0 及后续 1.x
- 决策：**项目接受下列已识别的安全风险，不实现 P0 的 per-student / Header 签名格式（v9），
  也不升级答题卡到能证明作者身份的格式。**

> 本记录**不是**「风险已修复」的声明。它说明项目为什么在已知残余风险下继续使用当前格式，
> 以及使用时必须遵守的补偿措施。任何「读不到题目」「防伪造答题卡」的绝对承诺都不成立。
>
> 事实依据见 [安全边界与威胁模型](安全边界与威胁模型.md)；实现层面的取证见
> [代码审阅报告](代码审阅报告.md) 第七十九轮。

## 1. 接受的风险

### R-01 同场学生可解出本场全部题干

**事实**：每个场次只有一个 `session_secret`，`PayloadData.banks` 保存本场完整题库。
学生用自己的学号解开信封后，可以解出本场**所有**题干。`answer` 与 `judge` 在打包时已剥离。

**影响**：本场题干可被合法名单内学生获取并扩散；不能读其他场次，不能读标准答案。

**接受理由**：

- 系统定位是「防君子 + 现场监考」，不是防逆向的强保密系统；
- 题干泄露的损失低于标准答案泄露，且现有流程依赖现场监考；
- 真正修复需要 per-student 试卷数据与密钥，属于 P0 新格式（v9；v8 已被代码题门禁占用），
  当前版本不做。

**补偿措施**：

- 重要考试必须现场监考、禁止携带可运行程序的设备；
- 题库按场次拆分，减少单场题干暴露面；
- 不把「题干绝对不可见」作为对教师的承诺。

### R-02 同场学生可读取 / 伪造他人答题卡

**事实**：答题卡密钥由包内 `K_manifest + paper_fingerprint` 派生；`check_binding`
只比较原卷指纹与 qids，**不证明答题卡作者身份**。收据是可选审计措施，不是必经流程。

**影响**：同场学生可读取、修改或伪造他人 `.eea`；教师端绑定校验只能发现
「不是本包原卷」，不能发现「不是本人填写」。

**接受理由**：

- 现有收卷流程是现场收卡 / 统一拷贝，答题卡不经学生自提交；
- 真正修复需要 per-student 答题卡密钥或教师侧签名链，属于新格式，当前版本不做；
- 收据可检测收卷后的改动，但不能替代身份认证。

**补偿措施**：

- 收卷必须现场完成，学生不得自行提交 / 转发 `.eea`；
- 教师校验时**必须**选择学生端包，不接受「未校验绑定」的通过状态；
- 重要考试启用答题卡收据，并核对**签发人指纹**（16 位）；
- 不把 `check_binding` 当作「作者身份认证」。

### R-03 默认无 PIN 时，任意已知名单内学号可解锁

**事实**：`--pin-login` 默认关闭；无 PIN 时入场密钥只依赖学号、场次与 `salt`。
知道名单内任意学号的人可以解锁该生信封。

**影响**：可冒用同场学生身份获取该场题干；与 R-01 叠加后影响扩大。

**接受理由**：

- 默认零配置是产品可用性要求；
- 低风险 / 随堂场景由现场监考与名单管理控制；
- 高风险场景可显式启用 `--pin-login`，**无需改变格式**。

**补偿措施**：

- 高风险考试必须启用每生 PIN；
- 名单与 PIN 表按考试保密要求管理，不公开传播；
- 发现异常登录时按场次作废 / 重考处理。

### R-04 Header 可被重加密，时间窗 / 回看策略可被改包绕过

**事实**：Header（含场次起止时间、时间令牌配置、`student_review`）只由包内 `K_manifest`
加密；学生可还原密钥、修改 Header 后重新加密。

**影响**：时间门禁、到点自动收卷、学生回看策略只对「不改包」的学生有效，
不能作为密码学边界。

**接受理由**：

- 纯客户端无法防拥有本机完全控制权的学生；
- Header 签名需要教师密钥与 P0 新格式（v9），当前版本不做；
- 现场监考与网络时间仍是主要控制手段。

**补偿措施**：

- 时间门禁按「UI 约束 + 现场监考」宣传，不作为防作弊保证；
- 重要考试使用现场统一开考 / 收卷，不依赖学生端自动冻结；
- 不把 `student_review` 当作强制保密控制。

## 2. 不在本记录中接受的事项

下列问题**不是**安全边界，仍需按普通缺陷修复，不能引用本记录豁免：

- 重叠场次导致学生被路由到错误场次（v1.0.2 起改为按信封 tag 过滤 + 时间窗内回退）；
- Verify / Keygen 子进程残留、答题卡 `recovered` 文件恢复、测试门禁误判等工程质量问题；
- 任何会导致正常考试无法进行、答题卡丢失或成绩错误的功能缺陷；
- 答题卡格式 / 容器版本不兼容导致的收卷失败（应通过同步升级解决，不是「接受风险」）。

## 3. 复审触发条件

出现以下任一情况时，必须重新评估本记录，并优先实施 P0 新格式（v9）：

1. 考试要求从「现场监考」变为「远程 / 无人监考」；
2. 题干或答题卡进入合规审计范围；
3. 发生同场题干扩散、答题卡伪造或时间窗绕过事件；
4. 需要把「防伪造 / 防篡改」作为对客户的合同承诺。

### R-05 网页考试模式：传输加密的边界与浏览器不可控

**事实**：v1.4.0 起可选「本地 exam-server + 学生浏览器」。按约定只用于**隔离局域网 + 现场监考**。
v1.5.0 起**默认 HTTPS（自签证书，首次启动自动生成）**；明文端口（默认 8080）只回 301 跳转、
不承载任何页面或数据；只有显式 `--tls off` 才回到明文 HTTP。

**影响**：
- 自签 TLS 能挡住同网段的**被动嗅探**（抓到的只是密文）；
- **不挡主动中间人**：除非学生把浏览器里看到的证书指纹与教师屏幕核对一致——自签没有公共 CA 背书；
- **不防主机木马与浏览器扩展**：它们本来就能读页面内存与设备上的密钥，网页应用无解；
- 浏览器无法阻止 DevTools、切屏、截图、搜索；
- 教师机是单点：断电/休眠/崩溃会影响全场；
- 服务端只持有考试包与 K_manifest，**不持有 master 与标准答案**。

**补偿**：自签 TLS（v1.5.0 起默认开）、启动横幅打印证书指纹供核对、
外部证书启动自检（私钥 / EKU / 链；v1.6.0 起）、明文端口只做 301 跳转、
专用 AP、关闭客户端隔离、现场监考、UPS、答案实时落盘、事件日志。
v1.4.3 起额外两项：服务端启动时三源校时（默认只告警，可配置为不通过拒绝启动）、
作答状态文件与事件日志只授予当前系统账户（Windows 受保护 DACL / Unix 0600）。
v1.4.5 起「答案实时落盘」才真正成立：每次保存都写加密状态，崩溃后重登可恢复未交卷作答。

**残余风险**：主动中间人（学生未核对指纹时）、教师机/学生机上的恶意软件、浏览器不可控、
教师机单点故障——这些**不因启用 TLS 而消失**，仍按上述补偿措施与现场监考接受。
