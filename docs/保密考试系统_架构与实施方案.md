## 1. 目标与非目标

**目标**：教师端编排多场考试 → 打包加密题库 → 生成学生端自解压包 → 学生凭「学号 + 网络时间门禁」
解锁 → 离线抽题生成个人试卷 → 离线作答 → 答题卡加密落盘 → 教师端批量回收、校验、判分；
可选地，用同一个考试包起一个局域网网页服务，让学生在浏览器里作答。

**非目标**（明确不做，见 §12）：

- 在线身份认证、服务端签名、实时监控（网页监考页只做进度与收卷，不构成监考）；
- 作弊防控（锁屏 / 进程监控 / 截屏检测 / 人脸识别）；
- 防拥有本机完全控制权的学生逆向；
- 逐题难度上下限过滤。

## 2. 三个结构性矛盾（决定了整个架构）

### 2.1 矛盾一：自解压包的密码不可能「只嵌在外部壳里」

SFX = stub + 加密数据。stub 运行时必须拿到密钥才能解密，所以：

- 密钥编译进 stub → 反汇编 / 字符串搜索 / 挂钩解密函数即可取出；
- 更致命的是：**多个学生共用一个密钥**时，一个人拿到就等于全班拿到。

**对策（已落地）**：

1. 密钥不写明文常量，而是**混淆存放**（`EXAMKEY1` + 32 字节 XOR 掩码）——只挡 `strings`，
   不冒充密码学保护；
2. **每场一个独立 `session_secret`**，泄漏面从「全班」缩到「某一场」；
3. 真正防线不是混淆，而是「即使拿到 `K_manifest`，也只能读场次表；题干需要**合法学号** +
   一次 Argon2id」。

### 2.2 矛盾二：网络时间门禁是最薄弱的一环

客户端永远可以被改时间。目标是**抬高成本**，而不是做到不可破：

| 级别 | 做法 | 攻击成本 |
|---|---|---|
| L0 | 读本机系统时间 | 改系统时间，0 成本 |
| L1 | HTTP `Date` 头 | 改 hosts / 中间人，低 |
| **L2（已实现）** | **3 个 HTTPS `Date` 取中位数 + fail-closed** | 需同时劫持多数源，中 |
| L3 | L2 + 服务端签名时间令牌（Ed25519） | 需要私钥，高 |
| L4 | L3 + 令牌绑定学号 / 场次 + 服务端记录一次性 nonce | 需要私钥 + 在线，最高 |

**已实现 L2**；L3 以**可选协议**形式实现（默认 `off`，需自建服务）；L4 的「服务端防重放部署」
**未提供**（`worker/` 只有空的 `src/`）。关键取舍：**失败即拒绝**——宁可考不了，也不能用被篡改的
时间放行。

### 2.3 矛盾三：「题库在包里」与「考试保密」冲突

学生端解压后题库就在本地。真正防泄漏只能在线发题，与「离线自解压包」的需求直接冲突。折中：

- 包里只放**本场**的题（不是全部题库）；
- 每场独立 `session_secret`，场次之间密码学隔离；
- 答题卡 / 试卷指纹绑定，支持事后溯源；
- 明确承认「同场题干可解」，把它写进风险记录（R-01），不假装解决。

## 3. 总体架构

### 3.1 离线模式（默认）

```text
教师机 ExamAdmin + exam-builder
  题库 / 学生与班级 / 场次 / 密钥 / 打包
        │ 分发（U 盘 / 群文件 / 内网共享）
        ▼
StudentClient.exe（stub + 加密 payload + 混淆密钥区 EXAMKEY1）
  exam-client：学号(+PIN) → 时间门禁 → 解信封 → 解本场题库 → 抽题 → 作答 → .eea
        │ 回收（现场拷贝）
        ▼
教师机：verify-answer-sheet --package → 判分 → CSV / 缺考 / 收据 / 审计
```

离线模式**没有服务器**；唯一外部依赖是解锁时的 HTTPS 取时。

### 3.2 网页模式（v1.4.0 起，可选）

```text
教师机 ExamAdmin「网页考试…」→ exam-server（单进程）
  ├─ 包 + keyfile → payload / header / 密钥区 → 本场题库
  ├─ 启动校时（warn / require / off）、TLS（自签 / 外部证书）、明文端口只 301
  ├─ 会话 / 限速 / 状态写盘 / 自动收卷 / 监考页（独立令牌）
  └─ answers-dir：state/、*.eea、events.jsonl、monitor.token、blocked.json、tls/
        ▲ HTTPS
学生浏览器（登录 → 取卷 → 作答 → 交卷）；教师另开浏览器看 /monitor
```

服务端**不持有 master、不持有标准答案**：只需要考试包与 `K_manifest`（`--keyfile`）；
题库在打包时已剥离 `answer` / `judge`，所以监考页也不可能下发答案。

**版本口径要写全**：网页模式在 **v1.4.0 提供**，但「**可正常作答**」实际**自 v1.4.2 起**——
v1.4.1 才修 `body`（选项 / 模板 / 改错代码）不渲染（此前选择题与填空 / 改错是空白），
v1.4.2 才修填空 / 改错按离线格式编码（此前判分全错）。只写其中一个版本号都会与发布说明冲突。

### 3.3 服务端进程内结构

- 自建 HTTP/1.1（`std::net::TcpListener` + 线程一连接）+ `rustls`/`ring` + `rcgen`；
  没有引入 axum / tokio / SQLite；
- 全局 `Mutex` 保护会话 / 限速桶 / 监考快照 / 封禁表，每个 `(学号, 场次)` 另有写盘锁；
  加密与写盘在全局锁**之外**执行（v1.4.4 起），避免一个学生的 fsync 堵住全场；
- 状态是加密 JSON（`state/<学号>-<场次>.json`），`events.jsonl` 写锁 + 整行一次写出；
- 自动收卷后台线程每 15 秒扫一轮，失败按 15→30→60→120→300 秒退避。

## 4. 数据流

### 4.1 打包（教师机）

```text
题库 JSON（含答案）
  → 管理端校验 + 生成 manifest（version 2）
  → 写临时题库（剥掉 answer / judge）                    ← 纵深防御第一层
  → exam-builder build：读 manifest / banks / stub
       每场 session_secret；每生信封（Argon2id(学号‖场次‖salt[‖PIN])）
       组 payload（header_ct + key_area + blob_area）；再剥一次 answer/judge ← 第二层
       追加到 stub 末尾 + payload_len + EXAMTAIL
       可选 --emit-keyfile（K_manifest）/ --emit-pins（PIN CSV）
  → StudentClient.exe（双击即用）
```

`--emit-pins` 是 `build` 的参数（`--pin-login` 必须配它才导得 PIN 表）；`--emit-keyfile` 产出的
`K_manifest` 是网页服务端唯一需要的密钥材料。

master 只能通过环境变量 `EXAM_MASTER` 或 `--master-file` 传递（文件权限由教师自管）。
**命令行 `--master` 参数已经移除**：它会把密钥暴露在进程列表（`ps` / 任务管理器）里，
`AGENTS.md` §5 明确禁止；需要自动化时请用文件或环境变量（优先级：`--master-file` > `EXAM_MASTER`）。
本项目的脚本与文档示例一律不提供 `--master` 用法；看到别人这样传，说明使用的是旧版二进制。
学生端 `exam-client` 同样只有 `EXAM_MASTER` / `--master-file`。

### 4.2 解锁与作答（学生机）

```text
启动 → 读尾部 EXAMTAIL → 校验版本 3..=8 → 取密钥区 K_manifest（或 master）
  → 解 header（场次表 / salt / KDF / time / student_review / pins_ct）
  → 【时间门禁】三源中位数；prefer/require 先试签名令牌
  → 时间窗内选场次（重叠取最小 session_id）
  → entry_key = Argon2id(学号‖场次‖salt[‖PIN]) → 按 tag 定位信封（一次 Argon）
  → session_secret → HKDF 解题库 → seed 抽题 → Paper → 渲染
  → 每次变化加密写 .eea（.tmp + rename）→ 交卷 / 到点冻结
```

**不变量**：时间门禁必须在**派生入场密钥之前**（`crates/client/src/workflow.rs::unlock`
的步骤顺序）。把它挪到后面等于允许「先解密再判断时间」。

### 4.3 收卷与判分（教师机）

```text
.eea → exam-builder verify-answer-sheet --file X.eea --package 学生端.exe
        用 master 派生 K_manifest → 解卡 → 重算该生试卷 → 比对指纹与 qids
        → JSON（退出码区分「包不可用 / 指纹不一致」）
  → ExamAdmin 判分（按题型勾选；问答 / 代码人工给分；双击改分留痕）
  → 5 份 CSV（明细 / 汇总 / 未判 / 全量 / 考生成绩表）+ 缺考名单
  → 可选：答题卡收据（Ed25519）、审计哈希链
```

`verify-answer-sheet` **强制要求 `--package`**（缺失时返回码 5）：没有包就无法证明「这份卡对应本包
原卷」。

### 4.4 网页作答（v1.4.0 起）

```text
教师：exam-server --package --keyfile [--tls auto|off] [--answers-dir]
  → 启动校时（默认 warn）→ 生成/复用监考令牌 → 绑端口 → 打印地址与证书指纹
学生：GET / → POST /api/login（CSRF + 限速 + try_unlock_session_with_pin）
  → GET /api/paper（不含标准答案）→ PUT /api/answer（单题 ≤1 MiB / 整卡 ≤16 MiB）
  → POST /api/submit（冻结 → seal → 写 .eea，先 fsync 再记已交卷）
  → GET /api/time（剩余秒数，顺带滑动续期 cookie）
教师：GET /monitor?t=<token>（15 s 轮询）
  → POST /api/monitor/collect / collect-all / block / unblock（令牌 + CSRF + 审计）
```

到点收卷：页面在剩余 0 秒时自动 `POST /api/submit`；页面已关闭的由后台线程每 15 秒扫一轮
（最多延迟 15 秒）。交卷**不受场次时间窗限制**（便于补交），但过期后不能再改答案。
`--session` **不绕过时间窗**：它只是「指定场次」，仍然要求当前时间落在该场次窗口内。

## 5. 技术栈选择与理由

| 组件 | 选型 | 理由 | 被否掉的方案 |
|---|---|---|---|
| 管理端 | Python + PySide6 + pydantic + cryptography + PyInstaller | 低频重配置工具，开发效率 > 运行时性能；JSON 校验与 CSV 导入最省事 | Tauri（构建链复杂）、Electron（体积 150MB+） |
| 学生端 | Rust + egui/eframe，**分发为单文件**（Windows exe / Linux ELF 或 AppImage） | 无需额外语言运行时；考试逻辑无需跨进程传密钥 | 两段式 SFX（杀软特征翻倍、清理复杂、密钥要过管道） |
| 抽题随机源 | `ChaCha8Rng` + 手写 Fisher-Yates | `StdRng` 不保证跨版本一致；`slice::shuffle` 实现可能变 | `seed_from_u64`（依赖 SplitMix64 细节） |
| 加密 | AES-256-GCM + HKDF + Argon2id | 标准组合，Rust / Python 两侧都有成熟实现 | — |
| 序列化 | serde_json（**不做压缩**） | 设计稿曾计划 zstd，实际未引入——包体积主要由题库文本决定，压缩收益不足以抵消依赖与调试成本 | zstd / gzip（未采用） |
| 取时 | WinHTTP（Windows）/ curl（其他） | 无 C 编译依赖、证书校验交给系统；NTP 的 UDP 123 常被校园网屏蔽 | ureq / reqwest（ring / aws-lc-rs 需完整 C 工具链） |
| 高亮 | syntect（纯 Rust，离线） | 不联网、不执行代码 | 调用外部高亮工具 |
| 网页服务端 | 自建 HTTP/1.1 + rustls + ring + rcgen | 不引入 tokio 运行时，单文件部署；TLS 静态链接、不依赖系统 OpenSSL | axum/tokio + SQLite（未做，见 §13） |

**编译工具链**：默认 MSVC；C 盘紧张时可用 `x86_64-pc-windows-gnu` + MinGW
（`.cargo/config.toml` 固定 linker）。MSVC 产物的兼容性与杀软误报率更好，正式发布优先用它。

## 6. 关键机制

### 6.1 密钥体系

```text
master（32B 随机，64-hex 展示，只存在教师机）
  │
  ├─ K_manifest = HKDF(master, salt="", info="manifest")
  │      ├─ 加密 Header（AAD "header-v3"）        ← 这是它唯一的解密对象
  │      ├─ 作为答题卡密钥的 IKM：
  │      │     K_sheet = HKDF(K_manifest, salt=hex(paper_fingerprint), info="ees-answer-sheet-v1")
  │      └─ 混淆后写进学生端 exe 的密钥区（EXAMKEY1 + 32B XOR 掩码）
  │
  ├─ PIN 表密钥 = HKDF(master, salt=包 salt, info="student-pins") → 加密 pins_ct
  │
  └─ 每生 entry_key = Argon2id(学号 ‖ session_id ‖ salt ‖ [PIN])   ← 与 K_manifest 无关
         └─ 解出信封内层：{ student_id, session_secret, exams, sections }
                └─ K_bank = HKDF(session_secret, info="bank") → 解密本场题库（PayloadData）
```

两点必须说清，否则会把边界理解错：

1. **信封不是 `K_manifest` 加密的**。信封的密钥是 `Argon2id(学号 ‖ 场次 ‖ salt ‖ [PIN])`，
   定位靠 `tag = blake3(entry_key)[..8]`；`K_manifest` 不参与信封解密，也解不开 PIN 表
   （PIN 表用 master 另派生）；
2. `K_manifest` 的 salt **必须为空串**：若用真实 salt 派生，客户端会陷入「要 salt 才能解 header、
   要解 header 才能拿 salt」的死锁。

KDF 生产参数（`KdfParams::default()`）：**m = 64 MiB、t = 3、p = 1**。
本机实测（2026-10-22，20 线程；**既有记录，本次重写未复跑**）：

| 参数 | 单次 | 8 线程枚举 10⁵ 学号 | 8 线程枚举 10⁶ 学号 |
|---|---|---|---|
| 19 MiB / t=2（旧值） | 18.2 ms | 3.8 分钟 | 0.6 小时 |
| **64 MiB / t=3（现值）** | **92.2 ms** | **19.2 分钟** | 3.2 小时 |
| 256 MiB / t=3 | 392.6 ms | 81.8 分钟 | 13.6 小时 |

> 旧值把枚举成本低估了一个数量级（文档曾误称 67 分钟，实测仅 3.8 分钟）。
> 现值的代价：单次派生约 92 ms；20 线程并发下 1500 个信封约 7 秒，核数少的机器按比例变长。
> **仍然诚实**：学号是低熵数据，离线可验证就意味着最终可枚举——参数只是抬高成本，不是密码学保证。

**参数必须限幅**：包内 header 是**不可信输入**。argon2 crate 的 `MAX_M_COST` 就是 `u32::MAX`，
一个 `m_cost = 4e9` 的包会让客户端申请约 4 TB，直接 abort 且没有可读错误。
因此 `KdfParams::validate()` 限定 `m ∈ [8 KiB, 1 GiB]`、`t ∈ [1, 16]`、`p ∈ [1, 8]`；
另有 `meets_production_strength()` 要求 m ≥ 64 MiB、t ≥ 3，低于此强度只能由 `--allow-weak-kdf`
显式构建（演示 / 测试）。

### 6.2 信封与场次隔离

信封布局自「容器第二版设计」起（`v2` 是设计代号，与容器版本号 v4–v8 是两套编号），
**每个学生一个信封**：

```text
envelope_j = AEAD( Argon2id(学号_j ‖ session_id ‖ salt [‖ PIN]),  student_id ‖ S_j ‖ exams ‖ sections )
data_i     = AEAD( HKDF(S_i, "bank"),  { banks, picks, bank_index, ranges } )
```

- 包里**不再有任何学号**（单元测试 `student_ids_never_appear_in_payload` 覆盖十进制 ASCII /
  LE / BE 三种形式）；
- `S_i` 每场随机生成、只存在于该场学生的信封里 → **场次间密码学隔离**；
- 枚举名单必须对每个候选学号跑一次 Argon2id，成本见 §6.1。

**鸡生蛋问题**：要先知道场次才能匹配学号。解法是「先解 header 拿到场次表，再用学号逐个试信封」——
header 由 `K_manifest` 解密（不依赖学号），信封由学号派生密钥解密；信封上的
`tag = blake3(entry_key)[..8]` 让定位只需一次 Argon2。时间门禁插在两者**之间**，因此它发生在
派生入场密钥之前（§4.2）。

### 6.3 时间门禁

```text
输入学号
  → 并发请求 3 个 HTTPS 源（超时 3s；最多采 2 轮，第二轮只重查失败的源）
  → 各自解析 Date 头 → 计算 now 与分歧
  → 成功源 < 2 或分歧 > 阈值 → 拒绝解锁（fail-closed）
  → 中位数作为 now → 找到 now ∈ [start, end) 且信封能解开的场次
  → 无匹配 → 明确区分「未到时间 / 已结束 / 不在名单 / PIN 错」
  → 命中 → 派生 entry_key → 解信封 → 解题库 → 进入作答
```

阈值（`spread_limit()`）：**≥3 源为 60 秒，2 源为 10 秒**。
2 源时收紧是有意的——中位数在偶数个源上会退化为较大的值，容差必须更小。
分歧超限时**整体拒绝**，不会剔除离群源后重算：剔除逻辑本身就需要一个「谁对」的判据，
而唯一可信的判据恰恰是这里要建立的东西。

**网页服务端（v1.4.3）**：`exam-server` 启动时用同一份三源清单（`timegate::default_sources()`）校时，
把「网络 − 本机」的差值存进 `clock::Clock`，之后所有场次窗口、限速窗口、最后活跃时间都用
`本机时钟 + 偏移`；不改系统时钟，也不在每次请求时取时（开考后断网不影响判定）。
取时失败时按档位处理：`warn`（默认）只告警并按本机时钟继续，`require` 拒绝启动，
`off` 完全不发请求。这样「教师机时钟错误」从「直接改变开考 / 收卷判断」降级为
「启动日志里的一条警告」。

### 6.4 抽题

```rust
// 种子：显式 blake3，不依赖 rand 的内部细节
let seed: [u8; 32] = blake3(学号 ‖ 场次 ‖ salt);
let mut rng = ChaCha8Rng::from_seed(seed);

// 每个题库一份池子，手写 Fisher-Yates（只依赖 next_u32）
fisher_yates_shuffle(&mut pool, &mut rng);
let picked = pool[..pick];
```

**不变量**：同 `(student_id, session_id, salt)` 必得同一份试卷。
`picker.rs` 里有黄金向量 `GOLDEN_FP`；改抽题算法必须同步更新它并说明原因——
改它意味着所有已发出的试卷指纹失效。

**难度区间**（早期版本起；发布说明从 v0.14.0 起记录）：只约束抽出的 N 题的**平均值**，
不对单题设上下限。实现是位集 DP 找 size=N 且 `sum ∈ [N·lo, N·hi]` 的子集；组合规模过大时
退化为滑窗 + 贪心修补。单边区间（只给 min 或只给 max）在构建期直接报错，不静默忽略。

**大题 / 部分**（v0.14 / v0.15）：`Section` 固定题库 + `parts` 各自题数与**精确**难度；
同一场次同一题库多个大题自动去重；抽题顺序 = UI 里 ↑/↓ 的顺序。
学生端**不显示**「第 x 部分」，只按大题分块。

### 6.5 容器格式与版本

```text
文件 = [ stub（学生端 exe、ELF 或 AppImage 模板） ][ payload ][ payload_len（u64 LE） ][ "EXAMTAIL" ]
                                                             ↑ 从这里倒着定位 payload

payload = MAGIC "EXAMPKG3"(8) | version(u32 LE) | header_len(u32) | header_ct
        | key_len(u32) | key_area | blob_area
                          │            └ 各场次题库密文（按 data_off/data_len 索引）
                          └ "EXAMKEY1"(8) + 32 字节掩码后的 K_manifest；key_len = 0 表示未内嵌
```

- `header_ct` 用 `K_manifest` 加密（AAD `header-v3`）；信封与题库在 `blob_area`，各自用
  `entry_key` / `K_bank` 加密；
- `EXAMTAIL` 尾部既用于倒着定位 payload，也用于**拒绝把已打包的学生端再当 stub 用一次**
  （否则上一场的信封与题库会完整留在新文件里，而界面看不出异常）；
- 长度字段一律 `u32::try_from`，不 `as` 静默截断。

| 版本 | 引入 | 内容 |
|---|---|---|
| v3 | 早期 | 旧信封布局（仍可读） |
| **v4** | 早期（**发布说明未覆盖，暂无可查记录**） | PIN 表进 header；普通包的当前版本 |
| **v5** | 早期（**发布说明未覆盖，暂无可查记录**） | 签名时间令牌（`mode != off`） |
| **v6** | v0.14.0 | 按大题（`sections`） |
| **v7** | v0.15.0 | 大题下的部分（`parts`） |
| **v8** | v1.1.1 | 含代码简答题（`qtype = code`） |
| v9 | — | **P0 per-student / Header 签名，未实现** |

v4 / v5 的引入版本在发布说明里查不到（首个小节是 v0.14.0）；历史文档里出现过
`v0.11.1` / `v0.13.1` 的写法，**属于据历史文档的推断，不是一手记录**，引用时必须带上这个限定。

规则：同一包命中多行时版本**取最高者**；解析侧接受 `3..=8`（`MIN_SUPPORTED_VERSION = 3`）；
无代码题时最高只写到 `LEGACY_HIGH_VERSION = 7`（只有大题 / 部分才升到 v6 / v7），避免把普通包
全部挡在门外；旧学生端遇到更高版本**明确拒绝**。

**为什么用版本而不是能力位**：能力位需要客户端理解每一位的含义，旧客户端遇到未知位只能猜；
版本号让「不认识的包」变成确定性的拒绝，而不是静默显示空白题（v1.1.1 的真实教训）。

### 6.6 答题卡

```text
文件：MAGIC(8) "EESANS02" | version(u32) | student_id(u64) | session_id(u32)
      | paper_fingerprint(64 个 hex 字符 = 32 字节) | AES-256-GCM 密文
密钥：HKDF(K_manifest, salt = hex 解码后的试卷指纹, info = "ees-answer-sheet-v1")
AAD ：student_id ‖ session_id ‖ paper_fingerprint（换人 / 换场 / 换卷都会解不开）
内容：{ version, student_id, session_id, paper_fingerprint, qids[], answers[], updated_unix,
        submitted, submitted_unix?, chosen_code_languages{qid→lang}? }
```

- `qids` 与 `answers` **等长同序**；`None` = 未作答，`Some("")` = 作答但留空；
- 指纹只哈希**题目 ID**（题干订正不应改变试卷指纹）；
- 长度上限：单题 1 MiB、整卡 16 MiB（`MAX_TOTAL_ANSWER_BYTES`）；
- `EESANS01` / v1 仍可读（`MIN_SUPPORTED_VERSION = 1`），读入后统一升为 v2 再写回；
  **v1.2.x 及更早的管理端 / builder 读不了 v2**（会报「不支持的答题卡版本 2」）；
- 损坏恢复：`.recovered` 备份名唯一递增（`.recovered`、`.recovered.N`），保存失败时不覆盖原卡；
- 文件名 `answers-<学号>-<场次>-<指纹前 8 位>.eea`，试卷指纹进文件名，避免同名覆盖。

### 6.7 工程文件、审计、收据

| 机制 | 格式 | 要点 |
|---|---|---|
| 主密钥备份 | `EESKEY02`（兼容 `EESKEY01`） | Argon2id(口令) + AES-256-GCM；8 位指纹核对；原子写 |
| 工程文件 | `EESPROJ3`（兼容 `EESPROJ2`） | 默认开启；头部带 KDF 参数并在调用前限幅（time ≤16、memory 8 MiB–256 MiB、parallel ≤8）；`.bak` + 原子替换 |
| 审计日志 | `audit-YYYYMM.jsonl` | 每行 `prev` + `hash`（blake2s-128）哈希链，改一行即断链；事件含打开 / 保存 / 打包 / 人工改分 / 签发 / 验证收据 |
| 答题卡收据 | JSON | Ed25519 对**规范化 JSON**（去掉 `signature`、`sort_keys`、紧凑分隔符）签名；内嵌公钥、`package_sha256`、每卡 sha256；签发人指纹 **16 位** |

**收据的边界**：只证明「收卷之后没被改」，**不证明**「这份卡是本人填的」。

### 6.8 网页服务端的安全与写盘

```text
浏览器 ──HTTPS(自签/外部证书)──► exam-server（单进程，每连接一线程，HTTP/1.1）
                                   ├─ /api/login   学号 + 可选 PIN → HttpOnly cookie
                                   ├─ /api/paper   本人试卷（答案不下发）+ 已保存作答
                                   ├─ /api/answer  每次保存即加密落盘
                                   ├─ /api/submit  封存 → 写 .eea（与离线端同格式）
                                   ├─ /api/time    服务器时间 + 剩余秒数（15 s 校准）
                                   ├─ /assets/*    app.js / app.css / monitor.*（内嵌进二进制）
                                   └─ /monitor     监考页 + 四个写接口（独立令牌）
```

- **登录**：`POST /api/login` 要 `X-EES-CSRF: 1`；按**真实 TCP 对端 IP**（`peer_addr`，不信
  `X-Forwarded-For`）与学号各一分钟窗口限速（默认每 IP 60 次/分钟、每学号 10 次/分钟，
  `--login-rate-limit 0` 关闭）；IP 桶在「拿到学号之后」才计数——同一 NAT 后面全班共用一个桶，
  坏请求 / 扫描器不该把真实学生挡在门外；被封禁的学生直接 403；
- **会话**：`ees_token` cookie（`HttpOnly; SameSite=Strict; Max-Age=3600`，TLS 下加 `Secure`），
  `/api/paper`、`/api/time` 滑动续期；交卷（默认策略）与退出立即失效；同一学号重登顶掉旧 token；
- **状态**：每次保存都加密写 `state/<学号>-<场次>.json`（原子写 + fsync），交卷路径额外 fsync；
  写盘串行化并复查，旧快照不会覆盖「已交卷」；
- **事件**：`events.jsonl` 并发写有锁 + 整行一次写出；
- **响应头**：所有响应带 `Content-Security-Policy`（`default-src 'none'; script-src 'self'; …`）、
  `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、
  `Permissions-Policy: geolocation=(), camera=(), microphone=()`；行内脚本 / 样式已拆到 `/assets/`，
  否则 CSP 只能靠 `'unsafe-inline'`；**301 跳转只带 `nosniff`**（无 body，其余头对它没有意义）；
- **TLS**：默认 `auto`（没有证书就生成 ECDSA P-256 自签证书，SAN 含本机地址，EKU `serverAuth`，
  365 天、提前 30 天自动重签）；ALPN 只声明 `http/1.1`；外部证书启动自检在内存里跑一次真实握手，
  致命项拒绝启动、警告项默认放行（`--tls-check strict` 收紧）；
- **文件权限**：状态目录 / 事件日志 / 令牌 / 私钥在 Windows 用受保护 DACL（仅当前用户），
  Unix `0600` / `0700`，旧文件启动时补收紧；
- **监考页**：独立令牌（32 字节 hex ＝ 64 hex 字符，不落 cookie、只走 `X-Monitor-Token`），
  弱令牌默认拒绝启动；写操作要求令牌 + CSRF，写操作之间 **1 秒冷却（429）**，审计只记令牌指纹
  前 8 位；收卷复用 `seal_and_export` 同一条路径；终止顺序固定为「先封存 → 再吊销 token → 再封禁」，
  解除只恢复登录，**封存不可撤销**。

### 6.9 题目级 `samples`（v1.9.0 起）

`Question.samples` 是**代码题 / 大题**的输入输出示例，v1.9.0 新增；v1.9.1 补上网页端渲染
（桌面端早就显示）。它与 `answer.samples`（大题评分参考，嵌在答案里）是两件事：
前者随包下发、给学生看；后者随 `answer` 一起被剥离。

`samples` 的**结构上界**（JSON Schema / 生成器）是：最多 20 组，`input`、`output` 各 ≤ 4096 **字符**。
但**实际门禁更严**：Rust 校验、管理端导入、`verify_bank.py` 三处一致要求
**每组 `input + output` 合计 ≤ 4096 UTF-8 字节**，且两者不能同时为空。
schema 只是宽松上界——**以合计字节为准**，否则会出现「schema 过了、导入被拒」的排查成本。

> 中文题干下 4096 **字符** 的 UTF-8 长度可达 12 KB，比 4096 **字节** 宽松 3 倍；
> schema 也没有「两组字段合计」这个概念（它只逐字段限长）。写题库时按字节算。

### 6.10 发布包与文档链路

Windows 发布 ZIP 不只是程序，还是一份**能离线打开的手册**；目录式 Linux ZIP 沿用相同结构：

- 根目录：`开始这里.md`、`使用说明.md`（= 教师使用手册）、`风险接受记录.md`；
- `docs/`：全部文档（手册里的相对链接指向这里）；
- `tools/bank_qc/`：题库自检工具（Python 3.10+，只用标准库）；
- `示例题库/`：三个演示题库 + 一份「为什么门禁会 FAIL」的 README；
- `ExamAdmin/`：`ExamAdmin.exe`、`exam-builder.exe`、`stub-template.exe`、`_internal/`
  （含 `exam-server.exe`）、许可证。

构建脚本 `scripts/make-release-zip.sh` 会改写手册里的相对链接，并**做死链自检**：包内任何 `.md`
的相对链接都必须能打开，围栏代码块必须成对，否则构建直接失败。这条门禁的起因是发布包
《使用说明》曾出现 10 处死链——手册在仓库里与 `docs/` 同级，进包后被挪到根目录，链接没跟着改。

**由此得到的三条写文档规矩**：

1. `docs/` 内的文档互相引用**只用裸文件名**（`[风险接受记录](风险接受记录.md)`），
   根副本会被自动改写成 `docs/…`；
2. `tools/bank_qc/` 里的文档用 `../../docs/…`（上两级 = 包根），这个形式在包里也成立；
3. **不给 `crates/`、`.agents/`、`schemas/`、`scripts/`、`AGENTS.md` 做相对链接**——它们不随包分发，
   链接在包里必然是死链，构建会判失败。这些目录只能用行内代码提及。

### 6.11 Linux 独立分发与示例快照

- Linux x86_64 可构建目录式 ZIP，或分发教师 AppImage 与生成后的学生 AppImage。`linux-appimage` 以 Ubuntu 22.04 构建、烟测并上传 CI 产物；**tag 触发的 GitHub Release 不上传 Linux 产物**。
- 学生 AppImage 不改变考试格式：builder 把现有 payload 追加到外层 AppImage，客户端从外层文件尾部读取；内层只负责提供原生程序和字体。答题卡与教师工程不写入临时解压目录。
- 新工程默认显示公开示例。打包版按示例内容哈希保存快照，工程引用用户数据目录，避免 AppImage 解压目录清理或升级后丢失题库。`--selftest` 直接验证资源，不创建快照。

构建、运行要求和迁移步骤见 [Arch Linux 指南](arch-linux.md)。

## 7. 数据结构

### 7.1 题库（原生格式）

```json
{"exam_id": "math-2026-final", "title": "高等数学 期末考试", "pick": 20,
 "questions": [{"id": "q001", "type": "single", "stem": "……",
   "body": {"kind": "options",
            "options": [{"key": "A", "text": "……"}, {"key": "B", "text": "……"}]},
   "answer": {"kind": "single", "answer": "B"},
   "score": 2, "difficulty": 2, "kp": "1.1"}]}
```

- `body.kind = "options"` 是**当前写法**（`options` 是 `{key, text}` 数组）；旧的
  `"options": ["A……", "B……"]`（字符串数组、没有 `body`，即 `banks/demo/` 与发布包 `示例题库/`
  里那些演示题库的写法）
  **模型层仍能读**（`Question.options` 向后兼容，读入后归一），但 **`tools/bank_qc/verify_bank.py`
  会判 error**（`body 必须是对象`）——所以新题库一律按上面写，别学演示库；
- `kp` 在**原生题库里必填**（`N.M`，1.1–12.9）；`difficulty` 按题型取值（多选固定 `9`，
  大题 1–4，其余 1/2/3）；
- `samples` 只对代码题 / 大题有意义，限额见 §6.9；
- 字段与校验见 [题库JSON规范](题库JSON规范.md)；出题口径见
  [出题质检与难度口径](出题质检与难度口径.md)。

### 7.2 manifest（打包输入，管理端生成）

```json
{"version": 2, "salt": "00112233445566778899aabbccddeeff",
 "kdf": {"m_cost": 65536, "t_cost": 3, "p_cost": 1},
 "sessions": [{"session_id": 1,
   "start": "2026-12-20T09:00:00+08:00", "end": "2026-12-20T11:00:00+08:00",
   "students": [2021001, 2021002],
   "exams": [{"file": "demo/math.json", "pick": 3}], "sections": []}],
 "time": {"mode": "off", "url": "", "pubkey": "", "max_skew": 300},
 "student_review": "none"}
```

- `students` 用 `u64`（真实学号常超 `i32::MAX`）；
- 时间**必须带显式时区**（`+08:00`）；两端都拒绝无偏移时间（会被当成 UTC，静默偏移 8 小时）；
- `max_skew` 的 schema 范围是 **30–3600**；
- `sections` 非空则走「按大题」模式，`count` / `difficulty` 可由 `parts` 汇总。

### 7.3 Header 与 Payload（包内结构）

```rust
struct Header {           // 由 K_manifest 加密（AAD "header-v3"）
    version: u32, salt: String, kdf: KdfParams,
    sessions: Vec<SessionHeader>,     // start/end/data_off/data_len/envelopes
    student_review: StudentReviewPolicy,
    pins_ct: Option<String>,          // 用 master 派生密钥（"student-pins"）加密的 PIN 表
    time: TimeConfig,                 // off / prefer / require
}
struct PayloadData {      // 由 session_secret 派生密钥加密，答案已剥离
    banks: Vec<ExamBank>, picks: BTreeMap<String,u32>,
    bank_index: Vec<BankIndex>, ranges: BTreeMap<String,(u8,u8)>,
}
```

## 10. 工程踩坑清单（都会再犯，写下来）

| 坑 | 现象 | 现在的做法 |
|---|---|---|
| Python 调子进程不指定编码 | 中文 Windows 按 GBK 解 UTF-8，异常在读取线程被吞，界面只显示「无输出」 | 所有跨语言调用显式 `encoding="utf-8"`，兜底文案带退出码 |
| 用截图判断 GUI 布局 | DPI 缩放 / 多显示器导致结论完全错误（本项目误判 3 次） | 管理端 `--dump-ui` 自绘 PNG + `info.json`；学生端 debug 构建 + `EES_DEBUG_LAYOUT` |
| 测试用 `std::env::temp_dir()` | 本机 MSYS 下指向 `/tmp`，原生进程写不进去 | 统一用 `target/` 下的目录 |
| 时区字符串比较 | `+0800` 被按 `HHMM` 拆错，`+14:59` 可 panic | 两端都做 ASCII 检查 + 范围校验 + `checked` 运算 |
| `exam_id` 直接拼路径 | 可写到临时目录外 | 按危险特征拒绝，写入端再复核 |
| release 里保留 `EES_*` | 把测试钩子发给学生 | 全部收进 `diag_env` / `diag_path`（`#[cfg(debug_assertions)]`） |
| 表格解析返回「消耗行数」被当成新索引 | 解析器死循环，内存涨到十几 GB | 索引前进用 `i += take_table(...)`，并有回归用例 |
| 中位数在偶数源上退化 | 2 源时取到较大值 | `spread_limit()`：2 源 10 秒、≥3 源 60 秒 |
| 打包后再当 stub 用 | 新包沿用旧 K_manifest / 旧信封，界面看不出 | 尾部 `EXAMTAIL` 检测直接拒绝 |
| 已交卷状态被旧快照覆盖 | 重启后学生回到可编辑，卡被改写 | 写盘锁 + 写前复查 `submitted`；先 fsync 卡再记已交卷 |
| 登录限速按 `127.0.0.1` | 全场一个桶，30 人以上集体 429 | 按 `TcpStream::peer_addr()` 的真实对端 IP 分桶 |
| `answers/` 未被 `.gitignore` 覆盖 | 默认答题卡目录在仓库根，令牌 / 答题卡可能被 `git add -A` 提交 | `.gitignore` 覆盖 `answers/`、`monitor.token`、`*.eea`、`state/` |
| 并发写 `events.jsonl` 交错 | 12 条交卷只解析出 2 条 | 全局写锁 + 整行一次写出 |
| 证书缺 EKU | 浏览器报不可绕过的 `ERR_SSL_KEY_USAGE_INCOMPATIBLE` | 自签证书固定 `serverAuth`；外部证书启动自检 |
| 发布包死链 | 手册 10 处链接指向包里不存在的文件 | 构建时改写链接 + 死链自检（围栏按行状态机剥离） |
| 监考页写操作漏测 | 路由 / 响应头 / 鉴权写错，CI 全绿 | `smoke-monitor.sh` 的断言钉住页面、令牌、收卷、`tls-only`、弱令牌 |

## 12. 明确不做的事（以及原因）

| 不做 | 原因 |
|---|---|
| 机器指纹绑定 + 在线心跳 | 误伤高（换机房 / 换网卡即锁死）、隐私敏感、要求全程联网 |
| nibble XOR 当安全卖点 | 会反汇编的人半天可破；降级为「防 `strings` 随手搜」，真正防线是每场一密 |
| DOCX / PDF 导出 | Rust 无成熟 DOCX 库、排版成本高；考试以屏幕作答为主 |
| 代码题自动判分 | 编译运行学生代码有安全与公平风险 |
| 逐题难度上下限 | 抹掉老师「难易搭配」的空间，只保留平均值约束 |
| P0 per-student / Header 签名（v9） | 已作为风险接受（R-01 ~ R-04）；需要时按复审条件重启 |
| 包内可配置时间源 | 等于给时间门禁留后门（`time_sources` 曾因此被删除） |
| 浏览器本地草稿（IndexedDB） | 服务端是唯一权威副本；断网期间未同步的题会丢，属于已接受的网页端残余限制 |

**网页版 `exam-server`**（v1.4.0 起）：启动即三源校时、每次保存加密落盘、交卷/自动收卷、
写盘时序串行化、状态文件权限收紧、网页端作答控件与断线提示、会话 cookie 滑动续期、

独立监考令牌、写操作全审计；v1.8.1 补封禁持久化、弱令牌拒绝、`smoke-monitor.sh` 门禁；

**未完成 / 明确不做**：`worker/` 时间服务（只有空 `src/`）；P0 新格式 v9；答题卡作者身份认证；
PDF/DOCX 导出；逐题难度过滤；监考页的历史趋势 / 导出 / 秒级推送（现为 15 s 轮询）；
服务端仍未换 axum/tokio + SQLite（单文件、线程一连接）。

**已知技术债（按影响排序）**：

1. 每个静态资源单独建连（`Connection: close`，无 keep-alive）：一次页面加载约 6–7 次 TLS 握手，
   50 人同时开考时握手数 ×7；局域网可接受，首屏变慢再单独立项（第三方 vendored 资源已允许
   缓存 1 小时）；
2. 状态是加密 JSON 文件，没有索引：监考快照要遍历 state 目录，人数很大时是 O(N) 读盘；
3. 自动收卷精度 15 秒（轮询周期），到点判定的最后 15 秒内学生仍可能保存。

**接手建议**：

1. 先读 `AGENTS.md`（工作规则）与 [代码审阅报告](代码审阅报告.md)（问题索引见该文件的轮次表）；
2. 改抽题算法前先看 `picker.rs` 的 `GOLDEN_FP` 断言——改它等于作废所有已发试卷；
3. 改容器或答题卡格式前，先确认版本号分配（v9 是留给 P0 的，别挪用）；
4. 任何「看起来更安全」的改动，先对照 [安全边界与威胁模型](安全边界与威胁模型.md) 判断它是否
   真在威胁模型内；改网页端先跑 `smoke-web.sh` / `smoke-monitor.sh` / `smoke-tls-cert.sh`；
5. 文档里的链接必须能在发布包里打开——`make-release-zip.sh` 会构建失败，不要靠「我本地能点开」。
