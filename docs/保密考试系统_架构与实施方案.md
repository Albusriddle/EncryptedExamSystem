## 1. 目标与非目标

**目标**：教师端编排多场考试 → 打包加密题库 → 生成学生端自解压包 → 学生凭「学号 + 网络时间门禁」
解锁 → 离线抽题生成个人试卷 → 离线作答 → 答题卡加密落盘 → 教师端批量回收、校验、判分。

**非目标**（明确不做，见 §11）：

- 在线身份认证、服务端签名、实时监控；
- 防作弊（锁屏 / 进程监控 / 截屏检测）；
- 防拥有本机完全控制权的学生逆向；
- 逐题难度上下限过滤。

## 2. 三个结构性矛盾（决定了整个架构）

### 2.1 矛盾一：自解压包的密码不可能「只嵌在外部壳里」

SFX = stub + 加密数据。stub 运行时必须拿到密钥才能解密，所以：

- 密钥编译进 stub → 反汇编 / 字符串搜索 / 挂钩解密函数即可取出；
- 更致命的是：**多个学生共用一个密钥**时，一个人拿到就等于全班拿到。

**对策（已落地）**：

1. 密钥不写明文常量，而是**混淆存放**（`EXAMKEY1` + 32 字节 XOR 掩码）——只挡 `strings`，
   不冒充密码学保护；
2. **每场一个独立 `session_secret`**，泄漏面从「全班」缩到「某一场」；
3. 真正防线不是混淆，而是「即使拿到 `K_manifest`，也只能读场次表；题干需要**合法学号** +
   一次 Argon2id」。

### 2.2 矛盾二：网络时间门禁是最薄弱的一环

客户端永远可以被改时间。目标是**抬高成本**，而不是做到不可破：

| 级别 | 做法 | 攻击成本 |
|---|---|---|
| L0 | 读本机系统时间 | 改系统时间，0 成本 |
| L1 | HTTP `Date` 头 | 改 hosts / 中间人，低 |
| **L2（已实现）** | **3 个 HTTPS `Date` 取中位数 + fail-closed** | 需同时劫持多数源，中 |
| L3 | L2 + 服务端签名时间令牌（Ed25519） | 需要私钥，高 |
| L4 | L3 + 令牌绑定学号 / 场次 + 服务端记录一次性 nonce | 需要私钥 + 在线，最高 |

**已实现 L2**；L3 以**可选协议**形式实现（默认 `off`，需自建服务）；
L4 的「服务端防重放部署」**未提供**（`worker/` 为空）。

关键取舍：**失败即拒绝**。宁可考不了，也不能用被篡改的时间放行。

### 2.3 矛盾三：「题库在包里」与「考试保密」冲突

学生端解压后题库就在本地。真正防泄漏只能在线发题，与「离线自解压包」的需求直接冲突。折中：

- 包里只放**本场**的题（不是全部题库）；
- 每场独立 `session_secret`，场次之间密码学隔离；
- 答题卡 / 试卷指纹绑定，支持事后溯源；
- 明确承认「同场题干可解」，把它写进风险记录（R-01），不假装解决。

## 3. 总体架构

```text
┌──────────────── 教师机：ExamAdmin（PySide6）+ exam-builder（Rust CLI） ────────────────┐
│  ├─ 题库管理：导入原生 JSON / questions+answers 成对文件，schema 校验、预览               │
│  ├─ 学生与班级：学号池（u64）+ 命名分组（成员 ⊆ 全局名单）                              │
│  ├─ 场次编排：时间、名单快照、按题库抽题（可设平均难度区间）或按大题 / 部分              │
│  ├─ 密钥管理：生成 64-hex master、加密备份 .eekey、指纹核对                             │
│  └─ 打包：调 builder → 产出 StudentClient.exe（可嵌 PIN / 令牌 / 回看策略）             │
└───────────────────────────────────────┬──────────────────────────────────────────────┘
                                        │ 分发（U 盘 / 群文件 / 内网共享）
                                        ▼
                    StudentClient.exe（单文件，内含加密 payload + 混淆密钥区）
┌──────────────────────────────────────────────────────────────────────────────────────┐
│  exam-client（Rust + egui，单进程）                                                  │
│   1. 欢迎弹窗 → 输入学号（+6 位 PIN）                                                │
│   2. 取网络时间（3 源中位数；可选签名令牌）→ 匹配场次                                  │
│   3. 用 (学号, 场次, salt[, PIN]) 派生 entry_key → 解开自己的信封 → 得 session_secret   │
│   4. HKDF(session_secret) 解密本场题库 → 内存中剥离答案后的 ExamBank                   │
│   5. 按 seed = blake3(学号 ‖ 场次 ‖ salt) 抽题 → 渲染（Markdown 子集 / 代码高亮）      │
│   6. 答题卡随改随加密落盘（.eea）→ 交卷 / 到点冻结                                     │
└───────────────────────────────────────┬──────────────────────────────────────────────┘
                                        │ 提交答题卡
                                        ▼
┌──────────────── 教师机：批量校验 + 判分 + 审计 ────────────────────────────────────────┐
│  exam-builder verify-answer-sheet --package <exe>  →  解密 + 绑定校验 + JSON 输出        │
│  ExamAdmin：判分（题型勾选 / 人工改分）→ 五份 CSV / 缺考名单 / 收据 / 审计日志           │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

**没有服务器**。唯一外部依赖是解锁时的 HTTPS 取时。

## 4. 技术栈选择与理由

| 组件 | 选型 | 理由 | 被否掉的方案 |
|---|---|---|---|
| 管理端 | Python + PySide6 + pydantic + cryptography + PyInstaller | 低频重配置工具，开发效率 > 运行时性能；JSON 校验与 CSV 导入最省事 | Tauri（构建链复杂）、Electron（体积 150MB+） |
| 学生端 | Rust + egui/eframe，**合并为单 exe** | 无运行时、静态链接、体积小；单进程避免临时落盘 exe 与跨进程传密钥 | 两段式 SFX（杀软特征翻倍、清理复杂、密钥要过管道） |
| 抽题随机源 | `ChaCha8Rng` + 手写 Fisher-Yates | `StdRng` 不保证跨版本一致；`slice::shuffle` 实现可能变 | `seed_from_u64`（依赖 SplitMix64 细节） |
| 加密 | AES-256-GCM + HKDF + Argon2id | 标准组合，Rust / Python 两侧都有成熟实现 | — |
| 序列化 | serde_json（**不做压缩**） | 设计稿曾计划 zstd，实际未引入——包体积主要由题库文本决定，压缩收益不足以抵消依赖与调试成本 | zstd / gzip（未采用） |
| 取时 | WinHTTP（Windows）/ curl（其他） | 无 C 编译依赖、证书校验交给系统；NTP 的 UDP 123 常被校园网屏蔽 | ureq / reqwest（ring / aws-lc-rs 需完整 C 工具链） |
| 高亮 | syntect（纯 Rust，离线） | 不联网、不执行代码 | 调用外部高亮工具 |

**编译工具链**：默认 MSVC；C 盘紧张时可用 `x86_64-pc-windows-gnu` + MinGW（`.cargo/config.toml`
固定 linker）。MSVC 产物的兼容性与杀软误报率更好，正式发布优先用它。

## 5. 关键机制

### 5.1 密钥体系

```text
master（32B 随机，64-hex 展示，只存在教师机）
  │
  ├─ K_manifest = HKDF(master, info="manifest")     → 加密 Header / 信封 / 答题卡密钥
  │      └─ 混淆后写进学生端 exe 的密钥区（EXAMKEY1 + 32B XOR 掩码）
  │
  └─ 每生 entry_key = Argon2id(学号 ‖ session_id ‖ salt ‖ [PIN])
         └─ 解出信封内层：{ student_id, session_secret, exams, sections }
                └─ K_bank = HKDF(session_secret, info="bank") → 解密本场题库（PayloadData）
```

KDF 生产参数（`KdfParams::default()`）：**m = 64 MiB、t = 3、p = 1**。
本机实测（2026-10-22，20 线程）：

| 参数 | 单次 | 8 线程枚举 10⁵ 学号 | 8 线程枚举 10⁶ 学号 |
|---|---|---|---|
| 19 MiB / t=2（旧值） | 18.2 ms | 3.8 分钟 | 0.6 小时 |
| **64 MiB / t=3（现值）** | **92.2 ms** | **19.2 分钟** | 3.2 小时 |
| 256 MiB / t=3 | 392.6 ms | 81.8 分钟 | 13.6 小时 |

> 旧值把枚举成本低估了一个数量级（文档曾误称 67 分钟，实测仅 3.8 分钟）。
> 现值的代价：单次派生约 92 ms；20 线程并发下 1500 个信封约 7 秒，核数少的机器按比例变长。
> **仍然诚实**：学号是低熵数据，离线可验证就意味着最终可枚举——参数只是抬高成本，不是密码学保证。

**参数必须限幅**：包内 header 是**不可信输入**。argon2 crate 的 `MAX_M_COST` 就是 `u32::MAX`，
一个 `m_cost = 4e9` 的包会让客户端申请约 4 TB，直接 abort 且没有可读错误。
因此 `KdfParams::validate()` 限定 `m ∈ [8 KiB, 1 GiB]`、`t ∈ [1, 16]`、`p ∈ [1, 8]`。

### 5.2 信封与场次隔离

容器 v2 起，**每个学生一个信封**：

```text
envelope_j = AEAD( Argon2id(学号_j ‖ session_id ‖ salt),  student_id ‖ S_j ‖ exams ‖ sections )
data_i     = AEAD( HKDF(S_i, "bank"),  { banks, picks, bank_index, ranges } )
```

- 包里**不再有任何学号**（单元测试 `student_ids_never_appear_in_payload` 覆盖十进制 ASCII / LE / BE 三种形式）；
- `S_i` 每场随机生成、只存在于该场学生的信封里 → **场次间密码学隔离**；
- 枚举名单必须对每个候选学号跑一次 Argon2id，成本见 §5.1。

**鸡生蛋问题**：要先知道场次才能匹配学号。解法是「用学号 + 时间先解密 header 再匹配」——
header 由 `K_manifest` 解密（不依赖学号），信封由学号派生密钥解密。所以：
**先解 header 拿到场次表 → 再用学号逐个试信封**。

### 5.3 时间门禁

```text
输入学号
  → 并发请求 3 个 HTTPS 源（超时 3s；单轮最坏 3s，失败源最多重试 2 轮）
  → 各自解析 Date 头 → 计算 now 与分歧
  → 成功源 < 2 或分歧 > 阈值 → 拒绝解锁（fail-closed）
  → 中位数作为 now → 找到 now ∈ [start, end) 且信封能解开的场次
  → 无匹配 → 明确区分「未到时间 / 已结束 / 不在名单 / PIN 错」
  → 命中 → 派生 entry_key → 解信封 → 解题库 → 进入作答
```

阈值（`spread_limit()`）：**≥3 源为 60 秒，2 源为 10 秒**。
2 源时收紧是有意的——中位数在偶数个源上会退化为较大的值，容差必须更小。

**不变量**：时间门禁必须发生在**派生入场密钥之前**（`client/src/workflow.rs::unlock` 的步骤顺序）。
把它挪到后面等于允许「先解密再判断时间」。

**网页服务端（v1.4.3）**：`exam-server` 启动时用同一份三源清单（`timegate::default_sources()`）校时，
把「网络 − 本机」的差值存进 `clock::Clock`，之后所有场次窗口、限速窗口、最后活跃时间都用
`本机时钟 + 偏移`；不改系统时钟，也不在每次请求时取时（开考后断网不影响判定）。
取时失败时按档位处理：`warn`（默认）只告警并按本机时钟继续，`require` 拒绝启动，`off` 完全不发请求。
这样「教师机时钟错误」从「直接改变开考/收卷判断」降级为「启动日志里的一条警告」。

### 5.4 抽题

```rust
// 种子：显式 blake3，不依赖 rand 的内部细节
let seed: [u8; 32] = blake3(学号 ‖ 场次 ‖ salt);
let mut rng = ChaCha8Rng::from_seed(seed);

// 每个题库一份池子，手写 Fisher-Yates（只依赖 next_u32）
fisher_yates_shuffle(&mut pool, &mut rng);
let picked = pool[..pick];
```

**不变量**：同 `(student_id, session_id, salt)` 必得同一份试卷。
`picker.rs` 里有黄金向量 `GOLDEN_FP`；改抽题算法必须同步更新它并说明原因——
改它意味着所有已发出的试卷指纹失效。

**难度区间**（v0.7.0+）：只约束抽出的 N 题的**平均值**，不对单题设上下限。
实现是位集 DP 找 size=N 且 `sum ∈ [N·lo, N·hi]` 的子集；组合规模过大时退化为滑窗 + 贪心修补。
单边区间（只给 min 或只给 max）在构建期直接报错，不静默忽略。

**大题 / 部分**（v0.14 / v0.15）：`Section` 固定题库 + `parts` 各自题数与**精确**难度；
同一场次同一题库多个大题自动去重；抽题顺序 = UI 里 ↑/↓ 的顺序。
学生端**不显示**「第 x 部分」，只按大题分块。

### 5.5 容器格式与版本

```text
文件 = [ stub（学生端 exe 本体） ][ payload ][ payload_len（u64 LE） ][ "EXAMTAIL" ]
                                                             ↑ 从这里倒着定位 payload

payload = MAGIC "EXAMPKG3"(8) | version(u32 LE) | header_len(u32) | header_ct
        | key_len(u32) | key_area | blob_area
                          │            └ 各场次题库密文（按 data_off/data_len 索引）
                          └ "EXAMKEY1"(8) + 32 字节掩码后的 K_manifest；key_len = 0 表示未内嵌
```

- `header_ct` 用 `K_manifest` 加密（AAD `header-v3`）；
- `EXAMTAIL` 尾部既用于倒着定位 payload，也用于**拒绝把已打包的 exe 当 stub 再用一次**
  （否则上一场的信封与题库会完整留在新文件里，而界面看不出异常）；
- 长度字段一律 `u32::try_from`，不 `as` 静默截断。

| 版本 | 引入 | 内容 |
|---|---|---|
| v3 | 早期 | 旧信封布局（仍可读） |
| **v4** | v0.11.1 | PIN 表进 header；普通包的当前版本 |
| **v5** | v0.13.1 | 签名时间令牌（`mode != off`） |
| **v6** | v0.14.0 | 按大题（`sections`） |
| **v7** | v0.15.0 | 大题下的部分（`parts`） |
| **v8** | v1.1.1 | 含代码简答题（`qtype = code`） |
| v9 | — | **P0 per-student / Header 签名，未实现** |

规则：解析侧接受 `3..=8`（`MIN_SUPPORTED_VERSION = 3`）；无代码题时沿用最高旧版本
（`LEGACY_HIGH_VERSION = 7`），避免把普通包全部挡在门外；旧学生端遇到更高版本**明确拒绝**。

**为什么用版本而不是能力位**：能力位需要客户端理解每一位的含义，旧客户端遇到未知位只能猜；
版本号让「不认识的包」变成确定性的拒绝，而不是静默显示空白题（v1.1.1 的真实教训）。

### 5.6 答题卡

```text
文件：MAGIC(8) "EESANS02" | version(u32) | student_id(u64) | session_id(u32)
      | paper_fingerprint(64 字节 hex) | AES-256-GCM 密文
密钥：HKDF(K_manifest, salt = hex 解码后的试卷指纹, info = "ees-answer-sheet-v1")
AAD ：student_id ‖ session_id ‖ paper_fingerprint（换人 / 换场 / 换卷都会解不开）
内容：{ version, student_id, session_id, paper_fingerprint, qids[], answers[], updated_unix,
        submitted, submitted_unix?, chosen_code_languages{qid→lang}? }
```

- `qids` 与 `answers` **等长同序**；`None` = 未作答；
- 指纹只哈希**题目 ID**（题干订正不应改变试卷指纹）；
- 长度上限：单题 1 MiB、整卡 16 MiB（`MAX_TOTAL_ANSWER_BYTES`）；
- `EESANS01` / v1 仍可读；**v1.2.x 及更早的管理端 / builder 读不了 v2**；
- 损坏恢复：`.recovered` 备份名唯一递增，保存失败时不覆盖原卡。

### 5.7 工程文件、审计、收据

| 机制 | 格式 | 要点 |
|---|---|---|
| 主密钥备份 | `EESKEY02`（兼容 `EESKEY01`） | Argon2id(口令) + AES-256-GCM；8 位指纹核对 |
| 工程文件 | `EESPROJ3`（兼容 `EESPROJ2`） | 默认开启；头部带 KDF 参数并在调用前限幅；`.bak` + 原子替换 |
| 审计日志 | `audit-YYYYMM.jsonl` | 每行 `prev` + `hash`（blake2s-128）哈希链，改一行即断链 |
| 答题卡收据 | JSON | Ed25519 对文件哈希签名；内嵌公钥 + `package_sha256`；验签需核对签发人指纹 |

**收据的边界**：只证明「收卷之后没被改」，**不证明**「这份卡是本人填的」。

## 6. 数据结构

### 6.1 题库（原生格式）

```json
{
  "exam_id": "math-2026-final",
  "title": "高等数学 期末考试",
  "pick": 20,
  "questions": [
    { "id": "q001", "type": "single", "stem": "……",
      "options": ["A……", "B……"], "answer": {"kind": "single", "answer": "B"}, "score": 2, "difficulty": 2 }
  ]
}
```

字段与校验见 [题库JSON规范](题库JSON规范.md)。

### 6.2 manifest（打包输入，管理端生成）

```json
{
  "version": 2,
  "salt": "00112233445566778899aabbccddeeff",
  "kdf": { "m_cost": 65536, "t_cost": 3, "p_cost": 1 },
  "sessions": [
    {
      "session_id": 1,
      "start": "2026-12-20T09:00:00+08:00",
      "end": "2026-12-20T11:00:00+08:00",
      "students": [2021001, 2021002],
      "exams": [{ "file": "demo/math.json", "pick": 3 }],
      "sections": []
    }
  ],
  "time": { "mode": "off", "url": "", "pubkey": "", "max_skew": 300 },
  "student_review": "none"
}
```

- `students` 用 `u64`（真实学号常超 `i32::MAX`）；
- 时间**必须带显式时区**（`+08:00`）；两端都拒绝无偏移时间（会被当成 UTC，静默偏移 8 小时）；
- `sections` 非空则走「按大题」模式，`count` / `difficulty` 可由 `parts` 汇总。

### 6.3 Header 与 Payload（包内明文结构）

```rust
struct Header {           // 由 K_manifest 加密
    version: u32, salt: String, kdf: KdfParams,
    sessions: Vec<SessionHeader>,     // start/end/data_off/data_len/envelopes
    student_review: StudentReviewPolicy,
    pins_ct: Option<String>,          // 用 master 派生密钥加密的 PIN 表
    time: TimeConfig,                 // off / prefer / require
}
struct PayloadData {      // 由 session_secret 派生密钥加密，答案已剥离
    banks: Vec<ExamBank>, picks: BTreeMap<String,u32>,
    bank_index: Vec<BankIndex>, ranges: BTreeMap<String,(u8,u8)>,
}
```

## 9. 工程踩坑清单（都会再犯，写下来）

| 坑 | 现象 | 现在的做法 |
|---|---|---|
| Python 调子进程不指定编码 | 中文 Windows 按 GBK 解 UTF-8，异常在读取线程被吞，界面只显示「无输出」 | 所有跨语言调用显式 `encoding="utf-8"`，兜底文案带退出码 |
| 用截图判断 GUI 布局 | DPI 缩放 / 多显示器导致结论完全错误（本项目误判 3 次） | 管理端 `--dump-ui` 自绘 PNG + `info.json`；学生端 debug 构建 + `EES_DEBUG_LAYOUT` |
| `grep -q` 在 `pipefail` 下误报 | `grep -q` 提前退出 → 上游写管道被杀 → 管道非 0 | 改成 `grep -c … >/dev/null`，构建输出先落文件 |
| 测试用 `std::env::temp_dir()` | 本机 MSYS 下指向 `/tmp`，原生进程写不进去 | 统一用 `target/` 下的目录 |
| 时区字符串比较 | `+0800` 被按 `HHMM` 拆错，`+14:59` 可 panic | 两端都做 ASCII 检查 + 范围校验 + `checked` 运算 |
| `exam_id` 直接拼路径 | 可写到临时目录外 | 按危险特征拒绝，写入端再复核 |
| 无上限 `request_repaint()` | 题号跳转找不到 rect 时 CPU 100% | 最多重试 3 帧 |
| release 里保留 `EES_*` | 把测试钩子发给学生 | 全部收进 `diag_env` / `diag_path`（`#[cfg(debug_assertions)]`） |
| 表格解析返回「消耗行数」被当成新索引 | 解析器死循环，内存涨到十几 GB | 索引前进用 `i += take_table(...)`，并有回归用例 |
| 中位数在偶数源上退化 | 2 源时取到较大值 | `spread_limit()`：2 源 10 秒、≥3 源 60 秒 |
| Markdown 围栏未闭合 | 整段被当代码块 | 未闭合按普通文本处理 |
| `image/jpg` 漏检 | 正则只认 `jpeg` | 正则与规范都兼容 `jpg` |

## 11. 明确不做的事（以及原因）

| 不做 | 原因 |
|---|---|
| 机器指纹绑定 + 在线心跳 | 误伤高（换机房 / 换网卡即锁死）、隐私敏感、要求全程联网 |
| nibble XOR 当安全卖点 | 会反汇编的人半天可破；降级为「防 `strings` 随手搜」，真正防线是每场一密 |
| DOCX / PDF 导出 | Rust 无成熟 DOCX 库、排版成本高；考试以屏幕作答为主，需要纸质版时由教师自行处理 |
| 自建 axum 时间服务器 | 要租 VPS / 配证书 / 维护进程；改用「协议 + 自建服务」由学校自行部署 |
| 代码题自动判分 | 编译运行学生代码有安全与公平风险 |
| 逐题难度上下限 | 抹掉老师「难易搭配」的空间，只保留平均值约束 |
| P0 per-student / Header 签名（v9） | 已作为风险接受（R-01~R-04）；需要时按复审条件重启 |
| 包内可配置时间源 | 等于给时间门禁留后门（`time_sources` 曾因此被删除） |
