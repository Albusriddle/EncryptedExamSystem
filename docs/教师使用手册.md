## 2. 第 1 步：导入题库

1. 双击 `ExamAdmin.exe` → 切到 **[题库]** 标签；
2. 点 **[导入题库]**，选中题库 JSON（可一次多选）；
3. 若弹出「确认导入」，在那里把题库 ID（用作文件名）和显示名称改成看得懂的名字；
4. 在列表里**双击某行**可以预览题干与选项。

| 按钮 | 作用 |
|---|---|
| **[导入题库]** | 导入原生 JSON，或成对的 `X.questions.json` + `X.answers.json` |
| **[移除选中]** | 从当前工程移除该题库（不删磁盘文件） |
| **[插入图片]** | 选图片 → 自动转成可粘进 `stem` 的 `![…](data:image/…)` 片段 |

### 2.1 题库长什么样

一份文件就是一门科目：

```json
{
  "exam_id": "math",
  "title": "高等数学",
  "pick": 20,
  "questions": [
    { "id": "m001", "type": "single", "stem": "1+1=?",
      "body": {"kind": "options", "options": [
        {"key": "A", "text": "1"}, {"key": "B", "text": "2"},
        {"key": "C", "text": "3"}, {"key": "D", "text": "4"}]},
      "answer": {"kind": "single", "answer": "B"},
      "score": 2, "difficulty": 1, "kp": "1.1" }
  ]
}
```

| 字段 | 含义 | 注意 |
|---|---|---|
| `exam_id` | 内部标识，会用作文件名 | 不能含 `\ / : * ? " < > \|`、空白或控制字符；不能以 `.` 开头/结尾；不能用 Windows 保留名；最长 64 字符；中文可以 |
| `title` | 学生看到的科目名 | 任意中文 |
| `pick` | 默认抽几题 | 不超过题量；`0` 表示空卷 |
| `questions[].id` | 题目编号 | 同库内唯一。**试卷指纹只哈希 id**，改 id 等于换了一份卷子 |
| `type` | 题型 | `single` / `multiple` / `judge` / `fill` / `fix` / `essay` / `code` |
| `stem` / `body` | 题干 / 正文形态 | `body` 四种形态：`options` / `template` / `code` / `text` |
| `answer` | 标准答案 | 打包时剥离，学生看不到；`essay` 可留空 |
| `judge` | fill/fix 的判题材料 | 打包时剥离；**系统不执行**，只用于出题方回放 |
| `kp` | 知识点编号 | 形如 `1.1`–`12.9` |
| `difficulty` | 难度 | 见 [2.5](#25-难度数字怎么读)，**这是唯一生效的难度字段** |
| `score` | 分值 | 默认 `2` |
| `meta` | 出题 / 质检标注（K/A/C） | **教师端导入时会被忽略**，见 [2.5](#25-难度数字怎么读) |

> 完整字段、`body` 的四种形态、外部格式（`format_version: 2`）与全部校验规则见
> [题库JSON规范](题库JSON规范.md)。

**编码必须是 UTF-8**。记事本：另存为 → 编码选 `UTF-8`；VS Code：右下角编码 →
`Save with Encoding` → `UTF-8`。存成 GBK / ANSI 会提示「不是合法的 UTF-8 JSON」。

### 2.2 代码简答题（`type: "code"`）

```json
{ "id": "q16", "type": "code", "code_languages": ["c"],
  "stem": "输入 n 与 n 个整数，输出最大值及其出现次数。",
  "body": { "kind": "text" }, "difficulty": 3, "score": 15,
  "answer": { "kind": "rubric", "total": 15,
              "points": [{"text": "读入", "score": 5}, {"text": "求最大值", "score": 5}, {"text": "统计并输出", "score": 5}],
              "reference": "int main(void)\n{\n    …\n}\n",
              "samples": [{"input": "6\n3 8 8 1 8 4\n", "output": "8 3"}] } }
```

| 写法 | 学生端表现 |
|---|---|
| `"code_language": "python"`（只 1 种） | 语言框灰色只读，显示 Python |
| `"code_languages": ["c","cpp"]`（≥2 种，最多 8 个） | 下拉框只能从这些里选 |
| 两个都不写 | 下拉框列出全部 11 种，并提示「以考场老师通知为准」 |
| 两个都写 | **导入 / 打包直接报错**，必须先删一个 |

- 支持 11 种：`python` / `c` / `cpp` / `java` / `rust` / `javascript` / `typescript` / `go` / `sql` / `bash` / `text`；
- **大题题库统一写 `code_languages: ["c"]`**（本项目口径）。写 `code_language` 或别的语言，
  自检工具会报错；
- 「自动识别语言」按钮**只有学生点了才运行**，不会自动改掉学生已选的语言；
- 学生选的语言写进答题卡，导出 CSV 多一列「学生自报语言」，**只是阅卷参考，不参与判分**
  （超出允许集合会标注「超出允许」）；
- 语言下拉框与识别按钮需 **v1.3.0+ 学生端**；
- 代码题**由老师人工评分**：系统不执行学生代码、也不执行 `judge`，
  `answer.reference` / `answer.samples` 只是给老师看的参考答案与样例；
- 含代码题的包是容器 **v8**，需要 **v1.1.1+** 学生端。

### 2.3 三种上限（容易踩）

| 项 | 上限 | 超了会怎样 |
|---|---|---|
| 单题代码答案 | 1 MiB | 输入框拒绝继续输入，计数变红 |
| 整张答题卡答案 | 16 MiB | 保存被拒，整卡计数变红 |
| 代码高亮 | 256 KiB | 自动降级纯等宽，**答案不受影响** |

### 2.4 导入前自检（可选，但推荐）

题库是"批量生产"的东西，一道题写错，最坏情况是整场考试的标准答案全空。正式导入前建议
先跑一次自检（需要 Python 3.10+；不装任何第三方库）：

```bat
:: 只看结构（几秒，不编译）：题数 / 答案形状 / 难度与 K/A/C 是否对得上 / 重复 / 排版
python tools\bank_qc\verify_bank.py <题库目录> --expect choice=500,fill=60,fix=61,rutuan=30,zhaosheng=30 --no-compile

:: 全量门禁（多花约半分钟）：再把填空/改错的判题材料编译回放一遍
python tools\bank_qc\verify_bank.py <题库目录> --expect choice=500,fill=60,fix=61,rutuan=30,zhaosheng=30
```

```bash
# Linux / macOS 同理
python3 tools/bank_qc/verify_bank.py <题库目录> --expect choice=500,fill=60,fix=61,rutuan=30,zhaosheng=30
```

把 `<题库目录>` 换成题库所在目录即可（**自己的题库不必套 500/60/61 这几个数**，
`--expect` 里写自己的题数，或整段去掉就不校验题数）。

> 工具随发布包一起提供（`tools/bank_qc/`），需要本机有 **Python 3.10+**；没有 Python 可以跳过这一步，
> 管理端导入时的格式校验仍然会执行。
>
> ⚠ **示例题库是演示用的，不满足出题口径**：对发布包里的 `示例题库/` 跑 `verify_bank.py`
> 会得到 `FAIL`，这是预期结果，不代表工具坏了。

输出末尾是 `errors=N warnings=M` 与一行 `PASS` / `FAIL`。`errors=0` 才建议导入；
warning 要逐条看（例如"选项不是 4 个""某档占比过高"），能解释再放行。

**判题回放需要一台装有 C 编译器的机器**（clang 或 gcc 都行）：
- 编译器在 `PATH` 里就什么都不用加；不在就加 `--clang <clang 或 gcc 的路径>`；
- 机器上根本没有编译器、或装了但跑不起来（回放前会用一段最小程序冒烟）时，
  工具会打印一条 WARN 并**跳过**回放（其余检查照常），不会因为环境问题把一份好题库
  判成 FAIL——但要清楚：那次**没有**验过判题材料；
- CI 里想"没有编译器就不许过"，加 `--require-compile`。

**自己出的库（题量不是 500/60/61）**：项目口径里的"每题 3 空""每档 ≥15 题"
会把小库判成 ERROR。只想查格式时加 `--min-per-level 0` 关掉配额检查；想连骨架种类
下限一起关，再加 `--max-skeleton-family 0`。

它能查什么、查不了什么（例如**查不出"这道题的答案内容对不对"**）写在
[bank_qc 说明](../tools/bank_qc/README.md) 里，请先看那张"不能查"的表，别把
`PASS` 当成"题目一定正确"。

> 自检**不能替代**管理端导入：最终仍要在 **[题库]** 里真导入一次，那是唯一的权威校验。

### 2.5 难度数字怎么读

题库里的 `difficulty` 是本项目约定的一套小整数，不是"1–255 随便填"：

| 题型 | 取值 | 含义 |
|---|---|---|
| 单选 / 判断 / 填空 / 改错 / 问答 | `1` / `2` / `3` | 基础 / 应用 / 综合，由 K/A/C 加权算出（见[口径文档](出题质检与难度口径.md)） |
| **多选** | **`9`** | 哨兵值。多选不参与 1–3 统计，**不是"第 9 档"** |
| **大题（代码题）** | **`3`** | 本项目大题统一难度 3、统一 15 分 |
| `0` 或没写 | —— | **未标注**。设了"平均难度区间"的题库不允许有未标注的题 |

两点务必知道：

1. **`meta` 里的 K/A/C 不算数。** 教师端导入时会直接把 `meta` 丢掉（模型里没有这个字段），
   所以"我把难度写在 meta 里"等于没写——真正生效的只有 `difficulty`；
2. **`9` 会被当成普通数字参与"平均难度"。** 抽题的难度区间只看**平均值**，
   所以含多选题的库（例如 50 道 `9` + 450 道 `1–3`，全库均值 2.61）不建议设平均难度区间：
   区间设得低时可行组合会变少，极端情况下直接报「区间不可行」。
   见 [4.2](#42-平均难度区间可选)。

## 3. 第 2 步：维护学生名单与班级

**全部学生**：左侧选「全部学生」→ 把学号粘进右侧大框（**每行一个**，也支持逗号 / 空格分隔）→
点 **[应用到名单]**。可直接从 Excel 复制一列粘进来，也可点 **[从 CSV 导入]**。

学号必须是**正整数**；重复的、非数字的会在下方提示，点应用时会被拦住。

**班级**（多班老师推荐）：

1. 点 **[新建班级]**，填班级名（可选填编号，如 `CS2101`）；
2. 选中该班，把学号粘进右侧框，点 **[应用到名单]**——**新学号会自动加入全局名单**；
3. 左侧三个视图：**全部学生**（整个学号池）、**未分班**（**只读**，只能核对谁还没分班，不能改名单、不能导 CSV）、各班级；
4. **[删除班级]** 只删分组，不删全局名单里的学号。

> 班级成员永远是全局名单的子集。从全局名单删掉一个学号，所有班级里的他也会一并消失。

## 4. 第 3 步：编排场次

### 4.1 基本操作

1. 切到 **[场次]** → 点 **[新建]**；
2. 填 **场次编号**（自动给）、**开始时间**、**结束时间**；
3. 选 **学号名单**：
   - **使用全部学生**：每次填入最新全局名单；
   - **按班级选择…**：勾选一个或多个班，成员自动并入本场，选完切回「自定义名单」并显示「本场 N 人，来自 M 个班」；
   - **自定义名单**：自己贴学号；
4. 勾选本场要考的科目，填每题抽几道；
5. 点 **[保存此场次]**。

> ⚠ **名单是保存时的快照**。之后在学生页加人，已保存的场次**不会自动更新**，
> 要重新点一次 **[保存此场次]**。

**时间必须带时区**：界面选择的时间会自动带本地偏移（如 `+08:00`）；手写 manifest 时必须写
`2026-12-20T09:00:00+08:00` 这种显式偏移。不带偏移的写法会被两端**拒绝**——旧版本会静默当成 UTC，整体偏移 8 小时。

### 4.2 平均难度区间（可选）

勾选 **「限制平均难度」** 并填 `1–255` 的区间：

- 只约束抽出的这 N 题的**平均难度**，**不**对单题设上下限（允许个别极难 / 极易题，只要均值在区间内）；
- 设置区间前，该题库**所有题**都必须标好 `difficulty`（`1`/`2`/`3`，多选 `9`，大题 `3`），
  有未标注（`0` 或缺失）的会被拦下；
- 界面每行实时显示「可达 X–Y / N 题未标难度」；区间不可行时保存会报错；
- ⚠ **含多选题的库不建议设区间**：多选的 `9` 会像普通难度一样参与平均（本库 500 题均值 2.61），
  区间设得低时可行组合会变少，极端情况下直接报「区间不可行」。
  确需设区间时，把多选拆到单独的库，或把上限放宽到能容纳 `9` 的范围。

> **设计边界（刻意如此，请勿要求改成逐题过滤）**：给老师留出「难易搭配」的空间。

### 4.3 按大题模式（可选，功能更强）

勾选 **「按大题模式（每行固定题库、题数、精确难度；可上下调整顺序）」**：

1. **[+ 新建大题]**：填标题、选题库、填题数、填精确难度；
2. 大题下可 **[+ 新建部分]**：每个部分独立设部分标题、题数、精确难度；
3. **[↑] [↓]** 分别调整「大题」与「部分」两层顺序，**顺序即抽题顺序**；
4. **[删除大题] / [删除部分]** 只删配置，不动题库。

| 项 | 说明 |
|---|---|
| 学生端会看到「第 x 部分」吗 | **不会**。部分只作抽题依据；右侧题号也只按大题分块 |
| 同一题库能拆成多个大题吗 | 能，系统保证同场次内不重复抽同一题 |
| **精确难度填几** | 大题库里的题**全部是难度 3**，所以必须填 **3**；填 1 / 2 / 4 会报「只有 0 题」 |
| 某难度题不够 | 保存 / 打包会明确报「只有 N 题」 |
| 容器版本 | 有大题 → v6；大题下再有部分 → v7 |
| 旧工程 | 打开旧 v6 单层工程后，不改部分则保存仍是 v6；只有新建 / 修改部分才升 v7 并提示旧学生端不可用 |
| 手写 manifest | 用 `parts` 时 `count` / `difficulty` 可省略，程序自动填汇总值 |

### 4.4 时间轴与重叠

底部时间轴把所有场次画出来：**蓝色 = 正常，红色 = 时间重叠**。

- 同一名学生同时出现在两个重叠场次 → **打包直接报错**。错开时间，或把这些学生从其中一场移除；
- 只是时间重叠、学生不重叠（例如同一天上午两个班同时考不同科目）→ 允许。

## 5. 第 4 步：打包

1. 切到 **[打包]**；
2. **主密钥**：点 **[生成]**（有进度条，约 1–2 秒）；
3. **学生端 stub**：保持默认（指向 `stub-template.exe`）；
4. **输出包**：选保存位置，例如 `<你的考试目录>\12月20日高数.exe`；
5. 按需勾选 **[每生 PIN 登录]**、时间令牌、**[仅教师可查看原卷]**、**[加密保存工程]**；
6. 点 **[开始打包]**。

出现这一行就是成功：

```text
✔ 已内嵌密钥：学生双击 exe 输入学号即可，无需任何参数或密钥文件。
```

耗时（每个学生都要单独做一次内存硬加密，慢是正常的，**不要为提速把 KDF 参数调低**）：

| 信封数（= 各场人数之和） | 约耗时 |
|---|---|
| 1,500 | 约 7 秒（单次派生 92 ms，20 线程并发实测） |
| 3,000 | 15 秒 |

### 5.1 主密钥：全系统最重要的东西

- **唯一**能生成新考试包 / 解密校验答题卡的东西；**不在**任何生成的包里，也**不在** `*.eesproj` 里；
- 丢了不影响已发出去的包（密钥已写进包内），但**无法再打新包**、**无法再校验答题卡**；
- 打包前后都可点 **[复制主密钥]** 粘进密码管理器（成功后 5 分钟自动清空输入框；若剪贴板仍持有该密钥则不清空并提示）；
- 日志里**永远不会**出现主密钥明文。

### 5.2 主密钥备份与恢复

| 操作 | 在哪 | 说明 |
|---|---|---|
| 备份 | 主密钥旁 **[备份]** | 生成 `.eekey` 加密备份，需设一个备份口令 |
| 恢复 | 主密钥旁 **[恢复]** | 选 `.eekey` + 输入备份口令 |
| 核对 | 主密钥下方「主密钥指纹」 | 8 位指纹，恢复后必须对得上 |

> 备份口令丢了同样打不开备份。请把 `.eekey` 与口令**分开**保存。

### 5.3 每生 PIN 登录（可选，高风险考试建议开）

勾选 **[每生 PIN 登录（生成 6 位 PIN，导出 CSV 发给学生）]**：

- 打包成功后**弹窗让你选 PIN CSV 的保存位置**（默认工程保存位置）；文件名 `登录PIN-<包名>-<时间>.csv`，表头 `场次,学号,PIN`，**只给老师**；
- 选到考试包目录 / 其子目录 / 不可写目录会报错并让你重选；取消则暂存 `%TEMP%\ees-pin-<时间>.csv` 并显示完整路径；
- 新 PIN 固定在 `100000–999999`（**无前导 0**，避免 Excel 把 `028879` 显示成 `28879`）；学生端 PIN 输入框会自动去空格并左补 `0`（兼容被 Excel 吃掉的旧表）；
- PIN 表**不以明文存在包里**，用 master 派生的密钥加密进 header；教师校验答题卡时用 master 解开；
- 学生丢了 PIN：重新打包会生成新 PIN。旧包丢了 PIN 表：`exam-builder export-pins` 可重新导出（需 master）。

### 5.4 学生回看（标题为「仅教师可查看原卷」）

| 勾选状态 | 学生端行为 |
|---|---|
| **勾选（默认）** | 学生端**没有**回看入口；考后由老师用 master 查看原卷 |
| 取消勾选 | 学生**已交卷且未到结束时间**可免授权只读回看；到点后仍直接进结束页 |

回看页顶部固定「← 返回已交卷页」，可反复「回看 → 返回 → 再回看」。

### 5.5 签名时间令牌（高级，需自建服务）

| 模式 | 行为 |
|---|---|
| 关闭（默认） | 只用 3 个公共 HTTPS `Date` 取中位数 |
| 优先 | 先试令牌，失败回退 HTTPS Date 并在日志警告 |
| 必须 | 没有有效令牌就**不开考**（断网 / 服务挂会无法开考，慎重） |

- 填 `https://` 令牌地址 + 服务端 Ed25519 公钥（base64，32 字节）；
- 「时钟偏差警告阈值」**只写日志**，不参与放行 / 拒绝（本机时钟可被学生修改）；
- 协议与最小服务端示例见 [时间令牌协议](时间令牌协议.md)；启用令牌的包是容器 **v5**。

### 5.6 工程加密

默认**开启**（`EESPROJ3`，Argon2id + AES-256-GCM）。新口令**至少 8 位**；打开加密工程最多重试 3 次；
加密工程强制扩展名 `.eesproj`；旧明文工程可正常打开，再另存为加密工程。
加密依赖缺失时会**降级明文保存并明确警告**——看到警告请先修环境再继续。

## 6. 第 4 步（续）：工程文件与保存位置

**每次启动是空白工程**（不会自动打开上次）。要接着做，点工具栏 **[打开上次工程]**（悬停显示路径；
文件已不存在时显示「文件已不存在：<path>」）；也可 **[打开工程…]** 选任意 `.eesproj`（对话框同时认 `.eesproj` 与旧 `.json`）。

**打包后自动保存**：

- 位置 = **[打包]** 页的「工程保存位置」，它**始终显示当前工程所在目录**，可直接编辑或点 **[浏览…]**；
- 默认是**程序目录**下的 `projects\<包名>-<内容哈希6位>.eesproj`；
- 程序目录不可写（Program Files / 只读 U 盘）→ 回退 `%LOCALAPPDATA%\ExamSystem\projects\`；
- **不会**存进考试包输出目录（输出目录及其**子目录**都算），会改存到默认目录；
- 已打开工程在同一目录 → 覆盖原文件；改了目录 → 另存一份（旧文件保留）；
- 每次打包日志会写「✔ 已保存到工程：<路径>」并弹窗显示路径；工具栏 **[打开工程目录]** 可直接打开。

> ⚠ 工程文件里有**标准答案与判分材料**，而且**不在考试包目录里**。不要拷到考试包旁边，更不要发给学生。

## 7. 第 5 步：考试当天

### 7.1 老师要做的

1. 把打好的 `.exe` 通过班级群 / U 盘 / 内网共享发给学生；
2. 告诉学生：「双击打开，输入学号（有 PIN 再输 PIN），点开始考试」；
3. 到时间窗口自动放行，不到时间提示「考试尚未开始」；
4. 建议**提前用测试学号打个测试包**试跑一次（不要用真名单）。

### 7.2 学生会看到什么

双击 exe → 欢迎弹窗（可选「不再提示」，记在 `%LOCALAPPDATA%\ExamSystem\skip_welcome`）→
输入学号（启用 PIN 时再输 6 位）→ 点 **[开始考试]** → 看到试卷。
顶部显示网络时间与「距离结束还有 …」。

### 7.3 时间门禁怎么判

- 并发向 `www.baidu.com` / `www.aliyun.com` / `www.tencent.com` 取 HTTPS `Date` 头，**取中位数**；
- **至少 2 个源成功**且源间分歧不超阈值（≥3 源 60 秒、2 源 10 秒），否则拒绝解锁（fail-closed）；
- 本机时钟被改？没用——判定完全基于网络时间；学生断网 → **拒绝解锁**（宁可考不了，也不能让时钟作弊）；
- 失败时会自动重试一轮（只重查失败源，约多 3 秒）。

### 7.4 答题卡保存在哪

| 位置 | 说明 |
|---|---|
| exe 同目录 `answers-<学号>-<场次>-<试卷指纹8位>.eea` | 首选；监考可直接拷走。**文件名带指纹**，同机开多份包不会互相覆盖 |
| `%LOCALAPPDATA%\ExamSystem\answers\` | 同目录不可写（Program Files / 只读 U 盘）时的回退位置 |

- 作答过程中**自动加密保存**；交卷 / 到点会写入「已交卷」；文件是密文，**不能用记事本打开**；
- 右侧题号卡：**已答 = 蓝色**、**未答 = 灰色**、**当前题 = 绿色描边**；
- 提前交卷需连点两次确认，交卷后直接进「已交卷」页，不再停留在试卷上。

> **误交卷怎么办**：重新生成同 salt 的 exe **不会**重置该机已交卷的答题卡。
> 补考请新建场次 / 更换 salt，或由监考老师移走该机 `answers-*.eea`。

## 7.5 网页考试（可选，v1.4.2 起）

适用于学生用 Mac / Linux / 平板等**没有 Windows 客户端**的场景。**只用于隔离局域网 + 现场监考**。

1. 先按第 4 步正常打包，并在「导出 K_manifest」里选一个保存位置（网页服务需要它）；
2. 打包完成后点「网页考试…」，确认考试包、K_manifest、端口（默认 8443，HTTPS）、答题卡目录
   （留空 = `<考试包目录>/web-answers`）；
   - **时间校验**默认 `warn`（机房没有外网也能开考，只在日志里提示）；
     确认教师机有外网、又要求时间强一致时选 `require`；选 `off` 会弹二次确认（不推荐）；
   - **同 IP 登录上限**默认 60 次/分钟；整班在同一个 NAT 后面、或做并发演练时，调大或设成 0；
   - **监听地址**默认「全部网卡」；教师机同时连着校园网/外网时，选「仅 <本机局域网地址>」，
     学生就只能从机房侧访问（比只依赖防火墙更直接）；选「仅本机」只给自己调试用。
3. 点「启动服务」，**等日志出现「考试服务已启动」**（无外网时开头要等一次取时，最坏约 6 秒），
   再把界面显示的 `https://<教师机 IP>:8443/` 告诉学生；
   - **首次访问会有「您的连接不是私密连接」**：让学生点「高级 → 继续前往 <IP>（不安全）」；
     这是考场内网自签证书，页面顶部也有同样的提示；
   - **指纹核对（建议，可选）**：启动日志里有「证书指纹（SHA-256）：…」。注意**拦截页本身看不到证书详情**：
     要先按上一条点「继续前往」进入页面，再点地址栏左侧的「不安全」→「证书无效」→「查看证书」→「详细信息」，
     找到 SHA-256 指纹与日志比对（冒号与大小写可忽略）。对得上说明没有被中间人替换；
   - **iPad / iPhone 请用 Safari**：iOS 上的 Chrome（WKWebView）无法绕过证书警告；
   若第 2 步的「监听地址」选了「仅本机」，界面显示的是 `https://127.0.0.1:<端口>/`——
   **这个地址只有教师机自己打得开，不要发给学生**；
4. 学生在浏览器输入学号（启用 PIN 时再输 PIN）作答：**单选/判断点选项、多选点多个方框**，
   填空与改错按「每行一个空 / 每行一条」填写；答案每 600 ms 自动保存一次并即时落盘
   （教师机崩溃 / 断电后重登可恢复，刷新页面也会自动恢复，不用重新输学号）；
5. 考后点「停止」，答题卡在 `web-answers/answers-*.eea`，与离线包一样用「收卷判分」处理。

注意事项：

- 教师机要关闭休眠、放行防火墙端口；Wi-Fi 需关闭「客户端隔离」，否则学生访问不到；
- **默认 HTTPS（自签证书）**：挡同网段的被动嗅探，但**不挡主动中间人**（除非让学生核对指纹）；
  `--tls off` 才是明文 HTTP（同网段可嗅探）。两种情况都只用于隔离局域网、不要接入互联网；
- **旧书签会自动跳**：`http://<教师机 IP>:8080/` 会 301 跳到 `https://<教师机 IP>:8443/`
  （明文端口只做跳转，不承载页面与数据）；
- **`--tls off` 什么时候用**：只在排障、或学生设备确实无法绕过证书警告（如受管 Chromebook）时临时用；
  它会让同网段重新可嗅探，用完请立刻改回默认；
- **证书放在哪、什么时候会重签**：`<答题卡目录>/tls/server.crt` 与 `server.key`（私钥仅当前系统账户可读），
  旁边还有 `server.json` 记录覆盖的地址与到期时间。有效期 365 天，**到期前 30 天会自动重签**；
  **换机器或换网段/IP 后**（证书里的地址不再匹配）也会自动重签。重签时启动日志会打印
  「证书已重签：<原因>」，**指纹随之变化**——如果印过旧指纹，请以启动日志里的新指纹为准。
  证书/私钥文件损坏时同样会备份后重签，一般不需要人工干预；
- 浏览器无法阻止 DevTools/切屏/搜索，必须有现场监考；
- 教师机是单点：建议接 UPS；开考前**先做 30–50 人演练**：
  1. 有源码环境时：在仓库里跑 `bash scripts/drill-web.sh --students 40`。它会模拟 40 人并发登录、
     `kill -9` 后重启恢复、并发交卷，并打印每阶段的 p50/p95 耗时与「收卡数量 / 事件条数 / 答题卡校验」结果；
  2. 没有源码环境时手工演练：找 30–50 台设备同时打开 `https://<教师机 IP>:8443/`（首次点「高级 → 继续」），
     各答一题后同时点交卷，
     观察有没有学生报「登录尝试过多」「保存失败」；
  3. 演练重点：Wi-Fi 已关闭「客户端隔离」、防火墙已放行端口、教师机不休眠；
     以及「断电后重启，学生重登还能拿回答案」（每次保存都会加密落盘，v1.4.5 起）。
- **启动时校时（v1.4.3 起）**：服务启动会先做一次三源网络时间校验，并打印「本地时间 / 网络时间 / 偏差 / 结论」。
  - 日志里出现「仅告警（取时失败…）」是正常的——机房/隔离局域网没有外网很常见；此时**请确认教师机系统时钟准确**，
    因为判定会退回本机时钟；
  - 如果有外网、又要求时间强一致，可在命令行加 `--time-check require`（不通过就不启动）；
    加 `--time-check off` 则完全不校验（不建议）；
  - 允许偏差默认 120 秒，可用 `--time-tolerance` 调整（小于 30 秒会按 30 秒算）；
- **回看策略在网页端也生效（v1.4.11 起）**：默认勾选「仅教师可查看原卷」时，学生交卷后网页会切到
  「已交卷」页、不再显示卷面；要允许学生交卷后查看，需在打包时**取消勾选**该项；
- **关浏览器与退出（v1.4.12 起）**：会话 cookie 是 60 分钟滑动续期——
  只关标签页再打开会**自动回到原卷**；关掉整个浏览器则需要重新输学号/PIN（答案不会丢）。
  顶栏右侧有「退出」：共享设备上考完请让学生点一下（会立刻让会话失效）；
  **采用默认「仅教师可查看原卷」时，交卷后会话也会立即失效**，属于预期行为；
- **断线与重启（v1.4.11 起）**：学生网络断开时页面**底部**会出现红色提示（答案留在页面里、自动重试，
  提示消失即恢复保存）；教师机重启后所有学生会看到「登录已失效」，点「重新登录」即可，
  已保存的答案不会丢；
- **状态文件只给当前账户（v1.4.3 起）**：`web-answers/state/` 与 `events.jsonl` 在 Windows 上只授予当前
  Windows 账户（Unix 为 `0600`）。换一个 Windows 账户启动服务，会读不到旧状态、断线恢复失效——这是预期行为，
  需要恢复时请用原来的账户启动；
- **没有在线监控页**：看不到「谁在线 / 谁已交卷」，进度只能数 `web-answers/answers-*.eea`，或看服务端日志；
- **交卷不受时间窗限制**：到点后仍可补交（便于自动收卷失败时补救），但过期后不能再改答案。

## 8. 第 6 步：收卷、校验、判分

### 8.1 校验答题卡

1. 打开 **[收卷判分]** 页；
2. 粘贴**主密钥**（与打包时同一把，64 位十六进制；可点 **[显示]** 回显）；
3. **必须选择学生端包**——用于核对「这份答题卡确实属于这个包的这个学生」。
   输入框标签写着「学生端包（可选）」，但**不选会被拦下**并提示「校验必须指定本次考试的学生端 exe」；
4. **[添加文件]** 选 `.eea`（可多选），或 **[添加文件夹]** 整个目录；也可直接把文件拖进列表；
5. 点 **[开始校验]**：表格显示学号、场次、题数、已答 / 未答、交卷时间、校验结果；
   - **✓ 通过（已绑定）**：文件与包、学号、试卷指纹全部对得上；
   - **✗ 失败**：鼠标悬停状态列看具体原因；
6. **[导出原始作答 CSV]**：一行一题，Excel 直接打开，**不含分数**。

> 校验进行中，列表按钮、主密钥输入、学生端包输入都会被冻结，避免结果与表格错位。

### 8.2 命令行校验（可选）

```bash
exam-builder verify-answer-sheet answers-2021001-1-91d70557.eea \
  --package 学生端.exe --master <64位主密钥>

# 推荐：master 走环境变量（命令行参数会出现在进程列表里）
EXAM_MASTER=<64位主密钥> exam-builder verify-answer-sheet \
  answers-2021001-1-91d70557.eea --package 学生端.exe --json
```

退出码：

| 码 | 含义 |
|---|---|
| `0` | 通过（含绑定校验通过） |
| `2` | 解密失败（密钥不匹配或文件被改） |
| `3` | 结构错误（文件头 / 版本 / 内容损坏） |
| `4` | 绑定不匹配（试卷指纹或题目列表与包内不一致） |
| `5` | 包用不了（不是同一 master 的包、包里没这个场次 / 学号）或参数 / IO 错误 |

### 8.3 缺考名单

校验完成后点 **[缺考名单]**：

| 状态 | 含义 |
|---|---|
| 已交卷 | 有卡且已交卷 |
| 未交卷 | 有卡但没点交卷（自动保存的） |
| **缺考** | 名单里有、但没有卡 |
| 校验失败 | 有卡但解不开 / 与所选包不匹配 |
| 名单外 | 有卡但学号不在该场名单里 |

- 顶部可勾选「包含没有答题卡的场次」（默认不勾，防止只导了一个场的卡就把别的场全标缺考）；
- **[复制本场缺考学号]** 方便发通知；**[导出缺考名单]** 生成 `缺考名单-<时间>.csv`。

### 8.4 自动判分

1. 「自动判分题型」里勾选**要自动判的题型**（默认单选 / 多选 / 判断；**填空与改错也能自动判**，
   按需勾上）；
2. 匹配规则可勾：**忽略大小写**、**忽略空白字符**、**填空/改错按项给分**；
3. 点 **[预检]**：检查题库里找不到的题号、没有标准答案的题、与所选包不匹配的答题卡（`binding=false`）；
4. 点 **[生成成绩]**：表格列出每题的学生作答、标准答案、得分。

判分对题库的要求（与 [题库JSON规范](题库JSON规范.md) §1.4 一致）：

| 题型 | 依赖的字段 | 说明 |
|---|---|---|
| 单选 / 判断 | `answer.answer`（字母） | 字母必须在选项里 |
| 多选 | `answer.answer`（字母数组） | 按**集合**比较，顺序无关 |
| 填空 | `answer.answer[]` 的每个 `answer` | 按空顺序比对；可切「按项给分」 |
| 改错 | `answer.answer[]` 的 `line` + `answer` | 按行比对学生改后的整行；学生答案在答题卡里是 JSON 数组 |

> **`judge` 不参与判分**。判分只看 `answer`；`judge` 是出题方用来回放验证的材料，
> 打包时已剥离，学生端也看不到。

改主密钥或换包后，旧成绩会**自动清空**——不会出现「导出的分数和当前输入对不上」。

### 8.5 人工给分 / 改分

双击「得分」列：

| 情形 | 显示 | 说明 |
|---|---|---|
| 已判题改分 | `原分 → 新分` | 汇总实时重算 |
| 未判题（问答 / 代码题 / 未勾选的题型） | `人工 N` | **打 0 分也有效** |
| 清空得分 | 回到「待人工判分」 | 撤销人工评分 |

代码题由老师**对照 `answer.points` 手工给分**（系统不按评分点自动累加）；
`answer.reference` 与 `answer.samples` 只在题库/工程里可见，可对照阅卷。

### 8.6 导出

点 **[导出判分结果]** 选目录，生成五份 CSV（文件名带 `YYYYMMDD-HHMMSS`，不会覆盖上一场）：

| 文件 | 内容 |
|---|---|
| `已判分-明细-<时间>.csv` | 逐题，含「人工调整」「调整时间」「学生自报语言」 |
| `已判分-汇总-<时间>.csv` | 每生一行 |
| `未判分-<时间>.csv` | 没勾自动判的题，含题干摘要，供人工判 |
| `全量-<时间>.csv` | 两者合并 |
| `考生成绩表-<时间>.csv` | 按学号排序，每种题型两列「得分 / 满分」，含班级、总分、得分率、未判题数与「完整 / 含未判」状态 |

导出目录里另有一份 `说明.txt`（`utf-8-sig`），写明本次判分口径与时间。

> 成绩表的**满分按整卷统计**（含未判题）；未判题不计得分，所以「得分率」是部分成绩。
> 状态列写着「含未判」就说明还没判完。
>
> 大题按每题 15 分进入总分：两个大题库各 30 题、总分 450；库内 `pick=4`，抽满即 60 分（4 × 15）。

## 9. 审计菜单

都在 **[收卷判分]** 页的 **[审计]** 按钮里。

| 菜单项 | 作用 |
|---|---|
| **签发答题卡收据** | 对本批 `.eea` 的**文件哈希**用教师私钥（Ed25519）签名，生成 `答题卡收据-<时间>.json` |
| **验证收据** | 校验签名、文件哈希、多余未签名文件、考试包哈希 |
| **备份收据私钥** | 导出 `.pem`，**建议设备份口令**（至少 8 位；留空则不加密，风险自负） |
| **恢复收据私钥** | 选 `.pem` + 输口令；程序解密后写回本机可用格式（之后签发 / 验证不再需要口令） |
| **考后查看原卷** | 输学号、场次，调 `exam-builder review-paper` 导出 `原卷-学号N-场次M.json` |

要点：

- 首次签发会自动生成 `receipt-key.pem`（`%LOCALAPPDATA%\ExamSystem\` 下，权限 0600）；收据内含**公钥**与 `package_sha256`，另一台电脑**无需私钥**即可验签；
- 验证时要核对**签发人指纹**（16 位）：本机有私钥时自动带出；验证别机的收据要输入对方指纹，**指纹不一致的收据不要接受**；
- 失败原因会结构化给出：`malformed` / `missing_public_key` / `fingerprint_mismatch` / `wrong_key` / `bad_signature`；
- **边界**：收据只能证明「收卷之后没被改」，**不能**证明学生交卷前没改自己的卡；
- `review-paper` 使用教师电脑上的 master，**不经过学生端时间门禁**；若同时给 `--sheet` 会校验答题卡 qids，对不上会报错。

**审计日志**：打开 / 保存 / 打包 / 人工改分 / 签发收据 / 验证收据都会写 `audit-YYYYMM.jsonl`
（工程文件所在目录；没有打开工程时写默认工程目录）。每条记录带 `prev` 与 `hash`
（blake2s-128 哈希链），改一行就会断链。工具栏 **[审计日志…]** 可查看最近一份并校验。

## 10. 命令行方式（可选）

```bash
# 生成 64 位十六进制主密钥
exam-builder.exe keygen

# 打包（默认把 K_manifest 写进包）
exam-builder.exe build --manifest manifest.json --banks ./banks \
  --stub stub-template.exe --out Student.exe

# 校验一个包能否被指定密钥解开
exam-builder.exe verify --package Student.exe

# 校验答题卡（--package 必须给）
exam-builder.exe verify-answer-sheet answers-2021001-1-91d70557.eea --package Student.exe

# 考后查看原卷
exam-builder.exe review-paper --package Student.exe --student 2021001 --session 1

# 从包里重新导出 PIN 表
exam-builder.exe export-pins --package Student.exe --out pins.csv
```

- master 优先用环境变量 `EXAM_MASTER` 或 `--master-file`；`--master` 会进进程列表，**仅供本机调试**；
- `build` 默认**拒绝覆盖**已存在的输出文件，需要时加 `--force`；
- `--allow-weak-kdf` 仅用于演示 / 自动化测试，**真实考试绝不要用**（枚举 10⁵ 个学号只需几秒）；
- `--pin-login` 必须配合 `--emit-pins` 导出 CSV；
- `--no-embed-key` 表示不把 K_manifest 写进包（学生须自行提供 master），仅调试用。

PowerShell 设环境变量：`$env:EXAM_MASTER = "你的64位十六进制密钥"`

## 10.5 界面交互约定（v1.3.2 起）

- **滚轮不会改值**：题库下拉、题数、难度、抽题数、场次编号、开始/结束时间等，滚轮只滚动页面，不会修改。
- **页签不会被滚轮切走**：滚轮停在顶部页签上不会切页。
- **小题之间有分隔线**：每道小题之间有一条细线并留出间距；换【大题】时还会多一条**更粗**的同色分隔线。
- **勾选框只认「方框 + 短标题」**：详细说明在悬停提示里；可点范围已按文字宽度收窄。
- **危险开关会二次确认**（默认按钮为「否」）：关闭「加密保存工程」、放开「仅教师可查看原卷」、启用「每生 PIN 登录」、已配置大题时关闭「按大题模式」。

## 11. 常见错误对照表

### 11.1 题库 / 导入

| 提示 | 原因 | 怎么办 |
|---|---|---|
| `不是合法的 UTF-8 JSON` | 文件存成 GBK / ANSI | 另存为 UTF-8 |
| `exam_id 不能包含路径分隔符或 Windows 禁用字符` / `exam_id 过长（N 字符，最多 64）` | 含 `\ / : * ? " < > \|`，或 id 太长 | 换掉这些字符（中文可用）/ 截短 |
| `题库 X 存在重复题目 ID` / `题目 ID 重复：CH-042` | 同库内 id 撞了 | 改 id（改 id 等于换了一份卷子） |
| `缺少答案：CH-042` / `多出答案：CH-999` | 题目与答案文件 id 对不上 | 补齐 / 删掉多余答案 |
| `缺少对应的答案文件` | 只导了 `.questions.json`，同目录没有 `.answers.json` | 放到同目录，或两个一起选 |
| `题型 choice 的答案 kind 应为 [...]，实际 'blanks'` | `verdict.kind` 与题型不匹配 | 按规范改 `kind` |
| `选项 27 个，超过 26 个（A–Z）` / `选项键应为 ['A','B','C']，实际 ['A','C']` | 选项太多 / 选项键不连续 | 压到 26 个以内、补上缺的键 |
| `答案 ['E'] 不在选项 ['A','B'] 中——学生永远选不到正确项` | 答案字母越界 | 改答案或补选项 |
| `模板里有 2 个 ____①____ 占位符，但 blank_count=3` | 占位符数与 `blank_count` 不一致 | 对齐两者 |
| `第 1 条改正项的 line=99 超出 1..8` / `wrong 与第 3 行原文不一致` | 改错行号越界 / `wrong` 与原文不逐字相同 | 改行号 / 逐字复制原行 |
| `code_language 与 code_languages 不能同时填写` / `code_languages 最多 8 个` | 两种声明都写了 / 超 8 个 | 删掉一个 / 减到 8 个以内 |
| `不支持的代码语言：'xxx'` | 语言名拼错或不在 11 种里 | 用规范里的 11 个之一 |
| `不支持的题型：'xxx'` | `type` 拼错 | 用规定的七个值之一 |
| `题库名相同` | 两个目录下有同名文件 | 改名，或在导入确认框里改题库 ID |
| 选择题**全被判错**、标准答案列是空的 | `answer` 写成了纯字母 `"B"`（不是对象） | 改成 `{"kind":"single","answer":"B"}`，见规范 §1.4 |
| 改了题库 JSON，打包出来还是旧题 | 工程里用的是**导入时**载入内存的题库；打包前只复查答案，不重读磁盘 | 重新导入该题库，或**重开工程**（会按记录的路径重读源文件） |
| 难度"改了没生效" / 均值对不上 | 把难度写进了 `meta`，而 `meta` 导入时被丢弃 | 改 `difficulty`（`meta` 只是质检标注） |
| 自检报 `多选 difficulty 必须固定为 9` | 多选写了 1/2/3 | 改成 `9`（哨兵值，不是第 9 档） |
| 自检报 `大题统一 15 分` / `大题必须写 code_languages: ["c"]` | 大题沿用了别的分值或语言 | 统一 15 分、`["c"]` |
| 自检报 `原始（未改）代码也能通过全部用例` | 改错题的错误不影响输出 | 换一处能改变结果的错误，或补能区分的用例 |
| 自检报 `找不到 C 编译器…（本次按 warning 放行）` | 本机 PATH 里没有 clang / gcc | 加 `--clang <编译器路径>`，或 `--no-compile` 明确只查结构；CI 用 `--require-compile` |
| 自检报 `fill 难度 1 只有 N 题（下限 15）` | 这是**项目交付口径**，不是格式错误 | 自己的小库加 `--min-per-level 0`；交付 2027 题库则补题 |
| 自检报 `title 里写「440 分」，但本题库分值和是 450 分` | 标题里的数字是手写的，系统不读 | 改标题（不影响判分，只影响老师看到的科目名） |
| 自检报 `占位符出现顺序是 ['③','①','②']` | 模板里的编号没有按 ①②③ 出现 | 判分按编号对位、不算错；但学生按位置填会错位，建议改成顺序编号 |
| 自检报 `多选答案等于全部选项（送分题）` | 四个选项全是正确项 | 改成 2–3 个正确项，或改成单选 |
| 自检报 `缺少 kp（形如 1.1–12.9）` | 产品允许不写 `kp`，但项目要求每题都有 | 补知识点编号（见教学大纲） |
| 自检报 `没写 score` | 省略了分值，产品按默认 2 分导入 | 补上分值（本项目每题型统一分值） |

### 11.2 场次 / 打包

| 提示 | 原因 | 怎么办 |
|---|---|---|
| `场次 1 与 2 时间重叠，且学生 … 同时在两场` | 同一学生被排进两个重叠场次 | 错开时间，或从其中一场移除 |
| `场次 1 重复引用题库 math.json` | 同场次勾了两次同一科目 | 去掉一个 |
| `学号必须是正整数` | 名单里有 0、负数、非数字 | 检查文本框 |
| `只有 N 题` / `区间不可行` / `难度区间要求所有题都标 difficulty` | 该难度题不够 / 区间无解 / 有题未标难度 | 降题数、放宽难度、补题；看界面显示的「可达 X–Y」；补 `difficulty` |
| `部分 X/Y 要抽 N 题，但题库 … 难度 1 只有 0 题` | 大题库全部是难度 3，精确难度却填了 1 / 2 / 4 | 把精确难度改成 **3** |
| 含多选的库设了平均难度区间，一直不可行 | 多选的 `9` 拉高了均值 | 取消区间，或把多选拆到单独的库 |
| `输出包被占用（os error 5）` | 学生端正开着，或文件被占用 | 关学生端 / 换文件名 / 换目录 |
| `找不到 stub` | `stub-template.exe` 被删或被单独拷走 | 从发布包恢复整个文件夹 |
| 弹窗「（取消）」 / `No module named argon2` | 老师中途取消 / 打包版缺依赖 | 取消不是失败（`.tmp` 已清理，可重来）；缺依赖请用官方发布包 |

### 11.3 学生端

| 学生看到 | 原因 | 怎么办 |
|---|---|---|
| `学号必须是正整数` / `学号必须是纯数字` | 输入了非数字 | 重新输入 |
| `考试尚未开始` / `本场考试已结束` | 未到开始时间 / 已过结束时间 | 显示的是网络时间；到点自动冻结属正常 |
| `学号 … 不在场次 … 的名单中` | 该学号没排进这场 | 去 [学生] / [场次] 检查 |
| `无法获取可信的网络时间` | 网络不通 / 防火墙拦了 443 | 已自动重试一轮；仍失败再点一次【开始考试】或换手机热点 |
| `各时间源分歧过大` | 疑似网络劫持 | 换网络；不要用奇怪的代理 |
| `不支持的容器版本` | 学生端比包旧 | 换与包同版本的学生端 |
| `PIN 错误` | PIN 输错，或 exe 与 PIN 表不是同一次打包 | 核对同次打包的 PIN 表 |
| 语言下拉框灰色 / 代码题超 256 KiB 没高亮 | 本题只允许 1 种语言 / 超过高亮阈值 | 都是正常现象，答案不受影响 |
| `[图片无法显示：…]` | 图片超硬上限或 base64 被截断 | 见 [图片使用教程](图片使用教程.md) |

### 11.4 收卷 / 判分

| 提示 | 原因 | 怎么办 |
|---|---|---|
| `必须选择学生端包` | 没选包 | 选本次考试那个 exe |
| `不支持的答题卡版本 2` | 管理端 / builder 太旧 | 升级到 v1.3.0+（**升级学生端时必须同步升级管理端**） |
| `解密失败（密钥不匹配或文件被改动）` | master 不对，或文件被改 | 用打包时那把 master |
| `校验工具没有任何输出（退出码 N）` | 被杀软拦截，或程序文件损坏 | 加白名单 / 重装发布包 |
| `绑定校验失败：试卷指纹或题目列表与包内数据不一致` | 答题卡不是这个包生成的 | 换正确的包；确认没混入上次考试的卡 |
| 成绩表出现「含未判」 / `题库里找不到题号` | 还有未判题 / 题库与打包时不一致 | 双击得分列补齐 / 重新导入打包时那份题库 |
| 「学生自报语言」写着「超出允许：…」 | 学生选了题目没允许的语言 | 仅提示；不参与判分，人工留意即可 |

## 12. 上线前自检清单

**打包之前**

- [ ] 题库都是 UTF-8，导入无报错；每份 `exam_id` 唯一且不含路径分隔符 / 保留名；
- [ ] 题库自检跑过：`verify_bank.py` 输出 `errors=0` + `PASS`（warning 已逐条解释）；
- [ ] 难度只有 `1`/`2`/`3`（多选 `9`、大题 `3`）；要用难度区间时所有题都标了难度，
      且该库**不含多选**（含多选时 `9` 会抬高均值，区间不好设）；代码题只写 `code_language` 或 `code_languages` 其中之一；
- [ ] 大题是 **30 题 / 难度 3 / 每题 15 分 / 总分 450**，`code_languages: ["c"]`；
- [ ] 填空每档 ≥15 题、改错每档 ≥15 题（总量不限）；每题 3 空 / 2 处错；
- [ ] 学号名单是正整数并与教务核对过；抽题数不超过各库题量；
- [ ] 场次时间带时区，时间轴上没有「同一学生跨重叠场次」的红条。

**打包之后**

- [ ] 日志出现「✔ 已内嵌密钥」；工程文件**不在**考试包输出目录里；
- [ ] 主密钥已存密码管理器并做了 `.eekey` 备份（口令另存）；启用 PIN 时 CSV 已保存且与 exe 同批；
- [ ] 用**测试学号**打测试包，实机跑通「输入学号 → 解锁 → 看题 → 交卷 → 答题卡落盘」；
- [ ] 抽 1 道单选题、1 道多选题、1 道填空题、1 道改错题，确认判分与标准答案列都正常。

**考试当天与收卷之后**

- [ ] 学生机能上网（443 通），提前试跑过一次；备用网络（手机热点）已准备；
- [ ] 监考老师知道答题卡在 exe 同目录，交卷后立刻拷走；
- [ ] 每份 `.eea` 都校验通过（**已绑定**）；缺考名单核对过；
- [ ] 五份 CSV 都导出，`说明.txt` 一起归档；重要考试已签发答题卡收据并记录签发人指纹。

## 13. 功能边界与安全须知

| 能做 | 不能做 |
|---|---|
| 看题、作答、交卷、到点冻结 | 锁屏、监控进程、检测截图 / 切屏 / 双屏 |
| 答题卡加密落盘、批量校验、导出 CSV | 证明答题卡是**本人**填的（见 R-02） |
| 单选 / 多选 / 判断 / 填空 / 改错自动判分 | 自动判问答与代码题（**不执行学生代码**） |
| 平均难度区间抽题、按大题精确难度抽题 | 逐题难度上下限过滤 |
| 缺考名单、成绩表、审计日志 | 服务端在线认证 / 实时监控 |

**学生端包里有什么**

| 内容 | 学生能不能拿到 |
|---|---|
| 场次时间、每场人数 | ✅ 能（header 用包内混淆的 `K_manifest` 解密） |
| 本场题干 | ⚠️ **有合法学号的学生能解出本场全部题干**（`answer` / `judge` 打包时已剥离；`meta` 根本没进模型） |
| 其他场次的题干 | ❌ 不能（每场独立 `session_secret`） |
| 标准答案 / `judge` 材料 / 大题参考答案 | ❌ 不能（它们都在 `answer` 里，打包时随 `answer` 剥离） |
| 名单外学号的信封 | ❌ 不能（需合法学号 + 一次 Argon2id） |

**四条已接受、没有修复的风险**：同场题干可解（R-01）、答题卡可伪造（R-02）、默认无 PIN 可冒用（R-03）、
Header 可重加密使时间门禁只是 UI 约束（R-04）。补偿措施与复审条件见 [风险接受记录](风险接受记录.md)。

**不要做的事**：把题库源文件（含 `answer` / `judge`）发给学生；把 `.eesproj` 发出去
（里面有完整名单与答案）；不同学期复用同一把主密钥；在同一个包里塞太多场次（单场出问题影响全部）；
把 master 写进命令行参数、日志、聊天记录。

**高风险考试的最低要求**：① 启用**每生 PIN 登录**；② **现场监考 + 现场收卡**，学生不得自行提交 / 转发 `.eea`；
③ 校验时**必须**选学生端包，不接受「未校验绑定」的通过状态；④ 启用工程加密、备份主密钥、签发答题卡收据并记录指纹；
⑤ 提前告知考务：本系统不防作弊，只是「防误操作 + 现场监考」的工具。
