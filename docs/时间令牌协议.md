# 签名时间令牌协议（v1）

> 适用版本 **v1.9.1**。协议自 v0.13.0 起（发布说明只从 v0.14.0 起有「更新摘要」小节，v0.13.x
> 没有一手小节可查）；`mode != off` 的包写容器 **v5**。
> **服务端不随仓库部署**（`worker/` 只有空的 `src/`）：本文件只定义协议，客户端与管理端已支持。
> 默认 `mode = off`，不配置的学校完全不受影响。教师侧配置见 [教师使用手册](教师使用手册.md)，
> 整体门禁口径见 [安全边界与威胁模型](安全边界与威胁模型.md) §11。

## 1. 目的与边界

HTTPS `Date` 头能挡住「改本机时间」，挡不住伪造 TLS / 劫持单个时间源。签名令牌把「可信时间」
从「某个网站说的」变成「持有私钥的服务说的」：客户端内置 Ed25519 **公钥**，服务端对
`时间戳 + 一次性 nonce` 签名；nonce 每次随机，因此**服务端无需记录状态**就能让旧响应重放失效。

**边界**（这四条比协议本身更重要）：

- 只保证「时间来自持有私钥的服务」，不保证服务本身正确——私钥持有者可以签任意时间；
  私钥泄漏等于时间源失守；
- 不防服务宕机：`require` 下服务不可用会**无法开考**（不是在开考时降级，而是直接起不来）；
- **不提供**服务端防重放部署：那需要服务端自己记录见过的 nonce，本仓库不含该实现；
- **不改变「客户端可被逆向」这一前提**：学生仍可改包 / 改程序跳过整个门禁，令牌只决定
  「客户端愿意采信哪个时间」，不决定「客户端不能被改」；
- 令牌**不绑定学号 / 场次**：协议里没有身份字段，也没有服务端 nonce 记录，所以拿到一份有效
  令牌的人在有效期内可以重复使用它。把它当成「一次一密」是误读。

## 2. 请求

```text
GET {url}?nonce=<32 位小写十六进制>
```

- `nonce` 每次随机生成（16 字节 → 32 hex）；若 `url` 已含 `?`，客户端用 `&` 追加；
- **只允许 `https://`**：`http://` 在 `TimeConfig::validate()` 就被拒，根本不会发请求；
- 超时 **3 秒**；响应体上限 **1 000 000 字节**（Windows 走 WinHTTP 读循环，非 Windows 走
  `curl -fsSL --max-filesize 1000000 --max-time <秒>`）；
- **只认 2xx**：3xx / 4xx / 5xx 直接失败，报 `时间服务 HTTP <code>`——错误页的 `Date` 不能当时钟。

## 3. 响应

```json
{"t": 1760000000, "n": "<原样回显的 nonce>", "sig": "<base64 Ed25519 签名>"}
```

| 字段 | 说明 |
|---|---|
| `t` | Unix 秒（整数，十进制） |
| `n` | 必须与请求 nonce **完全一致**（逐字节原样回显，不做大小写 / 去空格处理） |
| `sig` | 对 `"{t}:{n}"`（UTF-8、无空格）签名，标准 base64（解码后 64 字节） |

被签名原文形如 `1760000000:3f2a9c…`——冒号是 ASCII，前后**不能有空格**；`t` 不要补零、
不要科学计数法。客户端先比较 `n`，再用 `t`、`n` 重组原文验签。

## 4. 客户端校验顺序

1. `validate()`：`mode ∈ {off, prefer, require}`、`url` 以 `https://` 开头、`pubkey` 是
   32 字节 base64；**`mode = off` 时直接返回**，不检查其余字段；
2. 解析 JSON（失败 → `时间令牌 JSON 无法解析`）；`n == nonce`（不等 → `nonce 不匹配（疑似重放）`）；
3. base64 解公钥（非 32 字节报错）→ `VerifyingKey::from_bytes`；base64 解签名（非 64 字节报错）
   → 验签 `"{t}:{n}"`；
4. 取 `t` 作为考试时间。**本机时钟只用于 `max_skew` 警告**，不参与放行判定；
   失败原因原样上报，**不静默降级**。

## 5. 模式、`max_skew` 与被否掉的方案

| mode | 行为 | 版本影响（只看令牌） |
|---|---|---|
| `off`（默认） | 不请求令牌，沿用三源 HTTPS `Date` 中位数 | v4 |
| `prefer` | 先试令牌；失败回退 HTTPS `Date` 并在日志警告 | v5 |
| `require` | 无有效令牌直接拒绝开考（断网 / 服务挂会无法开考） | v5 |

- 表中的 v4 / v5 是「**只因令牌**」的版本；若同时有大题 / 部分 / 代码题，容器版本**取最高者**
  （v6 / v7 / v8），与令牌模式无关——不要以为 `mode = prefer` 一定是 v5；
- 未知 `mode` **不会**静默回退：`validate()` 直接报错，客户端拒绝开考；
- `prefer` 的回退是「可用性优先」，不是「安全等价」：回退后只剩三源 `Date` 的强度；
- `max_skew`（默认 300 秒；管理端可设 **30–3600**）是「本机时钟偏差警告阈值」：超过只打印一行
  警告，**不参与放行 / 拒绝**——本机时钟可被学生修改，用它做判据等于把门禁交给学生；
- 更远的方案（L4：令牌绑定学号 / 场次 + 服务端记 nonce）**未实现**，也不在 v1.x 的计划内。

## 6. 配置位置

令牌配置随包以加密形式放在容器 Header 的 `time` 字段里（`schemas/manifest.schema.json`
的 `TimeConfig`）：

```json
{"time": {"mode": "prefer", "url": "https://time.example.edu/api/time",
          "pubkey": "<base64 32 字节>", "max_skew": 300}}
```

管理端在 **[打包]** 页填「时间令牌」「令牌 URL」「令牌公钥」「时钟偏差警告阈值」；`mode = off`
时其余字段可不填，`mode != off` 时 URL 与公钥都必填。包内配置是**不可信输入**：客户端解析
Header 后会重新 `validate()`，不信任包里的自述。

## 7. 最小服务端示例（Python + Flask）

```python
# pip install flask cryptography
import base64, os, time
from flask import Flask, jsonify, request
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey

app = Flask(__name__)
SK = Ed25519PrivateKey.from_private_bytes(base64.b64decode(os.environ["TIME_SK"]))
print("pubkey(base64) =", base64.b64encode(SK.public_key().public_bytes_raw()).decode())

@app.get("/api/time")
def time_token():
    n = request.args.get("nonce", "")
    if len(n) != 32 or any(c not in "0123456789abcdef" for c in n):
        return jsonify(error="bad nonce"), 400
    t = int(time.time())
    return jsonify(t=t, n=n, sig=base64.b64encode(SK.sign(f"{t}:{n}".encode())).decode())
```

示例只演示**签名逻辑**；它必须部署在 HTTPS 上（反向代理或受管证书），客户端只接受 `https://`。
私钥**只在服务端**（示例从环境变量读，不落盘）；公钥（44 字符 base64）填进管理端。
不要在前面加 CDN / 缓存层：`?nonce=` 被缓存会直接触发 `nonce 不匹配`。

部署后 curl 自查：`NONCE=$(python -c "import secrets;print(secrets.token_hex(16))")`，
再 `curl -fsS "https://…/api/time?nonce=$NONCE"`。`n` 必须与 `$NONCE` 完全一致，
`t` 与 `date +%s` 相差几秒内。

## 8. 常见错误

| 提示 | 原因 | 怎么办 |
|---|---|---|
| `时间令牌 URL 必须以 https:// 开头`（管理端表单）/ `只支持 https:// 开头的地址`（客户端） | 配了 `http://` 或裸域名 | 改成 `https://…/api/time`；两层文案说的是一件事，出现在哪一层取决于校验时机 |
| `时间令牌公钥必须是 32 字节 Ed25519 公钥` | 填成了 PEM / hex / 长度不对 | 用服务端打印的 base64 44 字符值 |
| `nonce 不匹配（疑似重放）` | 服务端回显了别的 nonce，或中间有缓存 | 关掉 CDN / 反代缓存，确认原样回显 `n` |
| `时间令牌签名验证失败` | `"{t}:{n}"` 拼法不一致（多了空格 / 少了冒号 / 用了别的编码） | 严格按 `f"{t}:{n}"` 生成签名原文 |
| `签名长度不是 64 字节` | 用了 hex 而不是 base64，或被截断 | 用标准 base64 输出 |
| `时间服务 HTTP 404 / 500` | 路径写错或服务端异常 | 核对 `url` 并查服务端日志 |

## 9. 自检清单

- [ ] `url` 是 `https://`、考场网可达、证书链正常；公钥是 base64 / 32 字节，不是 PEM、不是 hex；
- [ ] 签名原文是 `"{t}:{n}"`（冒号 ASCII、无空格），服务端原样回显 nonce，`curl` 取到的时间对得上；
- [ ] 先选 `prefer` 试跑，日志无告警后再考虑 `require`；已与考务确认 `require` 的后果
      （服务挂了就开不了考）；
- [ ] 学生端版本能读容器 v5（客户端只接受不高于自身 `VERSION` 的包），即 v0.15.0+；
- [ ] 服务端私钥有备份：**丢了就再也签不出被现有学生端接受的时间，只能重新打包分发新 exe**；
- [ ] 明确知道本协议**不绑定学号 / 场次**、没有服务端 nonce 缓存，「转发有效令牌」需自行防护。

## 10. 与三源取时的关系

- `prefer` / `require` 之外的一切场景都走 `common::timegate` 的三源中位数（百度 / 阿里 / 腾讯的
  HTTPS `Date`），**令牌不是替代品**，只是把「时间来自谁」从三个网站换成一把私钥；
- 两种来源共用同一个 `NetworkTime` 结构与同一个 `fail-closed` 判定；时间门禁在派生入场密钥
  **之前**执行（`client/src/workflow.rs::unlock`），令牌成功与否不改变这个顺序；
- `mode` 只由启动时读到的包内配置决定，**包内配置不能指定时间源**（`time_sources` 曾因此被删除：
  那等于给时间门禁开后门），能配的只有「令牌 URL + 公钥」。
