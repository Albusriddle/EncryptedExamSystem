# 保密考试系统

管理端编排多场考试 → 打包加密题库 → 学生凭**学号 + 网络时间门禁**解锁个人试卷。

- 教师端：`ExamAdmin`（PySide6 图形界面，Windows）
- 命令行：`exam-builder`（打包、校验、导出 PIN、考后看原卷、校验答题卡）
- 学生端：`exam-client`（单 exe，双击运行，按场次与网络时间解锁）

> 当前版本 **1.10.0**。Release 正文由 `scripts/release_body.py` 从本文件提取
> **当前版本那一节**，因此 `## 更新摘要（vX.Y.Z）` 小节必须存在且唯一。
>
> **记录范围**：本文件从 **v0.14.0** 起逐版本记录（共 72 个版本，最新在前）；
> 更早版本（v0.13.2 及以前）未逐条整理，需要时查 `git tag` 与 `git log`。

## 更新摘要（v1.8.0）

新增**监考页**：老师可以在考试进行中看到全场进度，并**强制收卷 / 终止作答 / 解除**。

### 能力

- **页面**：`<scheme>://<教师机 IP>:<port>/monitor?t=<令牌>`，启动横幅直接打印完整地址；
  每 15 秒自动刷新（切到后台时暂停，回到前台立刻刷），也可点「立即刷新」；
- **看到什么**：名单人数 / 已登录 / 在线（60 秒内有过请求）/ 已交卷 / 封存中 / 未登录 / 已终止，
  以及每个学号的**状态、已答（已落盘）/总题数、最后保存、登录时间**；
  **名单里还没登录的学生也在表里**——这是查「谁还没进来」的地方；
- **收卷**：单人立即封存，走的是**学生交卷同一条** `seal_and_export()` 路径（`.eea` 格式完全一致）；
  幂等，已封存返回 `already`；
- **终止**：先封存 → 再让登录失效 → 再禁止重新登录（否则「踢了等于没踢」），并可在表格里「解除」，
  误点可恢复（答案卡仍在）；
- **批量收卷**：一次封存所有还没交卷的人；确认框列出人数与学号，并要求**输入「收卷」两个字**；
  服务端**再校验一次**这个确认词（不能只靠前端）；返回分「已收卷 / 已封存跳过 / 失败」三类，
  部分失败不影响其它人。

### 安全

- **独立监考令牌**：32 字节随机 hex，存在 `<答题卡目录>/monitor.token`（0600 / 受保护 DACL），
  重启复用（URL 不变）；首屏读到后立刻从地址栏抹掉，之后只走 `X-Monitor-Token` 头，
  **不落 cookie**；与学生会话完全隔离（学生 cookie 访问监控接口 401，有用例守着）；
- **CSRF**：所有写操作要 `POST` + `X-Monitor-Token` + `X-EES-CSRF: 1` 两个自定义头；
  跨站页面带不上自定义头，本服务也不发 CORS 头；
- **审计**：每次收卷/终止/解除写一行 `events.jsonl`（学号、结果、**令牌指纹前 8 位**），
  令牌明文不落日志；
- **明文模式**：默认**允许**写操作（覆盖「机房只跑明文排障」的场景），但横幅与页面顶部都有
  红字警告「令牌可被同网段嗅探」；要彻底关掉用 `--monitor-write-mode tls-only`
  （此时明文写操作返回 403）。这条风险已作为 **R-06** 记入风险接受记录；
- 监考页**只读 + 四个受控写操作**（收卷 / 批量收卷 / 终止 / 解除），不下发答案/题干，只有计数。

### 名单从哪来

考试包的 session header 是**匿名**的（只有 tag + 密文），服务端数得出「有多少人」但不知道「是谁」。
因此：

- 管理端「网页考试…」启动时会把项目里的学号写成 `<答题卡目录>/roster.txt` 并传 `--roster`；
- 命令行用户需自己给 `--roster <文件>`（每行一个学号，`#` 开头为注释）；没给时监考页只显示
  已登录的人，横幅会提示「名单有 N 人但没给 --roster」。

- Rust **391**（server 117，+19：令牌/越权/stats 字段/收卷幂等/批量确认词/终止三步/解除/审计不含令牌/
  明文与 `tls-only`/`.eea` 可被 `answer_sheet::open` 反解）；
- pytest **464 passed + 1 skipped**（+3：`--roster` 进 argv、名单文件去重升序、无名单时不传）；

  点「收卷」→ 确认框（学号 + 已答 + 后果）→ 确定 → 「已交卷 1」、`.eea` 落盘、

## 更新摘要（v1.6.0）

本版给**外部证书**（`--tls-cert/--tls-key`，学校内网 CA 签发）加上**启动自检**，不新增依赖、
不改协议。

### 为什么

外部证书以前只做 PEM 解析 + 组 `ServerConfig`；`with_single_cert` **不校验**私钥是否配套、
是否过期、EKU 是否含 `serverAuth`、SAN 是否覆盖教师机地址。配置错了要等学生打开浏览器才暴露，
而且「私钥配错」在学生侧表现为「连接被重置」而不是证书警告，最难排查。

### 做法：启动时在内存里跑一次真实 TLS 握手

- 用这份证书建 `ServerConfig`，把 `--tls-ca`（或叶子证书本身）当信任锚，对 `tls_hosts` 里
  **每个地址**跑一次 `ClientConnection ↔ ServerConnection` 互喂字节的握手：**不开端口、不走网络**，
  单地址最多 8 轮 / 256 KiB 兜底；
- 一次握手同时覆盖：私钥与证书是否匹配、是否过期、EKU 是否 `serverAuth`、SAN 是否覆盖该地址、
  链能否接到 `--tls-ca`；
- 结论分级，按「学生是否根本连不上」处理：

| 结论 | 级别 | 处理 |
|---|---|---|
| 私钥与证书不匹配（`KeyMismatch` / `BadSignature`） | **致命** | 拒绝启动，提示检查配套关系与 `--tls-ca` |
| 链不可信（`UnknownIssuer`） | **致命** | 拒绝启动，提示 `--tls-ca` 没签过这张证书 |
| 缺 EKU `serverAuth`（`InvalidPurpose`） | **致命** | 拒绝启动，点名 `ERR_SSL_KEY_USAGE_INCOMPATIBLE`（Chrome 不可绕过） |
| 已过期 / SAN 不覆盖某地址 | **警告** | 告警继续（浏览器仍可「继续」，停服更糟），并列出受影响地址 |
| 其它（解析/IO/未知） | **致命** | 拒绝启动并带原始错误 |

- 新增 `--tls-check warn|strict`：默认 `warn`；`strict` 让「过期 / SAN 缺失」也拒绝启动；
- 新增 `--tls-ca <path>`：**只用于自检的链校验**，不改变发给学生的证书链；
- 自签证书与 `--tls off` 不受影响（给了这两个参数会打印「仅对外部证书生效」）。

### 行为变化（升级须知）

**私钥不配套 / 缺 `serverAuth` / 链不可信**这三类**配置错误**会让服务拒绝启动（这三种情况下
学生根本连不上，早失败好过开考后炸），并打印修法，而不是带着坏配置起来、让学生去踩。
**已过期 / SAN 缺失**默认只告警（浏览器仍可点「继续」）；想让它们也拒绝启动才用
`--tls-check strict`。

**v1.6.0 的已知偏差**：证书「尚未生效」（`notBefore` 晚于教师机时钟，典型是教师机时钟慢了）
在本版被归进「致命」，比实际需要更严——浏览器对这种情况允许「继续」。v1.6.1 起改为**警告**，
并提示「先校教师机时钟」。

### 验证

- Rust **366**（+6，全部是自检用例：配套通过、私钥不匹配致命、过期只报 1 条警告、
  SAN 缺地址、缺 serverAuth 致命、`--tls-ca` 链校验正确/无关 CA）；
- 手工场景（真二进制）：A 证书 + B 私钥 → 拒绝启动；配套证书 → 「自检通过（私钥匹配、
  EKU serverAuth、SAN 覆盖：127.0.0.1）」；默认 hosts 但证书只含 `127.0.0.1` → 2 条警告后正常启动；
  `--tls-check strict` → 同样情形拒绝启动；`--tls off --tls-check strict` → 提示忽略并继续。

## 更新摘要（v1.5.0）

## 更新摘要（v1.4.12）

本版让网页端「关掉页面还能回来」，并把会话的生命周期说清楚（不新增模块）。

### 会话 cookie：60 分钟、滑动续期

- 登录下发 `Max-Age=3600`（`HttpOnly; SameSite=Strict`）；`/api/paper` 与 `/api/time`（前端每 15 秒轮询）
  都会**顺手续期**——所以 2 小时的考试不会被 60 分钟 TTL 掐断，只有**纯空闲 60 分钟**才失效；
- 直接效果：**只关标签页再打开**会通过 cookie 自动回到原卷（v1.4.11 的 `boot()` 已有自动恢复，
  本版补上「关掉浏览器后也能回来」）；
- 关掉整个浏览器仍会丢 cookie，需要重新输学号/PIN——但答案在服务端，重登即恢复。

### 提交与退出：会话立即失效

- **交卷**：默认策略（「仅教师可查看原卷」）下服务端把 cookie 置为 `Max-Age=0`，
  共享设备上不会留下可续的「已交卷」会话；策略为「允许回看」时**保持会话**（否则学生交完就看不到自己写的）；
- **新增 `POST /api/logout`**：要求 `X-EES-CSRF`，清 cookie **并从内存删掉 token**（拷走 cookie 也无法继续用）；
- 页面顶栏右侧新增**「退出」**：先冲掉未同步的作答，再调用退出接口，最后回登录页。

### 关页前冲掉「未同步的尾巴」

- `pagehide` / `visibilitychange(hidden)` 时用 `fetch(..., {keepalive: true})` 把未发送的作答发出去，
  把「关页丢失窗口」从最多 600 ms 压到接近 0（服务端仍是权威副本，本版**不做**任何浏览器本地存储）。

## 这个系统能做什么

题干与选项都支持 Markdown（选项可多行、可放代码块）；题干另支持表格（左右拖动）
与内嵌图片；学生端离线作答，交卷后答题卡加密落盘；管理端可自动判分
（单选/多选/判断/填空/改错），问答与代码简答题由老师人工给分；
已判与未判分别导出 CSV，并附一份按学号排序、按题型分项的考生成绩表；
收卷后可对照场次名单生成缺考名单；打包后自动保存工程
（`<包名>-<内容哈希6位>.eesproj`，保存位置可在打包页设置）；
下次启动为空白工程，工具栏【打开上次工程】可恢复；
场次可按题库设置**平均难度区间**（只约束平均值，不限制单题），抽题自动满足；
场次也可按“大题 → 部分”固定题数与精确难度。

## 五分钟跑通

| 步骤 | 在哪 | 做什么 |
|---|---|---|
| 1 | `[题库]` | 【导入题库】选 `示例题库\数学.json` |
| 2 | `[学生]` | 粘学号（每行一个），点【应用到名单】 |
| 3 | `[场次]` | 【新建】→ 设时间 → 勾科目 →【保存此场次】 |
| 4 | `[打包]` | 【生成】拿主密钥 →【开始打包】 |
| 5 | 分发 | 生成的 `.exe` 发给学生，双击输入学号即可 |
| 6 | `[收卷判分]` | 收 `.eea` → 选包 + 粘主密钥 → 校验 → 生成成绩 → 导出 CSV |

学生**不需要**任何密钥文件、不需要配置、不需要安装。

## 安全要点

- **主密钥**是全系统最重要的东西：不在任何生成的包里，也不在工程文件里，请存进密码管理器。
- 学生端包内嵌了读 header 的密钥（`K_manifest`，掩码存放）。拿到包的人能看场次时间与人数；
  有**合法名单内学号**的学生可解密**本场题干**（`answer`/`judge` 已剥离），
  **不能**读其他场次或标准答案。
- 答题卡加密只能防误改、防明文，**不能防蓄意篡改**；同场学生可读取/伪造他人答题卡。
- 时间门禁与“学生回看”开关是 **UI 约束**，不是密码学边界。
- 题库源文件（含 `answer`）不要发给学生；`.eesproj` 也不要发（含名单与答案）。

> 以上四条对应 [风险接受记录](风险接受记录.md) 的 R-01～R-04，
> 不是“已修复”，是“已知并接受”。

## 已知限制

- 学生端支持**作答**（单选 / 多选 / 判断 / 填空 / 改错 / 问答 / 代码简答）、**交卷**与到点自动冻结；
- 答题卡加密保存在学生机（`answers-<学号>-<场次>-<试卷指纹8位>.eea`），
  教师用管理端 **收卷判分** 页批量校验并导出 CSV；校验**必须**指定学生端包；
- **代码题不自动判分**：`judge` 材料随题库保留，编译运行学生代码有安全与公平风险，仍人工判；
- 自动判分只按题型勾选，暂不支持逐题开关；
- 答案必须写成 `{"kind": …, "answer": …}` 对象，纯字母写法（`"answer": "B"`）能导入但**不会自动判分**；
- 答题卡自 v1.3.0 起为 `EESANS02`/v2，**v1.2.x 及更早的管理端读不了**，升级请同步。
