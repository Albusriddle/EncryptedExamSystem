# 保密考试系统

管理端编排多场考试 → 打包加密题库 → 学生凭**学号 + 网络时间门禁**解锁个人试卷。

- 教师端：`ExamAdmin`（PySide6 图形界面，Windows）
- 命令行：`exam-builder`（打包、校验、导出 PIN、考后看原卷、校验答题卡）
- 学生端：`exam-client`（单 exe，双击运行，按场次与网络时间解锁）

> 当前版本 **1.4.9**。Release 正文由 `scripts/release_body.py` 从本文件提取
> **当前版本那一节**，因此 `## 更新摘要（vX.Y.Z）` 小节必须存在且唯一。
>
> **记录范围**：本文件从 **v0.14.0** 起逐版本记录（共 57 个版本，最新在前）；
> 更早版本（v0.13.2 及以前）未逐条整理，需要时查 `git tag` 与 `git log`。

## 更新摘要（v1.4.9）

本版是 v1.4.8 那批修复的**复审收尾**（4 个 P2 + 28 个 P3），仍不新增功能。

### 数据正确性（这是本版最重要的两条）

- 「已交卷」的卡完整性判定从「只比 8 字节魔数」改为**真正打开校验**（头 / 版本 / 指纹 / AAD / 答案长度）：断电留下「魔数对、内容截断」的卡时会被识别并**重写**，学生不再永久交不了卷；
- 严格时间解析**接线到运行期**：服务端启动、登录、挑场次与客户端解锁都改用 `container::parse_session_window`（必须带时区偏移、结束晚于开始），不再有「构建期严、运行期松」导致的 8 小时偏移。

### 网页服务端

- 场次窗口统一 `[start, end)`：启动挑场次原来用 `now <= end`，比其它路径多开一秒；
- `session_window` 改为 `Option`，三处调用方（取卷 / 保存 / 收卷）不再各自猜「0 表示没有窗口」；
- 自动收卷失败退避改为 **App 级**：学生重新登录不再把退避清零（磁盘满时又变回每 15 秒重写一次大文件）；
- 状态写盘锁从「全局一把」改为**按学生分桶**：50 人同时交卷时 durable fsync 不再把别人的保存排在后面；
- 请求体上限改为**按路由**：`/api/answer` 4 MiB（1 MiB 答案 + JSON 转义的上限），其余 64 KiB；超限回 **413**、chunked 回 **411**，并在回响应后短暂 drain，避免客户端只看到「连接被重置」；
- 写盘失败会清掉临时文件，启动时也会清掉残留的 `*.json.<序号>.tmp`；durable 写盘补目录 fsync；
- **登录接口也校验 `X-EES-CSRF: 1`**（防登录 CSRF：任意网页都能用别人的学号把受害者登进攻击者的会话）；
- 新增 4 条回归用例：坏卡重写、无时区拒绝、并发保存/交卷后仍是已交卷、带 body 的 413 仍可读。

### 学生端

- 取时（Linux/curl 分支）补 `User-Agent`：`aliyun` 对 curl 默认 UA 返回 403，收紧「只认 2xx」后 Linux/CI 上会从三源掉到两源；
- 整卡 16 MiB 守卫覆盖**填空 / 改错**（原来只挡问答与代码题）；到点自动冻结前先做超限判定——超限**不冻结**并提示「需监考处理」，避免「已冻结但没有卡」；
- `--master-file` 明确传错时直接报错（只有残留的 `EXAM_MASTER` 才降级为警告）；
- 答题卡 durable 落盘补目录 fsync；代码编辑器恢复防呆输入上限（权威口径仍是保存时的 UTF-8 字节）；
- 图片限幅用例补「有效小图能正常解码」的正例。

### 管理端与工具链

- PIN 表暂存件改为**保留 7 天**，不再在下一次打包开始时（配置校验之前）就删掉唯一副本；
- `atomic_write` 临时名带 pid + 序号、支持 `mode=`（收据私钥用 0600 创建），`.eekey` 也补了权限收紧；工程保存的 `.bak` 改用 rename；
- `build_exe.py` 的版本比对容 `v` 前缀与 `+build`，产物候选会逐个试；缺 `exam-client` 的检查提前到打包开头；
- `smoke-web.sh` 的 curl 失败不再静默退出；`pick_python` 阈值改 3.11（脚本用了 `datetime.UTC`）；`verify-embed.sh` 补「坏 keyfile 必须失败」「BOM 必须成功」两条负向用例；`bump_version.py` 对 Ctrl-C 也回滚。

### 文档

- `AGENTS.md` 的发版流程改为「先写 release-notes → `bump-version.sh` → 预检 6c 把关」；「提交前必跑」改指 `scripts/run-admin-tests.sh`；
- server README 更正「自动保存到内存」「过期后首次请求自动导出」两处失真描述；
- 架构文档补齐网页版现状、`scripts/` 清单与审阅轮次；审阅报告统一项数与 `ReadOutcome` 变体数；
- 教师手册补「仅本机监听时不要把地址发给学生」与「每 600 ms 保存并落盘」。

## 更新摘要（v1.4.8）

本版是一次**全仓审阅后的集中修复**（15 个 P2 + 46 个 P3，共 61 项），不新增功能。

### 数据安全与并发（网页服务端）

- 「保存」与「交卷」的状态写盘串行化并复查：旧快照不再能把「已交卷」覆盖回「未交卷」；状态临时文件按序号取名，避免并发 rename 撞车；
- 答题卡先 `fsync` 再记「已交卷」，且「已交卷」判定改为校验 `EESANS02` 魔数——断电留下半截卡会被识别并重写，而不是永久接受坏卡；
- 状态锁中毒不再让全站 panic（统一 `into_inner()`），后台收卷线程单轮 panic 不再整线程退出；
- Argon2 登录槽位改为 RAII 守卫：panic 不再永久泄漏槽位（原来 4 次 panic 后登录会永久阻塞）；
- 请求体上限 20 MiB → 2 MiB，超限回 **413**（原来直接断开连接）；`chunked` 请求回 **411**；
- 场次窗口统一 `[start, end)`（服务端原来含 end、客户端不含，差 1 秒），并在启动时算一次缓存（不再每个请求解密 header）；
- 自动收卷失败改指数退避（15 s → 5 min 封顶），避免坏状态下每 15 秒重写一次大文件。

### 学生端

- 整卡 16 MiB 超限时**写入前拒绝**；交卷前硬校验，超限不冻结、明确提示删减（原来会出现「已交卷但磁盘上没有卡」）；
- 「交卷二次确认」5 秒失效，编辑/滚动即清空（原来误点一次后单击就交卷）；
- `*.eea.recovered*` 恢复**最新**一份（原来取最旧）；
- 代码答案上限统一按 UTF-8 **字节**（原来输入按字符、保存按字节，中文会「能输入不能保存」）；交卷那次落盘 `fsync`；
- 图片在解码前按 4096×4096 / 64 MiB 限幅（压缩炸弹不再先解码）；
- `EXAM_KEYFILE` 带 BOM 或格式错误时**明确失败**（原来静默产出未嵌密钥的客户端）；残留的非法 `EXAM_MASTER` 只告警并忽略。

### 核心库

- 抽题 DP 的 parent 索引 `u16 → u32`（题库 > 65 535 题时不再截断/越界），返回前复核难度和；
- HTTP `Date` 解析做范围校验与受检算术（畸形头不再让 debug 构建 panic）；取时要求 HTTP 2xx；
- `build_payload` 对每个题库调用 `validate()`（绕过 CLI 的调用不再能产出重复题号的包）；
- 新增 `parse_rfc3339_strict` / `container::session_times`，供调用点做「必须带时区偏移」的严格校验。

### 管理端与工具链

- 主密钥备份 `.eekey`、收据私钥、工程文件改为「临时文件 + fsync + 原子替换」；
- `build_exe.py` 校验内嵌 `exam-builder` / `exam-server` 版本与 `VERSION` 一致，缺 `exam-client` 时明确失败；
- PIN 表明文暂存改到应用数据目录，并在下次打包时清理；
- 网页考试对话框：答题卡目录留空时用 `<考试包目录>/web-answers`（原来传空值会让服务端启动失败）；
- `verify-embed.sh` 不再吞掉编译失败；脚本与 CI 去掉 argv 里的 `--master`；CI 增加 Windows `cargo test`、`ruff format --check`、`scripts/` 的 ruff、每 job 超时、预检 job 装 uv（预检 15 项在 CI 里完整执行）；
- 演练脚本空集合不再打印「✓ 0 份」；`smoke-*` 修掉 `curl | grep -q` 与 GNU `date -d` 依赖；`.preflight/` 进 gitignore；`make-release-zip` 校验版本参数；`bump_version.py` 两阶段写盘。

## 更新摘要（v1.4.5）

- **作答实时落盘**：每次保存（前端 600 ms 防抖）就把加密状态写到磁盘，交卷路径额外 `fsync`；教师机崩溃 / 断电 / 误杀进程后重登，未交卷的答案也能拿回（此前只在交卷时落盘，整场作答会全丢）；
- **修复「按 IP 限速」从未生效**：服务端没有使用 TCP 对端地址（硬编码 `127.0.0.1`），全场共用一个限速桶，30 人以上的场次从第 21 个学生起集体 429；现在按真实对端 IP 分桶，默认 60 次/分钟，可用 `--login-rate-limit` 调整（`0` = 不限）；
- **修复并发写事件日志交错**：`events.jsonl` 由多线程追加，一次 `writeln!` 拆成两次写会与别人的写入交错成乱码（12 人演练里 12 条交卷只解析出 2 条）；现在加写锁并一次性写出整行；
- **新增局域网演练脚本** `scripts/drill-web.sh`：N 人并发登录 / 作答 / `kill -9` 后重启恢复 / 并发交卷 / 收卡校验，输出各阶段 p50/p95/max 与数量核对；CI 以 12 人规模常跑，本地 `--students 40` 即考场规模；
- 网页冒烟与演练脚本的 Python 解释器探测改为「能真正跑起来」才算数（Windows 上 `python3` 常被应用商店占位程序劫持）。

## 这个系统能做什么

题干与选项都支持 Markdown（选项可多行、可放代码块）；题干另支持表格（左右拖动）
与内嵌图片；学生端离线作答，交卷后答题卡加密落盘；管理端可自动判分
（单选/多选/判断/填空/改错），问答与代码简答题由老师人工给分；
已判与未判分别导出 CSV，并附一份按学号排序、按题型分项的考生成绩表；
收卷后可对照场次名单生成缺考名单；打包后自动保存工程
（`<包名>-<内容哈希6位>.eesproj`，保存位置可在打包页设置）；
下次启动为空白工程，工具栏【打开上次工程】可恢复；
场次可按题库设置**平均难度区间**（只约束平均值，不限制单题），抽题自动满足；
场次也可按“大题 → 部分”固定题数与精确难度。

## 五分钟跑通

| 步骤 | 在哪 | 做什么 |
|---|---|---|
| 1 | `[题库]` | 【导入题库】选 `示例题库\数学.json` |
| 2 | `[学生]` | 粘学号（每行一个），点【应用到名单】 |
| 3 | `[场次]` | 【新建】→ 设时间 → 勾科目 →【保存此场次】 |
| 4 | `[打包]` | 【生成】拿主密钥 →【开始打包】 |
| 5 | 分发 | 生成的 `.exe` 发给学生，双击输入学号即可 |

学生**不需要**任何密钥文件、不需要配置、不需要安装。

## 安全要点

- **主密钥**是全系统最重要的东西：不在任何生成的包里，也不在工程文件里，请存进密码管理器。
- 学生端包内嵌了读 header 的密钥（`K_manifest`，掩码存放）。拿到包的人能看场次时间与人数；
  有**合法名单内学号**的学生可解密**本场题干**（`answer`/`judge` 已剥离），
  **不能**读其他场次或标准答案。
- 答题卡加密只能防误改、防明文，**不能防蓄意篡改**；同场学生可读取/伪造他人答题卡。
- 时间门禁与“学生回看”开关是 **UI 约束**，不是密码学边界。
- 题库源文件（含 `answer`）不要发给学生；`.eesproj` 也不要发（含名单与答案）。

> 以上四条对应 [风险接受记录](风险接受记录.md) 的 R-01～R-04，
> 不是“已修复”，是“已知并接受”。

## 已知限制

- 学生端支持**作答**（单选 / 多选 / 判断 / 填空 / 改错 / 问答 / 代码简答）、**交卷**与到点自动冻结；
- 答题卡加密保存在学生机（`answers-<学号>-<场次>-<试卷指纹8位>.eea`），
  教师用管理端 **收卷判分** 页批量校验并导出 CSV；校验**必须**指定学生端包；
- **代码题不自动判分**：`judge` 材料随题库保留，编译运行学生代码有安全与公平风险，仍人工判；
- 自动判分只按题型勾选，暂不支持逐题开关；
- 答案必须写成 `{"kind": …, "answer": …}` 对象，纯字母写法（`"answer": "B"`）能导入但**不会自动判分**；
- 答题卡自 v1.3.0 起为 `EESANS02`/v2，**v1.2.x 及更早的管理端读不了**，升级请同步。
