# 安全边界与威胁模型

> 目的：把「防什么、不防什么」写清楚，避免把本系统当成监考 / 防作弊系统。
> 适用版本：**v1.4.12**。本文与 [风险接受记录](风险接受记录.md) 是安全口径的唯一来源；
> 其他文档若与之冲突，以本文为准。

## 0.1 网页考试模式（v1.4.2 起，可选）

`exam-server` 只在**隔离局域网 + 现场监考**下使用，HTTP 明文；服务端从考试包 + K_manifest 启动，
不持有 master 与标准答案。它把风险从「本地包」转移到「网络 + 教师机」：

- 同网段可嗅探题干/作答；
- 浏览器不可控（DevTools、切屏、搜索、截图）；
- 教师机单点故障；
- 详细决策见 [风险接受记录](风险接受记录.md) R-05。

v1.4.3 起，教师机时钟不再被无条件信任：

- 启动时用同一套三源中位数校时（`common::timegate`，源码内置的三个站点），
  成功则把偏差存成时钟偏移，**场次判定用校准后的时间**，不修改系统时钟；
- 取时失败时按档位处理：`warn`（默认，机房/隔离局域网没有外网是常态）只告警并按本机时钟继续，
  `require` 拒绝启动，`off` 完全不发请求；档位只能由启动参数决定，**包内配置不能指定时间源**；
- 作答状态文件收紧为「仅当前用户」：Windows 用受保护 DACL 切断 `Administrators` / `Users` /
  `Everyone` 继承，Unix `0600`/`0700`，升级前遗留的旧文件在启动时补收紧；
- 作答在**每次保存**时加密落盘（v1.4.5 起），教师机崩溃 / 断电后重登可恢复未交卷答案；
- 登录限速按**真实对端 IP** 分桶（v1.4.5 起；此前 `Request.peer` 被硬编码成 `127.0.0.1`，
  全场共用一个桶，30 人以上场次会集体 429）；
- 监听地址可以只绑局域网网卡（v1.4.7 起管理端可选，默认仍为 `0.0.0.0`）：外网侧直接
  连不上，比只依赖防火墙更直接；但 HTTP 明文本身仍只允许用于隔离局域网；
- 残余风险：同机管理员（或能取得 SYSTEM 权限的攻击者）本来就能改 ACL、改系统时钟，
  上述措施不防这一类；`warn` 档下如果教师机时钟错且完全断网，判定仍按错误的本机时钟进行，
  所以现场需要确认时钟（启动日志会打印本地时间与结论）。

## 0. 已接受的风险（决策，不是缺陷待办）

2026-10-29，项目决定**接受**下列风险，不在 v1.x 内实现 P0 的 per-student / Header 签名格式（v9）
或答题卡 v3。补偿措施与复审条件见 [风险接受记录](风险接受记录.md)。

| 编号 | 事实 |
|---|---|
| **R-01** | 同场学生可解出本场**全部题干**（`answer` / `judge` 已剥离） |
| **R-02** | 同场学生可读取 / 伪造他人答题卡；`check_binding` 只校验原卷指纹与 qids |
| **R-03** | 默认无 PIN 时，任意已知名单内学号可解锁该生信封 |
| **R-04** | Header 可被重加密；时间窗与 `student_review` 只是 UI 约束，不是密码学边界 |

**本决定不改变上述事实，也不把它们说成已修复。**

## 1. 系统边界

```text
教师机（ExamAdmin + exam-builder）
   │  生成主密钥、打包、保存工程、校验答题卡、判分
   ▼
考试包（StudentClient.exe，内含加密题库 / 名单 / 场次）
   │  分发给学生
   ▼
学生机（离线作答，答题卡 .eea 加密落盘）
   │  回收（U 盘 / 共享目录 / 现场拷贝）
   ▼
教师机（批量校验、判分、导出、签发收据）
```

**没有服务器**：没有在线身份认证、没有服务端签名、没有实时监控。
唯一的外部依赖是解锁时的 HTTPS 取时（可选签名令牌需自建服务，默认关闭）。

## 2. 资产

| 资产 | 位置 | 泄露后果 |
|---|---|---|
| 题库与标准答案 | 考试包（加密）+ 工程文件 | 泄题 |
| 主密钥 master | 教师保存（密码管理器 / `.eekey` 备份） | 可重新打包、解密 / 绑定校验 |
| `K_manifest` | 学生端 exe 内（`EXAMKEY1` + XOR 掩码） | 可解密本包的场次表与信封 |
| 场次 `session_secret` | 每个学生的信封内 | 可解密本场题库 |
| 答题卡 | 学生机 `.eea` | 泄露作答内容 |
| 工程文件 | 教师机 `.eesproj`（默认口令加密） | 含答案与完整名单 |
| 成绩 / 缺考名单 / PIN 表 | 教师机 CSV | 隐私 |
| 收据私钥 | 教师机 `receipt-key.pem`（0600） | 可伪造收据签名 |

## 3. 对手分级

| 等级 | 能力 | 本系统能否防 |
|---|---|---|
| **L1 随手翻看** | 打开文件、改扩展名、`strings` 搜索 | ✅ 加密 / 剥离答案 / 密钥区掩码 |
| **L2 有心学生** | 逆向 exe、提取 `K_manifest`、改答题卡、改 Header 重加密 | ❌ 只能抬高成本（见 §5） |
| **L3 教师机被入侵** | 拷走工程 / 主密钥 / 收据私钥 | ❌ 只能靠工程加密、备份与审计降低影响 |
| **L4 网络中间人** | 代理、改 hosts、伪造时间 | ⚠️ TLS + 三源 HTTPS `Date` 中位数；可选签名令牌（默认 off，服务端防重放未随仓库提供） |

## 4. 明确的安全承诺

- 考试包**不含明文标准答案**：`answer` 与 `judge` 在打包时被剥离；
- 包内只嵌**混淆后的 `K_manifest`**，**不是** master；
- master 只在教师机；学生端不接收、不保存 master，也不允许出现在命令行参数里；
- 答题卡**不是明文**，防止误传与随手查看；
- 工程文件默认口令加密（`EESPROJ3`；兼容读取 `EESPROJ2`）；主密钥可加密备份（`.eekey`）；
- 打包 / 保存会**避开考试包输出目录**（含子目录），降低「工程随包发出」的概率；
- 操作留痕：打开 / 保存 / 打包 / 人工改分 / 签发收据 / 验证收据都写哈希链审计日志；
- 答题卡收据（Ed25519）可**检测收卷后的改动**；
- 时间门禁 `fail-closed`：成功源不足或分歧过大一律拒绝放行。

## 5. 明确不承诺

- **不防作弊**：不锁屏、不监控进程、不检测截图 / 切屏 / 双屏；
- **不防学生伪造自己的答题卡**：密钥在客户端，提取后可改卡再加密；
- **不防同场学生伪造他人的答题卡**：答题卡密钥由包内 `K_manifest + paper_fingerprint` 派生，
  `check_binding` 只校验原卷指纹与 qids，收据不是强制必经步骤；
- **不防同场题干扩散**：学生用自己的学号可解密本场信封，得到本场全部题干（答案 / 判分材料已剥离）；
  不能读其他场次或标准答案；
- **不防教师机被完全控制**：工程 / 主密钥 / 收据私钥被拷走即失守；
- **不防网络攻击**：默认只有 HTTPS `Date`；签名令牌是可选实现（默认 off），服务端部署与防重放未随仓库提供；
- **收据不等于身份认证**：它只证明「收卷之后没被改」，不证明「这份卡是本人填的」。

## 6. 版本与兼容门禁

容器格式当前实现到 **v8**；**v9 的 P0 新格式未实现**。解析侧接受 v3–v8（`MIN_SUPPORTED_VERSION = 3`）。

| 包类型 | 容器版本 | 最低学生端 |
|---|---|---|
| 普通 | v4 | v0.15.0+ |
| 时间令牌（`mode != off`） | v5 | v0.15.0+ |
| 大题（`sections`） | v6 | v0.15.0+ |
| 大题下的部分（`parts`） | v7 | v0.15.0+ |
| 含代码简答题（`qtype = code`） | v8 | v1.1.1+ |
| P0 per-student / Header 签名 | **v9（未实现）** | — |
> 表中「最低学生端」为保守口径：v0.15.0 起的客户端可读 v4–v7；更早的客户端未逐版本验证。


**答题卡**：自 v1.3.0 起为 `EESANS02` / v2（新增 `chosen_code_languages`），可读 `EESANS01` / v1；
**v1.2.x 及更早的管理端 / builder 会以「不支持的答题卡版本 2」拒绝新卡**，收卷前务必同步升级。

## 7. 交卷后回看

- 默认 `student_review = none`：学生端没有回看入口；
- 打包时取消「仅教师可查看原卷」才为 `free`：学生**已交卷且未到结束时间**可只读回看；
- 到点后学生端一律不提供无授权回看；
- 教师考后查看原卷用 `exam-builder review-paper`，需要教师电脑上的 master，**不经过学生端时间门禁**；
- 正式分发的学生端不需要 master；开发 / 无内嵌包仍可用 `EXAM_MASTER` 或 `--master-file`（master 本身不允许进命令行）。

## 8. 残余风险与缓解

| 风险 | 当前缓解 | 后续（路线） |
|---|---|---|
| 学生提取 `K_manifest` | 只能读场次表；本场题干需合法学号 + 一次 Argon2id | per-student 密钥（v9，未实现） |
| 同场题干扩散 | 题库按场次拆分（每场独立 `session_secret`）；现场监考 | per-student 试卷数据（v9，未实现） |
| 学生改 / 伪造答题卡 | 绑定校验 + 收据（可选）+ 现场收卡 | per-student 答题卡密钥或教师签名（未实现） |
| 未知学号冒用 | 可选每生 PIN（`--pin-login`） | 高风险考试强制启用 |
| 改系统时钟 / 改 Header | 三源网络时间 + `fail-closed` | 签名令牌 + 防回拨（可选实现已提供协议） |
| 工程文件被拷走 | 默认口令加密（EESPROJ3） | 备份策略与介质管理 |
| 主密钥丢失 | `.eekey` 加密备份 + 8 位指纹核对 | — |
| 改分争议 | 哈希链审计 + 答题卡收据（需核对签发人指纹、含包哈希） | 审计日志导出与外部归档 |

## 9. 使用建议

- **校内测验 / 随堂考**：标准模式即可；
- **期末等较重要考试**：启用工程加密、备份主密钥、启用每生 PIN、收卷时现场核对；
- **高风险考试**：不要只依赖本系统，必须配合现场监考 + 现场收卡；
  可上线签名时间令牌，并按 [风险接受记录](风险接受记录.md) §3 判断是否需要更强的格式。
