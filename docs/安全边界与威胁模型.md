# 安全边界与威胁模型

> 目的：把「防什么、不防什么」写清楚，避免把本系统当成监考系统或作弊防控系统。
> 适用版本：**v1.10.0**。本文与[风险接受记录](风险接受记录.md)是安全口径的唯一来源：本文定义「防什么、不防什么」，风险记录定义「哪些残余风险已被正式接受」。其他文档（含发布说明、教师手册）若与这两份冲突，以这两份为准。
>
> 事实依据：容器与答题卡常量见 `crates/common/src/container.rs`、`crates/common/src/answer_sheet.rs`；时间门禁见 `crates/common/src/timegate.rs`；网页端见 `crates/server/src/`。本目录的相对链接**不指向 `crates/`**：发布包只带 `docs/`、`示例题库/`、`tools/`，指向 `crates/` 的链接在包里是死链。

## 0. 三句话结论

1. 本系统是**「防误操作 + 抬高逆向成本 + 现场监考」**的组合，不是密码学意义上的强保密系统。
2. 已经明确**接受**的风险（R-01 ~ R-06）**没有被修复**；本文与风险接受记录都不把「读不到题目」「防伪造答题卡」当作承诺。
3. 所有安全结论都只对**当前格式**（容器 v8、答题卡 v2）成立；改动格式前先读 §9 与[风险接受记录](风险接受记录.md) §9。

## 1. 系统边界

离线模式（默认）：

```text
教师机（ExamAdmin + exam-builder）
   │  生成主密钥、打包、保存工程、校验答题卡、判分、签发收据
   ▼
考试包（单文件 StudentClient.exe：stub + 加密 payload + 混淆密钥区 EXAMKEY1）
   │  分发（U 盘 / 群文件 / 内网共享）
   ▼
学生机（离线作答，答题卡 .eea 加密落盘）
   │  回收（U 盘 / 共享目录 / 现场拷贝）
   ▼
教师机（批量校验、判分、导出、审计）
```

**离线模式没有服务器**：没有在线身份认证、没有服务端签名、没有实时监控；唯一的外部依赖是解锁时的 HTTPS 取时（签名令牌可选，默认关闭）。

两条**可选**旁路都不改变上图的信任主体：

- **网页模式**（v1.4.0 起可选）：由教师机跑 `exam-server`，学生用浏览器作答。服务端只拿考试包与 `K_manifest`，**不持有 master，也不持有标准答案**；边界见 §6。
- **签名时间令牌**（`mode` 默认 `off`）：解锁时向学校自建服务取签名时间，替代「某个网站说的时间」；协议见[时间令牌协议](时间令牌协议.md)。

网页模式把风险从「本地包」转移到「网络 + 教师机」，不会让风险消失。**它在 v1.4.0 提供，但「可正常作答」实际自 v1.4.2 起**：v1.4.1 才修 `body`（选项 / 模板 / 改错代码）不渲染，v1.4.2 才修填空 / 改错按离线格式编码（此前判分全错）。

三条**信任假设**（不成立时，本文所有结论都要重估）：

1. 教师机与教师账户是可信的：能读工程 / master 的人就是考务负责人；
2. 学生机是**不可信**的：学生拥有本机管理员权限只是时间问题；
3. 网络是**不可信**的：时间源、局域网、浏览器与服务器之间都不假设有可信通道。

## 2. 资产

| 资产 | 位置 | 泄露后果 |
|---|---|---|
| 题库与标准答案 | 教师机题库文件、加密工程（打包时答案被剥离后才进包） | 泄题（最严重） |
| 主密钥 master | 教师保存（密码管理器 / 加密备份 `.eekey`） | 可重新打包、派生 `K_manifest` 解 header、解 PIN 表、校验收据 |
| `K_manifest` | 学生端 exe 密钥区（`EXAMKEY1` + 32 字节 XOR 掩码） | 可解 header（场次时间、人数、信封列表）、可解他人答题卡；**不能**解信封 |
| 场次 `session_secret` | 每个学生的信封内 | 可解本场题库（该场全部题干；答案与判分材料已剥离） |
| 答题卡 | 学生机 / 回收介质上的 `.eea` | 泄露作答内容 |
| 工程文件 | 教师机 `.eesproj`（默认口令加密，`EESPROJ3`） | 含标准答案与完整名单 |
| 成绩 / 缺考名单 / PIN 表 | 教师机 CSV | 隐私；PIN 表可直接用于冒名登录 |
| 收据私钥 | 教师机 `receipt-key.pem`（0600） | 可伪造收据签名 |
| 监考令牌 `monitor.token` | `<答题卡目录>`（0600 / 受保护 DACL） | 可替学生收卷、终止作答（R-06） |

三点容易被误读（**这是本节最重要的一段**）：

- `K_manifest` **不是** master：它由 `HKDF(master, salt = "", info = "manifest")` 派生（salt 必须为空串，否则会陷入「要 salt 才能解 header、要解 header 才能拿 salt」的死锁）。它**只做两件事**：加密 Header（AAD `header-v3`），以及**作为答题卡密钥的 IKM**（`HKDF(K_manifest, salt = hex(paper_fingerprint), info = "ees-answer-sheet-v1")`）。拿到它**可以**解开 header、也可以改写后重新加密（这正是 R-04 的根源），**不能**解 PIN 表（PIN 表密钥是 `HKDF(master, salt = 包 salt, info = "student-pins")`，用 master 另派生）、**不能**解信封；
- **信封不是用 `K_manifest` 加密的**：每个学生的信封由 `entry_key = Argon2id(学号 ‖ 场次 ‖ salt ‖ [PIN])` 解密，定位靠 `tag = blake3(entry_key)[..8]`。所以「拿到 `K_manifest` 就能读题干」不成立——还需要一个**合法学号**加一次 Argon2id。这也是「包内没有学号明文」之后剩下的真实边界（R-01 / R-03）；
- 题目级 `samples`（输入 / 输出示例，v1.9.0 起）**随包下发**：它是**给学生看的演示数据**，不属于答案材料；大题 `answer.samples` 嵌在 `answer` 里，随 `answer` 一起被剥离。它留在包里不改变 R-01 的接受理由（详见[风险接受记录](风险接受记录.md) R-01 的边界说明）。

master 只能通过环境变量 `EXAM_MASTER` 或 `--master-file` 传递（文件权限由教师自管）。**命令行 `--master` 参数已经移除**：它会把密钥暴露在进程列表（`ps` / 任务管理器）里，`AGENTS.md` §5 明确禁止；需要自动化时请用文件或环境变量（优先级：`--master-file` > `EXAM_MASTER`）。本项目的脚本与文档示例一律不提供 `--master` 用法；看到别人这样传，说明使用的是旧版二进制。学生端 `exam-client` 同样只有 `EXAM_MASTER` / `--master-file`。

## 3. 对手分级（L2 是设计对手）

| 等级 | 典型能力 | 本系统能否防 |
|---|---|---|
| **L1 随手翻看** | 打开文件、改扩展名、`strings` 搜索、翻目录 | ✅ 加密 / 打包剥离答案 / 密钥区掩码 |
| **L2 有心学生** | 逆向 exe、提取 `K_manifest`、改答题卡、改 Header 重加密 | ❌ 只能抬高成本（每场一密 + 一次 Argon2id）；见 R-01 ~ R-04 |
| **L3 教师机被入侵** | 拷走工程 / 主密钥 / 收据私钥 | ❌ 只能靠工程加密、备份、审计降低影响 |
| **L4 网络中间人** | 代理、改 hosts、伪造时间 / 证书 | ⚠️ TLS + 三源 HTTPS `Date` 中位数；可选签名令牌（默认 off，服务端防重放未提供） |

## 4. 明确的安全承诺（均已实现，可核对）

| 承诺 | 实现要点 | 边界 |
|---|---|---|
| 考试包不含明文标准答案 | `q.answer` / `q.judge` 在打包时被剥离（管理端写临时题库时剥一次、builder 组包时再剥一次，纵深防御） | 只在「用 builder 打包」这条路径成立 |
| 包内只嵌混淆后的 `K_manifest` | `EXAMKEY1` + 32 字节 XOR 掩码；**不是** master | 掩码只挡 `strings`，不是密码学保护 |
| master 只在教师机 | 考试包不携带 master；学生端正常解锁不需要它（仅开发调试可用 `EXAM_MASTER`/`--master-file`）；管理端经环境变量传、子进程输出逐行打码 | 教师工具已移除命令行 `--master`（只接受 `EXAM_MASTER`/`--master-file`）；第三方输出不受控 |
| 每生每场一个匿名信封 | 每人独立 `entry_key`（Argon2id），按 `blake3(entry_key)[..8]` 定位；包里不出现学号明文 | 同场学生共用一个 `session_secret`（R-01） |
| 答题卡不是明文 | `EESANS02` / v2，AES-256-GCM；AAD = 学号 ‖ 场次 ‖ 试卷指纹，改任一项都解不开 | 密钥由包内 `K_manifest` + 试卷指纹派生（R-02） |
| 工程与密钥备份默认加密 | `EESPROJ3`（兼容读 `EESPROJ2`）/ `EESKEY02`（兼容 `EESKEY01`），Argon2id + AES-256-GCM，原子写 | 口令强度决定实际强度 |
| 打包 / 保存工程避开输出目录 | 跳过考试包输出目录（含子目录），降低「工程随包发出」的概率 | 只防误操作，不防刻意复制 |
| 时间门禁 fail-closed | 3 源 HTTPS `Date` 取中位数；成功源 < 2 或分歧超限即拒绝放行 | 不防「三个源同时被劫持」（阈值见 §11） |
| 操作留痕 | `audit-YYYYMM.jsonl` 哈希链（每行 `prev` + `hash`，blake2s-128），改一行即断链 | 能发现改动，不能阻止整段删除 |
| 收据可检测收卷后改动 | Ed25519 对**规范化 JSON** 签名；内嵌公钥、`package_sha256`、每卡 sha256、16 位签发人指纹 | 不证明「这份卡是本人填的」 |
| 网页端默认 TLS、状态文件仅本人可读 | v1.5.0 起自签 ECDSA P-256；受保护 DACL / Unix `0600` | 不防主动中间人与主机木马（R-05） |

### 4.1 承诺的验证方式

安全承诺不能只靠文档，下面这些都可以自己跑 / 自己核对：

| 承诺 | 怎么核对 |
|---|---|
| 包内不含标准答案 | 用 `exam-builder verify --package` 看结构；对包做 `strings` 搜已知答案（应搜不到）；代码上 `answer` / `judge` 在打包前被剥 |
| 密钥区不是 master | 搜 `EXAMKEY1` 后按掩码还原，得到的是 `K_manifest`；单测 `key_area_is_obfuscated` 断言密钥区里没有 K_manifest 的 hex / 原始字节 |
| 包内无学号明文 | 单测 `student_ids_never_appear_in_payload`（十进制 ASCII / LE / BE） |
| 时间门禁 fail-closed | 断网解锁应提示「无法获取可信的网络时间」并拒绝；单测覆盖 2 源 / 3 源分歧 |
| 答题卡加密 | 用记事本打开 `.eea` 是二进制乱码；改一个字节后校验失败（退出码 2） |
| 收据可验签 | 用收据里的公钥在另一台机器上验签；核对签发人指纹（16 位） |
| 网页默认 HTTPS | 启动横幅是 `https://`，明文端口只 301；`curl http://…:8080/` 应拿到 301 |
| 状态文件仅本人可读 | Windows 看 DACL、Unix 看 `0600`；换账户启动应读不到旧状态 |

> 这些检查多数有现成脚本：`scripts/verify-embed.sh`、`scripts/preflight-release.sh`、`scripts/smoke-web.sh`、`scripts/smoke-monitor.sh`。数字基线见仓库 `README.md` §8。

## 5. 明确不承诺

- **不控作弊，也不防拥有本机控制权的学生**：不锁屏、不监控进程、不检测截图 / 切屏 / 双屏 / 虚拟机；学生能改系统时钟、改 exe、改 Header、调试进程；
- **不防同场题干扩散**：学生用自己的学号可解出本场**全部题干**（答案 / `judge` 已剥离）（R-01）；
- **不防伪造 / 读取他人答题卡，也不把收据当身份认证**：`check_binding` 只比较原卷指纹与 `qids`，不证明答题卡作者身份；收据只证明「收卷之后没被改」（R-02）；
- **不防冒用学号**：默认无 PIN，知道名单内学号即可解锁该生信封（R-03）；
- **不把时间窗当密码学边界**：时间窗、到点收卷、`student_review` 都是 UI 约束，改包可绕过（R-04）；
- **不防主机恶意软件 / 浏览器扩展**：它们能读页面内存、替换服务端程序或注入脚本；TLS 只保护传输链路，不解决这一类；
- **不防教师机被完全控制**：工程 / 主密钥 / 收据私钥被拷走即失守；
- **不防网络攻击**：默认只有 HTTPS `Date`；签名令牌是可选实现（默认 `off`），服务端部署与防重放**未随仓库提供**（`worker/` 只有空的 `src/`）；
- **收据不等于身份认证**：它只证明「收卷之后没被改」，不证明「这份卡是本人填的」。

## 6. 网页考试模式的边界（R-05）

`exam-server` 只在**隔离局域网 + 现场监考**下使用；服务端从考试包 + `K_manifest` 启动，**不持有 master 与标准答案**。边界如下：

- **传输**：v1.5.0 起默认 HTTPS（首次启动生成 ECDSA P-256 自签证书，SAN 含本机地址，EKU `serverAuth`，有效期 365 天、到期前 30 天自动重签）；启动横幅打印 SHA-256 指纹，学生首次访问点「高级 → 继续前往」；
  - 能挡：同网段的**被动嗅探**（抓到的只是 TLS 密文）；
  - **不能挡主动中间人**：除非学生把浏览器里看到的指纹与教师屏幕核对一致——自签没有公共 CA 背书；
  - 明文端口（默认 8080）只回 301 跳转，**不返回页面、不承载数据**；只有显式 `--tls off` 才回到明文 HTTP，此时同网段可嗅探题干 / 作答；
- **外部证书**（学校内网 CA 签发）：启动自检在内存里跑一次真实 TLS 握手，覆盖私钥配套 / 过期 / EKU / SAN / 链；致命项拒绝启动、警告项默认放行（`--tls-check strict` 收紧）。自检**不代表学生设备信任该 CA**：把 CA 装进学生设备，等于把「伪造任意 HTTPS 站点」的能力长期留在考场，本项目**不建议**这么做；
- **浏览器不可控**：DevTools、切屏、搜索、截图、插件都不受服务端约束；
- **不防主机木马 / 浏览器扩展**：它们能读页面内存与设备上保存的密钥，任何网页应用都挡不住；
- **教师机是单点**：断电 / 休眠 / 崩溃影响全场；
- **iOS 上的 Chrome（WKWebView）无法绕过证书警告**，iPad / iPhone 需用 Safari；
- 详细决策与残余风险见[风险接受记录](风险接受记录.md) R-05。

网页端的**残余限制**（不是缺陷待办，是当前实现的选择）：

1. **交卷不受场次时间窗限制**：到点后可补交（便于自动收卷失败时补救），但过期后不能再改答案；
2. **没有本地草稿（IndexedDB）**：服务端是唯一权威副本，断网期间未同步的那几题会丢；
3. **监考页是 15 秒轮询**，不是秒级推送；「在线」= 60 秒内有过请求；
4. **单文件状态 + 每连接一线程**（没有 SQLite / keep-alive）：监考快照要遍历状态目录，一次页面加载约 6–7 次 TLS 握手，局域网内可接受。

## 7. 监考页的边界（R-06）

v1.8.0 起服务端提供 `/monitor`：

- 独立监考令牌（**32 字节 hex ＝ 64 hex 字符**，存 `<答题卡目录>/monitor.token`，0600 / 受保护 DACL），**不落 cookie**、首屏后从地址栏抹掉、后续只走 `X-Monitor-Token` 头；
- 弱令牌（不是 64 hex）默认**拒绝启动**，只有 `--monitor-allow-weak-token` 才放行并在横幅红字警告；
- 写操作（收卷 / 批量收卷 / 终止 / 解除）要求 `POST` + 令牌 + `X-EES-CSRF: 1`，全部写进 `events.jsonl` 审计，**只记令牌指纹（SHA-256 前 8 位）**，不记令牌本身；同一令牌 1 秒内只允许一次写（超出返回 429），防止脚本把教师机磁盘打成瓶颈；
- **明文模式默认允许写操作**（机房只跑明文排障），此时令牌可被同网段嗅探——拿到它就能替学生收卷 / 终止，这是明文本身的限制，已记入 R-06；
- 要求严格的部署用 `--monitor-write-mode tls-only`（明文下写操作直接 403，只读仍可用）；
- 令牌泄漏的处置：删掉 `monitor.token` 重启会重新生成——**旧书签随之失效**，需要重新从横幅取地址；`--monitor-token` 会进进程列表，仅应急。

## 8. 已接受的风险（决策，不是缺陷待办）

2026-10-29，项目决定**接受**下列风险，不在 v1.x 内实现 P0 的 per-student / Header 签名格式（v9）或答题卡 v3。补偿措施与复审条件见[风险接受记录](风险接受记录.md)。

| 编号 | 事实（一句话） | 当前状态 |
|---|---|---|
| **R-01** | 同场学生可解出本场**全部题干**（`answer` / `judge` 已剥离） | 接受，未修复 |
| **R-02** | 同场学生可读取 / 伪造他人答题卡；`check_binding` 只校验原卷指纹与 `qids` | 接受，未修复 |
| **R-03** | 默认无 PIN 时，任意已知名单内学号可解锁该生信封 | 接受，未修复（可显式开 `--pin-login`） |
| **R-04** | Header 可被重加密；时间窗与 `student_review` 只是 UI 约束，不是密码学边界 | 接受，未修复 |
| **R-05** | 网页模式：自签 TLS 只挡被动嗅探、不挡主动中间人；浏览器不可控；教师机单点 | 接受，未修复 |
| **R-06** | 明文模式监考令牌可被同网段嗅探，写操作默认 `allow` | 接受，未修复（可 `--monitor-write-mode tls-only`） |

**本决定不改变上述事实，也不把任何一条说成「已修复」。** 读这张表时注意三点：**「已接受」不等于「低风险」**（R-01 / R-02 在无人监考场景下就是直接的泄题与替考通道）；**「补偿措施」不是技术修复**（现场监考、收卡、启用 PIN 都是流程约束，可以被绕过）；**「v9 未实现」不是排期问题**（需要新容器格式与教师侧签名链，属于重构级改动）。

## 9. 版本与兼容门禁

容器格式当前实现到 **v8**；**v9 的 P0 新格式未实现**。解析侧接受 `MIN_SUPPORTED_VERSION = 3` 到当前 `VERSION = 8`；无代码题时最高只写到 `LEGACY_HIGH_VERSION = 7`（只有大题 / 部分才升到 v6 / v7），避免把普通包全部挡在旧学生端门外。

| 包类型 | 容器版本 | 打包侧判定条件 | 引入版本 |
|---|---|---|---|
| 普通包 | v4 | 无令牌、无大题、无代码题 | 早期（发布说明从 v0.14.0 起，未逐版本记录） |
| 含签名时间令牌 | v5 | `time.mode != off` | 早期（同上） |
| 按大题 | v6 | `sections` 非空且无 `parts` | v0.14.0 |
| 大题下再分部分 | v7 | 任一大题存在 `parts` | v0.15.0 |
| 含代码简答题 | v8 | 任一题 `qtype == code` | v1.1.1 |
| P0 per-student / Header 签名 | **v9** | **未实现** | — |

- 同一包同时满足多行时，容器版本**取最高者**；客户端只接受「不低于 3、不高于自身 `VERSION`」的包，看到更高版本**明确拒绝**，不会静默显示空白题（v1.1.1 的真实教训）。因此「能读 vN 的最低学生端」= 引入 vN 的那个版本；v4 / v5 的对应版本仓库**没有**逐版本记录，本文不给数字。
- **答题卡**：自 v1.3.0 起为 `EESANS02` / v2（新增 `chosen_code_languages`），可读 `EESANS01` / v1，读入后统一升为当前版本再写回；**v1.2.x 及更早的管理端 / builder 会以「不支持的答题卡版本 2」拒绝新卡**，收卷前务必同步升级。
- `VERSION` 是唯一版本来源（`VERSION` / `Cargo.toml` / `admin/pyproject.toml` 三处同步，另有 `Cargo.lock` / `uv.lock` 由 `scripts/bump-version.sh` 派生）。

## 10. 交卷后回看

- 默认 `student_review = none`：学生端没有回看入口；
- 打包时取消「仅教师可查看原卷」才为 `free`：学生**已交卷且未到结束时间**可只读回看；
- 到点后学生端一律不提供无授权回看；
- 教师考后查看原卷用 `exam-builder review-paper`，需要教师电脑上的 master，**不经过学生端时间门禁**；
- `student_review` 是策略，不是密码学控制（R-04）。

## 11. 时间门禁的事实与阈值

- 并发请求三个 HTTPS 站点的 `Date` 头：`https://www.baidu.com` / `https://www.aliyun.com` / `https://www.tencent.com`（`timegate::default_sources()`）。三个源**固定**，**不可由包内配置替换**（`time_sources` 曾因此被删除：那等于给时间门禁开后门）；
- **成功源 < 2 或分歧超限 → 拒绝放行**（`fail-closed`），不剔除离群源后重算；
- 分歧上限由可用源数量决定（`spread_limit()`）：**≥3 源 60 秒，2 源收紧到 10 秒**（偶数个源上中位数会退化为较大的值，容差必须更小）；
- 本机时钟只用于警告，不参与放行判定；`max_skew`（默认 300 秒，管理端可设 **30–3600**）只是「本机时钟偏差警告阈值」；
- **不变量**：时间门禁必须在**派生入场密钥之前**（`crates/client/src/workflow.rs::unlock` 的步骤顺序）。挪到后面等于允许「先解密再判时间」；
- 三个默认源里阿里云对无 UA 的请求会直接 403，所以内置的 curl / WinHTTP 请求带固定 UA；换成别的取时实现时不要省略它，否则 3 源会静默退化成 2 源（容差从 60 秒收紧到 10 秒）；
- 可选签名令牌（`off` / `prefer` / `require`，默认 `off`），协议见[时间令牌协议](时间令牌协议.md)；
- 网页服务端启动时做同一套三源校验，把「网络 − 本机」的偏差存成时钟偏移，之后场次判定用校准后的时间；`warn`（默认，只告警）/ `require`（不通过拒绝启动）/ `off`（不请求）；
- 残余风险：`warn` 档下如果教师机时钟错且完全断网，判定仍按错误的本机时钟进行，所以现场需要确认时钟（启动日志会打印本地时间与结论）。

## 12. 残余风险与缓解

| 风险 | 当前缓解 | 后续（路线） |
|---|---|---|
| 学生提取 `K_manifest` | 只能读场次表与信封列表（均不含学号）；本场题干需合法学号 + 一次 Argon2id | per-student 密钥（v9，未实现） |
| 同场题干扩散 | 题库按场次拆分（每场独立 `session_secret`）；现场监考 | per-student 试卷数据（v9，未实现） |
| 学生改 / 伪造答题卡 | 绑定校验 + 收据（可选）+ 现场收卡 | per-student 答题卡密钥或教师签名（未实现） |
| 未知学号冒用 | 可选每生 6 位 PIN（`--pin-login`） | 高风险考试强制启用 |
| 改系统时钟 / 改 Header | 三源网络时间 + `fail-closed` | 签名令牌 + 服务端防重放（协议已定义，服务端未提供） |
| 工程文件被拷走 | 默认口令加密（`EESPROJ3`） | 备份策略与介质管理 |
| 主密钥丢失 | `.eekey` 加密备份 + 8 位指纹核对 | — |
| 改分争议 | 哈希链审计 + 答题卡收据（核对签发人指纹与包哈希） | 审计日志导出与外部归档 |
| 监考令牌被嗅探 | 默认 HTTPS；`tls-only` 逃生阀；审计只记指纹 | 考场网络分段 |
| 网页模式中间人 | 自签 TLS + 指纹核对 + 现场监考 | 学校内网 CA（需评估学生设备信任成本） |

### 12.1 上线前安全核对（按威胁模型逐项）

| 检查 | 通过标准 |
|---|---|
| 主密钥 | 已存密码管理器；有 `.eekey` 加密备份且口令分开保存；没有出现在聊天 / 命令行 / 日志里 |
| 工程文件 | 默认加密；不在考试包输出目录（含子目录）；不随包分发 |
| 学生端包 | 只发生成后的包，不发模板 / 管理端 / PIN 表 / 工程 |
| 名单与 PIN | 名单按保密要求管理；高风险考试启用每生 PIN 并现场核对身份 |
| 时间 | 学生机能访问 443；教师机时钟校准；网页模式确认 `--time-check` 档位 |
| 收卷 | 现场收卡，不让学生自行提交 / 转发 `.eea`；校验时必选学生端包 |
| 网页模式 | 隔离局域网；默认 HTTPS；核对证书指纹；明文仅排障；监考令牌不外传 |
| 记录 | 重要考试签发答题卡收据并记录签发人指纹；审计日志归档 |

## 13. 使用建议

- **校内测验 / 随堂考**：标准模式即可，但仍需现场看着；
- **期末等较重要考试**：启用工程加密、备份主密钥、启用每生 PIN、收卷时现场核对；重要场次启用收据并核对签发人指纹；
- **高风险考试**：**不要只依赖本系统**——必须配合现场监考 + 现场收卡；网页模式只在隔离局域网启用；可上线签名时间令牌，并按[风险接受记录](风险接受记录.md) §9 判断是否需要更强的格式。

## 14. 口径、证据与不确定点

- 事实来自代码常量：`container.rs`（`VERSION = 8` / `MIN_SUPPORTED_VERSION = 3` / `LEGACY_HIGH_VERSION = 7`、`manifest_key`、`student-pins`）、`answer_sheet.rs`（`EESANS02` / v2 / `MIN_SUPPORTED_VERSION = 1`）、`timegate.rs`（三源与 `spread_limit`）、`crypto.rs`（`KdfParams` 限幅）、`model.rs`（`TimeConfig::validate`）、`crates/server/src/{main,monitor,clock,secure_fs}.rs` 与 `crates/server/src/tls/*`；
- 测试与门禁的当前基线见仓库 `README.md` §8；数量会随提交和平台变化，实际以 CI 与脚本输出为准；
- 「能读 vN 的最低学生端」只对 v6 / v7 / v8 有发布说明可查（v0.14.0 / v0.15.0 / v1.1.1）；v4 / v5 的对应版本仓库没有逐版本记录，本文**不给数字**；
- 外部证书自检只回答「浏览器让不让进」，不做逐字段审计（`rustls` 不暴露 `notAfter`）；更早版本的行为只能从代码与注释推断（发布说明从 v0.14.0 起）；
- `crates/`、`.agents/`、`schemas/`、`scripts/` **不随发布包分发**，因此本文只用行内代码提到它们，**不提供相对链接**（发布包构建会判死链）。

## 15. 常见误解（逐条纠正）

| 误解 | 事实 |
|---|---|
| 「考完把 exe 收回来就安全了」 | 学生仍可在交回前提取 `session_secret` 与题干；收 exe 只能防后续扩散，不能防当场解包 |
| 「有 PIN 就防替考」 | PIN 只是多一次 Argon2id；6 位 PIN 空间 10⁶，离线可枚举，仍需现场核对身份（R-03） |
| 「答题卡是密文，所以能证明是本人填的」 | 加密只证明「能解开」，不证明「谁填的」；同场学生可伪造（R-02） |
| 「HTTPS 了就不怕中间人」 | 自签证书没有公共 CA 背书；不核对指纹就挡不住主动中间人（R-05） |
| 「监考页看见在线就说明学生在做题」 | 「在线」= 60 秒内有过请求；学生关页面但没交卷会显示 `offline`，不是消失 |
| 「改了题干，学生手上的卷子也变了」 | 试卷指纹不含题干；已发的包不会因为改源文件而变化，必须重新打包分发 |
| 「打包后收回了 exe，答题卡就作废了」 | 答题卡与试卷指纹、K_manifest 绑定，与 exe 文件是否在手无关 |
| 「工程文件加密了，所以主密钥也安全」 | 工程口令与 master 是两把东西；master 丢了工程也救不回已发卷的校验能力 |
