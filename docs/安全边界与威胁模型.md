# 安全边界与威胁模型

> 目的：把"防什么、不防什么"写清楚，避免把本系统当成监考/防作弊系统。
> 适用版本：v0.15.x 起。

## 0. 已接受风险（决策）

2026-10-29，项目决定**接受**同场题库共享、答题卡可伪造、默认无 PIN 可冒用、Header 可重加密等风险，不在 v0.15.x 内升级 container v8 / answer_sheet v2。补偿措施与复审条件见 [风险接受记录](风险接受记录.md)。

本决定不改变以下事实，也不把风险说成已修复：

- 同场学生可解出本场全部题干（答案/judge 已剥离）；
- 同场学生可读取/伪造他人答题卡，`check_binding` 只校验原卷指纹/qids；
- 默认无 PIN 时，任意已知名单内学号可解锁；
- 时间门禁与 `student_review` 是 UI 约束，不是密码学边界。

## 交卷后回看

- 默认 `student_review=none`：学生端没有回看入口；
- 打包时取消“仅教师可查看原卷”才启用 `free`：学生已交卷且未到结束时间可只读回看；
- 到点后学生端一律不提供无授权回看；
- 教师考后查看原卷用 `exam-builder review-paper`，需要教师电脑上的 master，不经过学生端时间门禁；
- 学生端不接收、不保存 master。
>
> **当前完成阶段 0–3（部分）**：主密钥备份、工程加密（默认开）、审计、校验和、
> 每生 PIN 信封（可选）、答题卡收据（教师侧 Ed25519，防收卷后改卡）。
> A1 的服务端签名未实现；A2 签名时间令牌已实现**可选协议**（默认 off，需自建服务；
> `require` 包为容器 v5，大题包为 v6，部分包为 v7；旧学生端会拒绝打开，请使用 v0.15.0+ 学生端）；
> A3 防作弊明确不做。

## 1. 系统边界

```
教师机（管理端 ExamAdmin + exam-builder）
   │  生成主密钥、打包、保存工程、校验答题卡、判分
   ▼
考试包（StudentClient.exe，内含加密题库/名单/会话）
   │  分发给学生
   ▼
学生机（离线作答，答题卡 .eea 加密落盘）
   │  回收（U 盘/共享目录）
   ▼
教师机（批量校验、判分、导出）
```

**没有服务器**：没有在线身份认证、没有服务端签名、没有实时监控。

## 2. 资产

| 资产 | 位置 | 泄露后果 |
|---|---|---|
| 题库与标准答案 | 考试包（加密）+ 工程文件 | 泄题 |
| 主密钥 | 教师保存（剪贴板/密码管理器） | 可重新打包、解密/绑定校验 |
| K_manifest | 学生端 exe 内 | 可解密本包内容 |
| 答题卡 | 学生机 `.eea` | 泄露作答内容 |
| 工程文件 | 教师机 `.eesproj` | 含答案与名单 |
| 成绩/缺考名单 | 教师机 CSV | 隐私 |

## 3. 对手分级

| 等级 | 能力 | 本系统能否防 |
|---|---|---|
| L1 随手翻看 | 打开文件、改扩展名 | ✅ 加密/剥离答案 |
| L2 有心学生 | 逆向 exe、提取密钥、改答题卡 | ❌ 只能提高成本（见下） |
| L3 教师机被入侵 | 拷走工程/主密钥 | ❌ 只能靠工程加密/审计降低影响 |
| L4 网络中间人 | 代理、改 hosts、伪造时间 | ⚠️ TLS + HTTPS Date；可选签名令牌（默认 off，服务端需自建）；服务端防重放部署未提供 |

## 4. 明确的安全承诺

- 考试包**不含明文答案**；答案在加密 payload 内。
- 答题卡**不是明文**，防止误传/随手查看。
- 工程文件默认口令加密（EESPROJ3，兼容 EESPROJ2）；主密钥可加密备份（.eekey）。
- 打包/保存会避开考试包输出目录，降低"工程随包发出"的概率。
- 操作审计：打开/保存/打包/人工改分写哈希链日志。

## 5. 明确不承诺

- **不防作弊**：不锁屏、不监控进程、不检测截图/切屏/双屏。
- **不防学生伪造自己的答题卡**：密钥在客户端，提取后可改卡再加密。
- **不防同场学生伪造他人的答题卡**：答题卡密钥由包内 K_manifest 派生，`check_binding` 只校验试卷指纹/qids；收据当前不是强制必经步骤。
- 学生可用自己的学号解密本场信封，得到本场题库题干（答案/判分材料已剥离）；不能读其他场次或标准答案。
- **不防教师机被完全控制**：工程/主密钥被拷走即失守。
- **不防网络攻击**：默认只有 HTTPS Date；签名令牌是可选实现（默认 off），服务端部署/防重放未随仓库提供。

## 6. 残余风险与缓解

| 风险 | 当前缓解 | 后续（路线） |
|---|---|---|
| 学生提取 K_manifest | 可解密本场题库题干；答题卡仍由 K_manifest 派生，本人/同场学生可伪造 | 需 per-student 答题卡密钥或服务端签名（未实现） |
| 学生改自己的答题卡 | 无 | 服务端签名；或现场监考收卷 |
| 改系统时钟 | 网络时间（可绕过） | 签名时间令牌 + 防回拨（阶段 4） |
| 工程文件被拷走 | 可选口令加密 | 默认加密 + 备份策略（阶段 2 收尾） |
| 主密钥丢失 | 加密备份 `.eekey` | 指纹核对 + 恢复流程 |
| 改分争议 | 哈希链审计 + 答题卡收据（公钥可验签、**需核对签发人指纹**、含包哈希） | 审计查看器/导出（已完成基础版） |

## 7. 使用建议

- 校内测验/随堂考：标准模式即可；
- 期末等较重要考试：启用工程加密、备份主密钥、收卷时现场核对；
- 高风险考试：不要只依赖本系统，必须配合现场监考；后续可上签名时间令牌/服务端签名。
