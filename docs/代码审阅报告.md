## 反复出现的教训（跨轮次模式）

1. **界面绿灯 ≠ 行为正确**：第 14 轮题号卡"三态从未实现"、第 11 轮"没选包也显示通过"，
   都是只断言模型不断言界面的结果。
2. **跨语言边界必须显式编码**：第 11 轮的 GBK 事故（中文 Windows 下 `text=True` 静默变空输出）
   是本项目最贵的一次教训，直接导致 `admin-package`（Windows）job 与 `encoding="utf-8"` 规则。
3. **文档与代码同源**：发布页/手册/架构/规范几乎每轮都要同步；凡是"写了但没改代码"的地方
   （第 5 轮把 300→60 改在测试里）必然在下一轮爆出来。
4. **状态机与冻结**：校验期间禁改输入（12/13 轮）、换卷重置题号卡（2 轮）、
   交卷后切页（14 轮）——都是"只禁用了一个按钮"引起的。
5. **路径与目录**：工程绝不能落进考试包输出目录（28/43/44 轮反复加固，含子目录判断）。
6. **不可信输入**：包内 KDF/salt/偏移/长度、时间字符串、`exam_id`，都必须在用前校验，
   否则就是 panic 或 OOM 路径（1/2/42/75 轮）。

## 技术无解项（设计边界，不是待办）

1. **学号是低熵数据**：拿到包的人可离线枚举名单。当前参数（64 MiB/t=3，单次约 92 ms）
   把 10⁵ 个学号的枚举成本抬到约 19 分钟（8 线程），这是成本，不是保证。
2. **包里嵌的是 `K_manifest` 而非 master**：泄漏后能读场次时间与人数；有合法学号的学生
   可解本场题干（答案/judge 已剥离），不能读其他场次或标准答案。
3. **有逆向能力 + 知道合法学号的人可在时间窗内解锁**：纯客户端方案无法消除（R-01/R-03）。
4. **必须联网校时**：完全断网时 fail-closed（宁可考不了，也不能用被篡改的本机时钟放行）。
5. **`stub-template.exe` 单独发给学生没有用**：它没有 payload，必须先由 builder 打包。
