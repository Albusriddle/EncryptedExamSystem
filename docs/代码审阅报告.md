## 一、P0 功能性错误（已修复）

### P0-1 清单的 `pick` 覆盖静默失效 ⚠️ 最严重

**现象**（实测）：

```
清单 pick=6，题库共 6 题  →  实际抽出 3 题
清单 pick=2，题库共 6 题  →  实际抽出 3 题   ← 完全无视清单
```

**根因**：`builder` 里用 `e.file.trim_end_matches(".json") == b.exam_id` 去匹配题库。
`file` 是 `"demo/math.json"`，去掉后缀得到 `"demo/math"`；而题库的 `exam_id` 是
`"demo-math"`（或 `"math"`）。两者永远不相等，`if let Some(p) = e.pick` 分支从不执行，
覆盖被静默丢弃。

**为什么单元测试没抓到**：测试直接调 `build_payload(master, banks, sessions, salt)`，
绕过了 builder 的匹配逻辑，而 `build_payload` 当时根本不看 `SessionExam.pick`。

**修复**：
1. `picks` 表下沉到 `PayloadData`，由 `build_payload` 统一解析并写入加密的 data 段；
2. 新增 `container::match_bank()` 做三级匹配（精确 stem → 完整路径归一 → 下划线归一），
   **匹配不到直接报错**，绝不静默回退；
3. `generate_paper` 改为接受 `pick_for` 回调，强制调用方使用 payload 的 picks 表；
4. 新增回归测试 `explicit_pick_overrides_bank_default`、`session_pick_override_is_applied`、
   `unknown_bank_reference_is_error`。

### P0-2 `extract_payload` 在损坏文件上 panic

**现象**（实测）：

```
thread panicked at container.rs:185: attempt to subtract with overflow
```

**根因**：`let start = exe_bytes.len() - 16 - payload_len;` 没有边界检查。
学生端读的是自己的 exe，如果文件被截断（下载中断、U 盘拔插、杀软隔离部分字节），
程序会直接崩溃而不是给出"文件损坏"的提示。

**修复**：显式检查 `payload_len > available` 并返回错误；新增
`corrupt_footer_returns_error`、`truncated_file_returns_error` 回归测试。

### P0-3 `generate_paper` 在 `pick > 题量` 时 panic

**现象**：`pool[..bank.pick as usize]` 越界 panic。
虽然 `ExamBank::validate()` 能拦住，但 `generate_paper` 不调用它，
一旦有路径绕过校验（比如 payload 被构造），考试当场崩溃。

**修复**：`pick_from_bank` 返回 `PickError::PickExceedsPool`，
`generate_paper` 返回 `Result<Paper, PickError>`；新增
`pick_exceeds_pool_returns_error` 回归测试。

## 二、P1 安全性与工程性问题（已修复）

### P1-1 主密钥走命令行参数，可被同机进程读取

`--master <hex>` 会出现在 `Win32_Process.CommandLine` 里，同一台机器上任何用户
（包括机房里的其他学生）都能用一条命令读到全部密钥。

**修复**：`--master-file` / `--master` / 环境变量 `EXAM_MASTER` 三种方式，
文件方式最安全；走命令行时打印警告。

### P1-2 环境变量静默覆盖显式参数（审阅过程中新发现）

修 P1-1 时我先把优先级设成"环境变量 > 命令行"，实测立刻踩坑：
机器上残留 `EXAM_MASTER=B`，管理员显式传 `--master A`，结果**包用 B 加密**，
而 `verify` 也用 B（因为同样读环境变量）所以"校验通过"——一个完美的静默错误。

**修复**：优先级改为 `--master-file > --master > EXAM_MASTER`，
**显式参数永远优先**。已加实测回归。

### P1-3 CI 从第一天就是红的

- `cargo fmt --check` 失败（代码没格式化）；
- `cargo clippy -D warnings` 失败（`Nonce::from_slice` deprecated、doc 缩进）；
- `admin/` 目录**完全没有被 git 跟踪**（0 个文件），但 CI 的 python job 要
  `cd admin && uv sync`，必然失败；
- `uv sync --locked` 需要 `uv.lock` 入库，而我在 admin/.gitignore 里排除了它（自相矛盾）。

**修复**：全部格式化；修 clippy；补齐 `admin/` 的 pyproject + 12 个测试；
`uv.lock` 入库；CI 增加 e2e job（真的打包 → verify → 名单内解锁 → 名单外拒绝）。

## 三、方案层面漏洞（需决策，尚未修）

### S-1 「学号试解密隐藏名单」的隐私保证是纸糊的

原设计声称"不暴露名单"，但实现里 `students` 是**明文**序列化进信封内层的，
外层 key 是 `HKDF(master, "envelope:{session}")`——**任何持有 master 的人都能解**。
而 master 就在学生端里（stub 现场拼装），所以学生只要逆向出 master，
就能读出**全班名单**和所有场次时间。

更根本的问题：低熵学号 + 离线可验证 = 必然可枚举，这是密码学定理，不是实现问题。

**决策选项**：
- (a) 接受现状，只做"防随手翻看"，在文档里如实声明（成本 0）；
- (b) 按班级/按学生分包，把名单拆散（包体积随班级数增长，管理端复杂度上升）；
- (c) 放弃离线名单校验，改成在线签到（与"离线自解压包"需求冲突）。

**建议 (a)**，但文档不能再说"不暴露名单"。

### S-2 时间门禁尚未实现，且它是唯一能防"考后重放"的机制

当前 `client` 完全不看时间。学生拿到包后，**任何时间都能解锁**，只要知道学号。
这不是"还没做"，而是当前形态下包一旦流出就是永久有效。

**必须在 M4 落地**，且注意：门禁失败要区分"未到时间/不在名单/已结束"，
否则学生无从判断是自己输错学号还是时间没到。

### S-3 每场一密并未真正实现

方案里说"每场考试一个独立密钥"，但当前 `build_payload` 只接受**一个** master，
所有场次共用。泄漏一个场次的 master = 全部场次沦陷。

**决策**：要么改成 `--master-file` 支持多密钥（每场一条），要么承认"全包一密"。

### S-4 答案剥离只在 data 段生效，header 的 bank_index 仍暴露题量

`bank_index` 里有 `total` 和 `pick`，能反推出题库规模。风险很低，但如果要严格，
可以让 `bank_index` 也只在解锁后可见。

## 四、其他观察（低优先级）

1. `Paper::fingerprint()` 用 `blake3` 拼接 exam_id 和题目 id，**没有分隔符**：
   `["ab","c"]` 和 `["a","bc"]` 会得到相同哈希。当前题目 id 格式固定，风险低，
   但加个长度前缀更稳妥。
2. `session_entry_key` 用 Argon2id 但**当前没被任何代码调用**（死代码），
   它是为 S-1 的 (b) 方案准备的。要么接上，要么删掉。
3. `picker` 的 Fisher-Yates 用了拒绝采样，但 `bound` 接近 `u32::MAX` 时
   `u32::MAX % bound` 的分支几乎不触发，实测性能没问题。
4. `demo/manifest.example.json` 里的 `time_sources` 指向 `time.example.com`（占位），
   M4 前必须换成真实地址，否则学生端会卡在超时。
5. 仓库还没有 `docs/` 之外的威胁模型文档，S-1 的结论应该写进去。
