## 二、本轮修复的核心设计

### 容器 v2：每生信封 + 每场独立密钥

```
header（K_manifest 加密）
  └ sessions[]
      ├ session_id / start / end / data_off / data_len
      └ envelopes[]                      ← 每个学生一个，无身份信息
            ├ tag[8] = blake3(入场密钥)[..8]
            └ blob   = AEAD(入场密钥, student_id ‖ session_secret ‖ exams)

blob_area
  └ 每场题库密文 = AEAD(HKDF(session_secret, "bank"), {banks, picks, bank_index})
```

**关键性质**：
1. `session_secret` 每场随机生成，只存在于该场学生的信封内 → 场次间密码学隔离；
2. 入场密钥 = `Argon2id(学号 ‖ 场次 ‖ salt)`，包里**不含任何学号**；
3. `tag` 让客户端**只算一次 Argon2** 就能定位自己的信封（1000 人时约 92ms vs 92 秒）；
4. `bank_index` 下沉到加密 data 段，解锁前看不到题量。

**枚举成本**：攻击者必须对每个候选学号跑一次 Argon2id(19MiB, t=2)。
10⁵ 个候选 ≈ 19 分钟（8 线程），10⁶ ≈ 3.2 小时。相比 v1 的"瞬间可读"是质的提升。

> ⚠️ 更正：本节早期写的"19MiB/t=2 ≈ 67 分钟"是估算错误。实测单次 18.2ms，
> 8 线程枚举 10⁵ 仅需 3.8 分钟。已提升默认参数到 64MiB/t=3（92ms/次）。

### 时间门禁

```
3 个 HTTPS 源并发取 Date 头
  → 成功 < 2 个？拒绝（fail-closed）
  → 最大分歧 > 300 秒？拒绝（疑似劫持）
  → 取中位数作为 now
  → now ∈ [start, end] 的场次
  → 门禁在派生密钥之前执行（不可绕过）
```

实测：3 个源分歧 1 秒，正确判定"考试尚未开始"，并给出可区分的原因。

## 三、本轮复检新发现并修复的问题

### N-1 时间窗倒挂不报错（已修）

`start: "2026-12-20T11:00:00"` > `end: "2026-12-20T09:00:00"` 时，
builder **照样生成包**，学生永远解不开——典型的"考场才炸"隐患。

修复：新增 `container::validate_sessions()`，构建期硬校验：
- 时间必须是合法 RFC3339；
- `start < end`；
- 场次编号不重复；
- 学号不重复。

### N-2 重复学号生成冗余信封（已修）

`students: [2021001, 2021001, 2021002]` 会生成 3 个信封（其中两个重复）。
功能上 `find` 只取第一个所以不出错，但说明清单有误且浪费体积。
现由 `validate_sessions` 直接报错。
