# exam-server（网页考试）

- 适用版本：**v1.7.1**

网页版学生端：教师在隔离局域网里启动它（管理端「网页考试…」入口），
学生用浏览器打开 `https://<教师机 IP>:8443/`（首次需点「高级 → 继续前往」），
输入学号（可选 PIN）后作答。

> 仅用于**隔离局域网 + 现场监考**。v1.5.0 起默认 **HTTPS（自签证书）**；
> 学生首次访问会提示「不安全」，点「高级 → 继续前往」即可（iPad/iPhone 请用 Safari）。

## 它证明的链路

```text
已构建考试包（含 K_manifest 密钥区）
  → 解析 payload / header
  → 学号 + PIN 试解信封（复用 container::try_unlock_session_with_pin）
  → 解密本场题库
  → 按学号确定性抽题（复用 picker）
  → 浏览器作答（每 600 ms 防抖，保存一次即加密落盘）
  → 交卷时用 answer_sheet::seal 写出 EESANS02
  → 现有 exam-builder verify-answer-sheet / 管理端可直接读
```

服务端**不持有 master、不持有标准答案**：它只需要考试包和 K_manifest。

## 运行

```bash
# 1. 先构建考试包（教师端正常流程也可）
#    master 只走环境变量：`--master` 会出现在进程列表里（仓库安全红线）
EXAM_MASTER=<64 位主密钥> exam-builder build --manifest live.json --banks banks \
  --stub stub-template.exe --out StudentClient.exe \
  --emit-keyfile key.txt
# 注：`stub-template.exe` 只在发布包里有；从源码构建时 --stub 用
#     `target/release/exam-client`（Windows 带 .exe）

# 2. 启动服务（教师机）
exam-server --package StudentClient.exe --keyfile key.txt \
  --port 8443 --answers-dir answers --time-check warn

# 3. 学生浏览器访问
#    https://<教师机 IP>:8443/   （首次会提示不安全 → 高级 → 继续前往）
```

命令行参数：

| 参数 | 说明 |
|---|---|
| `--package` | 已构建的考试包 |
| `--keyfile` | `--emit-keyfile` 生成的 K_manifest（64 hex） |
| `--bind` | 监听地址，默认 `0.0.0.0` |
| `--port` | HTTPS 端口，默认 `8443` |
| `--tls` | `auto`（默认：没证书就自动生成自签证书）/ `off`（明文，仅排障） |
| `--tls-cert` / `--tls-key` | 用自己的证书（例如学校内网 CA 签发的）；不给就自动生成到 `<answers-dir>/tls/` |
| `--tls-host` | 证书 SAN 里要包含的地址（可多次）；默认=本机局域网 IP + 本机 `--bind` 地址 + 127.0.0.1 + localhost |
| `--tls-ca` | 外部证书的签发 CA（可选；**只用于启动自检的链校验**，不改变发给学生的证书链） |
| `--tls-check` | 外部证书自检严格程度：`warn`（默认，过期/SAN 缺失只告警）/ `strict`（同样拒绝启动） |
| `--http-redirect-port` | 明文 301 跳转端口（默认 `8080`，方便旧书签；`0` = 关闭） |
| `--gen-cert` | 只生成自签证书然后退出（配合 `--tls-host`） |
| `--session` | 指定场次；默认选当前时间窗内的场次 |
| `--answers-dir` | 交卷答题卡输出目录，默认 `answers/` |
| `--state-dir` | 作答状态目录，默认 `<answers-dir>/state` |
| `--time-check` | `off` / `warn`（默认，只告警）/ `require`（不通过拒绝启动） |
| `--time-tolerance` | 允许的本机与网络时间偏差，默认 `120` 秒（夹取到 30–86400） |
| `--login-rate-limit` | 同一 IP 每分钟登录尝试上限，默认 `60`；`0` = 不限制（演练/同 NAT 时用） |

启动时会先做一次三源网络时间校验并打印结论（本地时间 / 网络时间 / 偏差 / 生效偏移）。
管理端「网页考试…」对话框可以设置 `--port` / `--bind` / `--answers-dir` / `--time-check` /
`--tls-cert` / `--tls-key` / `--tls-ca` / `--tls-check`（后四个在「证书来源 → 自己的证书」里）/
`--login-rate-limit` / `--tls auto|off`，并在服务打印出「考试服务已启动」之后才显示访问地址。
自己证书的四个参数在界面「证书来源 → 自己的证书」里；界面只做形式校验（文件存在 / PEM / 成对），
真正的强校验是启动自检（见下文 TLS 段）。
启动横幅里的地址跟随 `--bind`：绑 `0.0.0.0` 时显示本机局域网 IP，绑具体地址时原样显示
（绑 `127.0.0.1` 调试时不会再打印一个学生连不上的地址）。
默认 `warn`：没有外网的隔离局域网会打印「取时失败，仅告警」后继续启动；
`require` 适合确实有外网、又要求时间强一致的考场。

注意这一步发生在**绑定端口之前**：无外网的机房最坏要等约 6 秒（两轮 × 3 秒超时），
这期间端口还不接受连接。请等到打印出「考试服务已启动」再通知学生访问。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/` | 登录页 + 作答页 |
| `POST` | `/api/login` | `{student_id, pin?}`，成功返回 HttpOnly cookie |
| `GET` | `/api/paper` | 本人试卷 + 已保存答案（不含标准答案）；另给 `answer_text`（填空/改错的纯文本显示值）、`review`（`none`/`free`）。已交卷且策略不允许回看时 `paper`/`answers`/`answer_text` 都是 `null` |
| `PUT` | `/api/answer` | `{qid, value}`，单题 ≤1 MiB，整卡 ≤16 MiB |
| `POST` | `/api/submit` | 冻结并写出 `.eea`；默认策略下同时让会话立即失效 |
| `POST` | `/api/logout` | 主动退出：清 cookie 并从内存删 token（旧 cookie 立刻 401） |
| `GET` | `/api/time` | 服务器时间与剩余秒数；附带 `time_mode` / `clock_offset_secs` 便于排障 |

## TLS

- 默认 HTTPS：启动时若 `<answers-dir>/tls/` 里没有证书，会自动生成一张 **ECDSA P-256 自签证书**
  （SAN 含本机局域网 IP、`127.0.0.1`、`localhost`；EKU 为 `serverAuth`——缺它浏览器会报
  **不可绕过**的 `ERR_SSL_KEY_USAGE_INCOMPATIBLE`）；有效期 365 天，**到期前 30 天自动重签**；
- **会自动重签的三种情况**（启动时判断，日志会打印「证书已重签：<原因>」）：
  证书已过期或将在 30 天内到期；本机地址变了、证书 SAN 已不含当前地址；
  旧版本遗留目录缺少元数据（`server.json`）。证书/私钥文件损坏时也会**备份后重签**，不需要人工删目录；
- ALPN 只声明 `http/1.1`（服务端不实现 h2，声明清楚避免浏览器猜）；
- 启动横幅打印 `https://<IP>:8443/` 与**证书指纹（SHA-256）**。核对路径：先点「继续前往」进入页面，
  再点地址栏左侧「不安全」→「证书无效」→「查看证书」→「详细信息」看 SHA-256 指纹
  （**拦截页本身看不到证书详情**）。这是自签场景下防中间人的唯一办法；
- **外部证书启动自检**（`--tls-cert/--tls-key`）：启动时在**内存里**跑一次真实 TLS 握手
  （不开端口、不走网络），因此走的是浏览器同一条校验路径，覆盖 **私钥是否配套 / 是否过期 /
  EKU 是否含 `serverAuth` / SAN 是否覆盖每个访问地址 / 链是否能接到 `--tls-ca`**。
  不用解析 X.509 的原因是「字段对不对」不等于「浏览器让不让进」，而握手直接回答后者。
  结论分两级（横幅会打印「自检通过」或「N 项警告」）：
  - **致命**（拒绝启动）：私钥与证书不匹配、EKU 缺 `serverAuth`、链不可用——这些情况下学生
    根本连不上，早失败好过开考后炸；
  - **警告**（继续启动）：已过期、**尚未生效**（教师机时钟慢了）、SAN 不覆盖某个地址——
    浏览器仍可点「继续」，把服务停掉反而更糟；`--tls-check strict` 可让警告也拒绝启动。
  证书文件请按「**叶子 → 中间 CA**」的顺序把中间证书一并放进去：只放叶子、且没给
  `--tls-ca` 时会被判成「链不可信」（那其实是缺中间证书，不是 CA 配错）。
  自检**不打印精确到期日**（`rustls` 不暴露 `notAfter`），只回答「是否过期」；
- 明文端口只做 301：`--http-redirect-port` 起一个**只回跳转**的监听器，不返回页面、不碰状态，
  旧书签 `http://<IP>:8080/...` 会自动跳到 HTTPS；
- 已知限制：**iOS 上的 Chrome 用的是 WKWebView，无法绕过证书警告**——iPad/iPhone 请用 Safari；
  受管 Chromebook 的策略也可能禁止「继续」。这类设备只能改用其他设备，或由老师用 `--tls off` 临时排障。

## 已具备（阶段 1）

- 答案落盘：`<answers-dir>/state/<学号>-<场次>.json`，原子写 + 交卷幂等；**每次保存都落盘**
  （v1.4.5 起，前端 600 ms 防抖；交卷路径额外 fsync）——教师机崩溃 / 断电 / 误杀进程后
  重登即可拿回未交卷的作答；
- 服务重启后重新登录会恢复答案与交卷状态；
- CSRF：**登录 / 作答 / 交卷都要求 `X-EES-CSRF: 1`**（防登录 CSRF：否则任意网页都能用别人的学号把受害者登进攻击者的会话）；
- **会话 cookie（v1.4.12）**：登录下发 `Max-Age=3600`（`HttpOnly; SameSite=Strict`），并在 `/api/paper`、`/api/time` 上**滑动续期**——只要还在答题就不会被 60 分钟 TTL 掐断；交卷（默认策略）与退出会让 cookie 立即失效，避免共享设备上留下可续会话；
- **回看策略（v1.4.11）**：服务端按包里的 `student_review` 决定交卷后还下不下发卷面；
  默认 `none`（「仅教师可查看原卷」）时，交卷后 `/api/paper` 只返回 `submitted`/`review`，
  网页端切到「已交卷」页。以前网页端完全忽略这个策略；
- **网页端作答控件（v1.4.11）**：单选/判断用 radio、多选用 checkbox（答案是 `B` / `AC`），
  填空/改错用 textarea（服务端把纯文本规范化成离线端的 JSON 编码，判分口径一致）；
- **断线提示（v1.4.11）**：保存失败时底部红色横幅说明「作答暂存在本页，正在自动重试」，
  退避重试（2 s→20 s）；剩余时间改为本地倒计时 + 15 s 校准，断线也照样走；
  教师机重启导致会话失效时，横幅给「重新登录」按钮（答案在服务端磁盘上，重登即恢复）；
- 单会话：同一学号重新登录会顶掉旧 token；
- 登录限速：按**真实对端 IP**（`TcpStream::peer_addr`）与学号各一分钟窗口；
  默认每 IP 60 次/分钟、每学号 10 次/分钟；
- 到点收卷：学生页面在剩余 0 秒时自动 `POST /api/submit`；页面已关闭的由后台线程每 15 秒
  收一轮（最多延迟 15 秒）。加密与写盘在全局状态锁**之外**进行（v1.4.4），不会堵住其他学生的请求；
- 事件日志：`<answers-dir>/events.jsonl`（并发写有锁 + 整行一次写出，v1.4.5）；
- 代码题：CodeMirror 5（行号 + C 系语言用 `clike` 近似高亮 + Python 专属高亮），静态资源内嵌；
- **写盘时序（v1.4.8）**：保存与交卷的状态写盘串行化并复查，「已交卷」不会被旧快照覆盖；
  答题卡先 fsync 再记已交卷，半截文件会被识别并重写；
- **启动校时（v1.4.3）**：三源中位数校验网络时间，偏差存成时钟偏移供场次判定使用；
- **状态文件权限收紧（v1.4.3）**：Windows 受保护 DACL（仅当前用户）/ Unix `0600`、`0700`，
  旧文件在启动时补收紧。

## 已知限制

- 自签证书不是公共 CA：能挡住同网段的**被动嗅探**，但**不防中间人**（除非学生核对指纹）；
- 外部证书自检只回答「能不能用」：它走的是 webpki 的 TLS 服务端校验（EKU / 有效期 /
  名称 / 链 / 签名 / `basicConstraints`），**不做逐字段审计**——叶子证书 `keyUsage` 的位组合、
  `policyConstraints` 这类字段不会单独报；需要逐字段核对请用 `openssl x509 -text`。
  也不打印精确到期日（`rustls` 不暴露 `notAfter`），只回答「是否过期」；
- `--tls off` 时仍是明文 HTTP（仅建议排障）；
- 状态文件是加密 JSON（不是 SQLite）；没有管理端监控页；
- 多标签页只靠单会话 token 顶掉旧页面，没有强制关闭；
- 隔离局域网没有外网时取时必然失败：默认档只告警，此时场次判定退回教师机系统时钟，
  需要现场确认时钟（`--time-check require` 可让它在取时失败时拒绝启动）；
- 换一个 Windows 账户启动服务会读不到旧状态文件（受保护 DACL 只给原账户），断线恢复随之失效；
- 交卷不受场次时间窗限制：到点后仍可补交（便于自动收卷失败时补救），但过期后不能再改答案；
- **静态资源缓存分级**：第三方 vendored 资源（CodeMirror 及语言模式）带
  `Cache-Control: public, max-age=3600`，刷新时不再重下（`codemirror.min.js` 就有 174 KB）；
  我们自己的 `app.js`/`app.css` 仍是 `no-store`——它们随版本变，缓存旧版本会让
  「升级后行为不一致」极难排查；
- **每个静态资源仍是单独建连**（`Connection: close`，未做 keep-alive）：一次页面加载约 7 次
  TLS 握手。局域网下可以接受；50 人同时开考时握手数会 ×7，若将来出现首屏慢，再单独立项做连接复用。
